# LinkCV 本地任务产物

`.specs/<KEY>/` 保存需要跨会话继续使用的本地任务产物，不保存机器阶段、文档哈希、验证快照或任务状态。纯后端与前后端混合方案以 `solution.md` 为业务和技术中心；已有页面的前端标准或完整设计以用户确认的真实路由当前差异为视觉依据，不额外建 Spec；全新页面才保存 HTML 原型，用户指定时使用 Figma。所有前端路径都不再要求 `ui-design.md`。

用户当前请求、可读取的 Issue、飞书文档及用户明确指定的其他材料都可以作为初始来源。Issue 存在时完整读取并关联；没有 Issue 不阻止方案、设计、实现或 PR。本地任务可以使用 `LOCAL-YYYYMMDD-SHORT-SLUG` 作为目录名。

飞书只提供方案或视觉设计形成前的初始输入。进入本地交付链后不反向同步飞书或 Issue 正文；PR 说明实际交付和重要差异。

## 产物组成

| 产物 | 什么时候存在 | 职责 |
| --- | --- | --- |
| `solution.md` | 纯后端或混合任务进入方案先行时 | 业务与技术中心，保存需求、流程、规则、数据、契约、实施步骤和验证映射 |
| `prototype/index.html` | 前端标准或完整任务未指定 Figma 时 | 自包含、可在浏览器打开的页面或区域原型；使用原生 HTML/CSS 和必要的最少 JavaScript，不依赖生产源码、外部网络或新增包 |
| Figma 设计稿 | 用户明确指定 Figma 时 | 用户可直接评审的可视设计；链接由当前请求、来源材料或交接消息提供 |
| `acceptance.feature` | 后端方案选择契约验收时 | 展开需要独立确认的可观察业务规则 |
| `manual_acceptance.md` | 自动化无法覆盖必要的跨端、浏览器、PDF 或视觉结果时 | 保存人工执行步骤和真实结果 |
| `implementation_report.md` | 存在已允许偏差、已接受限制或必须交接的遗留事项时 | 只补充方案之外的新事实 |

同一任务只有一个当前 `solution.md`。前端设计以人与 AI 的逐轮问答和当前可见界面为主：真实路由、HTML 原型或 Figma 只保存当前画面，不单独承担完整设计说明，也不是后续生成的固定提示词。用户最新明确反馈优先；混合任务的业务、API、权限、数据与失败语义仍只写在 `solution.md`。

## 领域与交付路径

- **直接实现**：不创建 Spec，根据当前请求和真实代码直接实现、验证和审查。
- **纯后端方案 → 实现**：确认 `solution.md` 后直接施工，或按所选路径先生成 `acceptance.feature`。
- **纯前端视觉设计 → 实现**：标准或完整档先由 `frontend-delivery` 询问一次大致方向；已有可运行页面默认直接形成真实路由预览，不创建重复 Spec；全新页面默认制作隔离的 HTML/CSS 原型，用户指定时使用 Figma。轻量任务不强制生成视觉产物。
- **混合方案 → 可视 UI 设计 → 分域实现**：先确认 `solution.md`，再生成从属原型或 Figma；后端和前端共同服从同一个业务契约。

顺序是内容关系，不是机器状态机。AI 根据最新用户指令、当前方案、确认的视觉产物、Git 差异、真实代码和本次验证判断下一步。缺少阶段字段、哈希或门禁命令本身不得构成阻塞。

## 创建和修订

后端或混合任务由 `backend-delivery` 完成七维判断；方案先行时使用 `solution-generator` 创建或修订 `solution.md`。前端标准或完整档由 `frontend-delivery` 在已有页面上形成可回退的真实路由预览，全新页面才生成可运行的 HTML 原型，用户指定时使用 Figma；不先交付一篇 UI 文档要求用户想象页面。

每轮只确认一个会影响下一次可见修改的高影响问题，不在设计前一次收集完整偏好，也不确认色值、字号、间距和精确断点。默认修改推荐方向；用户要求比较或存在两个同样合理的方向时才生成多版。用户反馈后继续修改当前画面，直到用户明确要求收口。

混合任务涉及范围、业务、API、权限、数据、状态、兼容或失败语义时先修改 `solution.md`；布局、交互呈现或视觉变化只修订原型或 Figma。普通文件组织、命名、测试落点不修改设计依据，按需在 PR 中解释。

## 验证与收尾

任务完成时运行与改动范围和风险匹配的真实命令，不保存本地“已通过”状态。跨会话不继承以前会话的测试结论；准备创建 PR 时必须在当前可提交内容上重新运行完整 `npm run check`。

PR 说明实际交付以及相对 `solution.md`、选定视觉产物和初始来源的重要差异；存在来源 Issue 时，PR 创建后只追加一条交付评论。人工验收文件中的单项结果可以保留，相关实现或环境变化后重新执行受影响项目。

## 跨会话与 worktree

新会话恢复任务时：

1. 读取当前请求；后端或混合方案读取 `solution.md`，前端读取真实路由中已确认的当前差异或用户确认的原型/Figma，混合任务同时读上游方案；
2. 视觉产物不可访问时请用户重新附上或恢复权限，不根据聊天记忆猜测；
3. 读取实际存在的 Acceptance、人工验收和实施报告；
4. 检查当前分支、Git 提交、工作区差异和真实代码；
5. 重新运行完成当前交付所需的检查。

多个任务或多个未确认原型都可能匹配时由用户指定，不自动猜测。

`.specs/*/` 被 Git 忽略，不进入提交或远端；`.worktreeinclude` 只在 Codex 新建本地托管 worktree 时复制一次本地产物，不会在已有 worktree、远程环境或不同设备之间实时同步。Figma 依赖其自身访问权限。

仓库长期只跟踪本说明，不把本地任务内容复制进 `docs/`。
