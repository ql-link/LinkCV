# LinkCV 本地任务产物

`.specs/<KEY>/` 保存需要跨会话继续使用的本地任务产物，不保存机器阶段、文档哈希、验证快照或任务状态。纯后端与前后端混合方案以 `solution.md` 为业务和技术中心；纯前端不创建设计 Spec，实际需要且经过确认的视觉结果由用户指定的 Figma、截图或原型保存。

用户当前请求、可读取的 Issue 及用户明确指定的外部材料都可以作为初始来源。Issue 存在时完整读取并关联；没有 Issue 不阻止方案、设计、实现或 PR。本地任务可以使用 `LOCAL-YYYYMMDD-SHORT-SLUG` 作为目录名。

用户指定的外部材料只提供方案或视觉设计形成前的初始输入。项目工作流不主动创建或回写这些材料；进入本地交付链后也不反向同步来源 Issue 正文，PR 说明实际交付和重要差异。

## 产物组成

| 产物 | 什么时候存在 | 职责 |
| --- | --- | --- |
| `solution.md` | 纯后端或混合任务进入方案先行时 | 业务与技术中心，保存需求、流程、规则、数据、契约、实施步骤和验证映射 |
| 用户原型附件 | 用户明确要求在本地保留附件时 | 只保存用户指定的附件；不为了满足前端流程额外复制设计稿 |
| `acceptance.feature` | 后端方案选择契约验收时 | 展开需要独立确认的可观察业务规则 |
| `manual_acceptance.md` | 自动化无法覆盖必要的跨端、浏览器、PDF 或视觉结果时 | 保存人工执行步骤和真实结果 |
| `implementation_report.md` | 存在已允许偏差、已接受限制或必须交接的遗留事项时 | 只补充方案之外的新事实 |

同一任务只有一个当前 `solution.md`。前端以最新确认的 Figma、用户原型和逐轮反馈为准，真实路由是实现与浏览器检查对象。混合任务的业务、API、权限、数据与失败语义仍只写在 `solution.md`。

## 产物与开发的关系

- **直接实现**：不创建 Spec，根据当前请求和真实代码直接实现、验证和审查。
- **纯后端方案 → 实现**：确认 `solution.md` 后直接施工，或按所选路径先生成 `acceptance.feature`。
- **纯前端开发**：当前 Codex 直接处理，不创建 Spec。视觉方向未决时可以独立使用原型能力，运行时行为需要观察时可以独立使用浏览器能力，存在确认设计时可以独立使用视觉对照能力；这些产物和检查互不构成前置关系。
- **混合任务**：后端链只用 `solution.md` 处理后端范围和跨端契约；UI 实现与前端能力选择在后端链之外独立进行，视觉材料不能改写上游契约。

顺序是内容关系，不是机器状态机。AI 根据最新用户指令、当前方案、确认的视觉产物、Git 差异、真实代码和本次验证判断下一步。缺少阶段字段、哈希或门禁命令本身不得构成阻塞。

## 创建和修订

纯后端任务和混合任务中的后端范围由 `flow-router` 完成七维判断；方案先行时使用 `solution-generator` 创建或修订 `solution.md`。`flow-router` 不安排 UI 实现或前端检查。纯前端由当前 Codex 依据请求和真实代码直接处理，不需要先建立本地产物；使用 `frontend-prototype` 时才产生用于视觉决策的外部材料。

存在 Figma 审核时，它负责收敛页面结构和视觉方向；没有 Figma 的任务不补做这一阶段。实现中只有设计与真实 API、权限或数据语义冲突时才提出具体问题。

混合任务涉及范围、业务、API、权限、数据、状态、兼容或失败语义时先修改 `solution.md`；布局、交互呈现或视觉依据需要变化时由用户补充或更新原型/Figma，AI 不代为改写设计。普通文件组织、命名、测试落点不修改设计依据，按需在 PR 中解释。

## 验证与收尾

任务完成时运行与改动范围和风险匹配的真实命令，不保存本地“已通过”状态。实施中只在能为下一步提供有效反馈的稳定节点运行最窄检查，完整差异稳定后统一完成一次任务范围验证。纯前端根据实际差异选择自动化验证，只有运行时行为需要观察时才使用浏览器检查，只有存在视觉依据时才使用视觉对照。PR 按实际领域组合检查；同一会话中未变化代码快照的充分结果可以复用，只有差异覆盖全仓、无法可靠缩小范围或用户明确要求时运行完整 `npm run check`。跨会话不继承以前会话的测试结论。

PR 说明实际交付以及相对 `solution.md`、选定视觉产物和初始来源的重要差异；存在来源 Issue 时，PR 创建后只追加一条交付评论。人工验收文件中的单项结果可以保留，相关实现或环境变化后重新执行受影响项目。

## 跨会话与 worktree

新会话恢复任务时：

1. 读取当前请求；后端或混合方案读取 `solution.md`，前端读取目标真实路由和当前差异，实际存在视觉依据时再读取其最新版本；
2. 本次任务依赖的视觉产物不可访问时请用户重新附上或恢复权限，不根据聊天记忆猜测；
3. 读取实际存在的 Acceptance、人工验收和实施报告；
4. 检查当前分支、Git 提交、工作区差异和真实代码；
5. 重新运行完成当前交付所需的检查。

多个任务或多个未确认原型都可能匹配时由用户指定，不自动猜测。

`.specs/*/` 被 Git 忽略，不进入提交或远端；`.worktreeinclude` 只在 Codex 新建本地托管 worktree 时复制一次本地产物，不会在已有 worktree、远程环境或不同设备之间实时同步。Figma 依赖其自身访问权限。

仓库长期只跟踪本说明，不把本地任务内容复制进 `docs/`。
