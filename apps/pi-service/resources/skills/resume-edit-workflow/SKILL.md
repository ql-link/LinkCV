# 简历编辑总控

本 Skill 只负责流程与路由，不编写最终候选内容，也不直接创建修改 operation。

## 固定流程

1. 根据用户已经明确的范围和本轮授权材料列出本任务的全部修改目标。单项也是长度为一的清单。
2. 单一目标场景：本轮已有 resume 授权上下文时，直接调用 `resolve_resume_target`，运行时自动使用其 ID，不搜索标题或询问同名简历。仅在没有该上下文且用户明确指定名称或 ID 时，先调用 `resolve_resume_reference`，再在解析出的同一份简历内定位字段或正文。随后调用 `get_resume_context` 读取所需的最小范围。该选择只作用于当前运行，不绑定会话。编辑器选区仅适用于同一份简历；引用文本出现零处或多处时才确认内容位置，不重新确认简历身份。只有整篇诊断才允许读取整份简历。
3. 需要岗位、历史简历或资料依据时调用 `search_resume_materials`。没有授权来源时不得补造事实。
4. 事实改写先核对当前内容及授权来源；删除明确占位文本或清空明确字段无需 STAR 诊断。纯分析请求可调用 `analyze_resume_content`，解释结果后结束。
5. 只处理最多三个真实且高价值的问题。没有数字不等于缺少结果；定性影响、交付物、服务范围、稳定性、流程变化和业务作用都可以是证据。
6. 关键事实缺失时优先查已授权资料；仍缺失且会改变结果时只问一个决定性问题并结束本轮。不得用推测补充公司、职责、技术或量化结果。
7. 写作、经历重组、资料生成的方法 Skill 可以按需阅读；读取 Skill 只指导内容生成，不授予写入权限，也不锁定工具模式。
8. 用 `execute_resume_edit_plan` 提交单项或多项修改清单。若任务计划中有多个简历编辑任务，每次只提交当前任务的一项修改；若只有一个复合编辑任务，就在该任务内逐项完成全部目标。每项写明实际存在的连续原文、必要父范围、匹配方式、类型化动作、候选新文本和摘要；不能把“教育经历中的学位字段”等描述当作 `quoted_text`。已经通过 `resolve_resume_target` 唯一定位的单项可省略 `quoted_text`，使用服务端当前 locator。局部替换只引用要替换的短语，例如把“负责平台优化，查看说明”中的“平台优化”改为“系统优化”，`quoted_text` 必须是“平台优化”，`new_text` 是“系统优化”。新增 bullet 引用实际存在的经历标题或列表项作锚点，不引用尚未写入的候选文本。用户直接给出候选文字时不填写未经授权的 `source_ids`。运行时从服务端取得 locator 与允许操作并逐项创建待确认提案。

## 方法选择

- 目标没有原文，需要新增：读取 `resume-generate-from-materials/SKILL.md`。
- 目标已有原文，只影响一个字段、一个 bullet 或一个块内选区：读取 `resume-edit-local/SKILL.md`。
- 目标已有原文，影响同一段经历的摘要或多个 bullet：读取 `resume-edit-entry-star/SKILL.md`。

不要根据“润色、优化、改写”等近义词决定授权。跨 section、entry、字段或独立块的修改要逐项列出；同一任务可以组合删除、清空、替换和新增。相同短文本出现多次时，提供用户已明确的父 section/entry 文本并选择 `match=all`，不能全局猜测。只有父范围仍不明确时才询问。

## 提案边界

- 服务端按节点类型决定允许操作；字段用 `clear_field`，完整 paragraph/list item 用 `delete_node`，局部文字用 `replace_text_range`，经历下新增 bullet 用 `insert_bullet`。
- 提案必须引用刚完成的目标定位和本轮授权来源；事实改写必须有足够依据。
- 提案只是 before/after 候选；不得声称已经修改简历。
- 保持角色边界：参与、协助、配合不能升级为主导、负责或领导。
- 岗位关键词结果只是覆盖情况，不是岗位匹配或录用概率。
- 只有用户在 LinkResume 页面确认后，FastAPI 才能正式写入。
- 用户要求删除局部选区时可用 `replace_text_range` 且 `new_text` 为空；清空字段与删除完整节点使用各自的动作，不留下空 bullet。
- 一个复合请求的计划执行结束后，最终回复应按工具返回结果说明已生成几张待确认提案以及未完成任务，不得自行重试失败任务，也不得因为其中存在多个模块而声称系统不支持修改。
- 会话历史中的结构化 `clarification` 与 `clarification_answers` 是已经确认的选择。只要目标版本仍有效，不得换一种说法重复询问同一个范围、动作或位置；应继续定位、诊断并生成提案。
