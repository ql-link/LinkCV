## 6. 风险与阻塞

当前没有已知阻塞。

已知风险：

- 本目录内容较多，如果后续不及时更新，会成为新的过期文档；因此每个可验证小步结束后必须更新本页，收口时必须删除整个目录。
- 项目入口临时指针如果在最终 PR 前未删除，会让正式分支长期引用临时计划；删除条件已写入 `README.md` 和阶段 6。
- 当前“第一批不写外部系统”是风险控制，不代表外部同步永远不做；是否启用必须在阶段 5 前重新确认。
- `.worktreeinclude` 只在创建本地 Codex 托管 worktree 时复制，不能被描述为同步；同一 Spec 若在多个 worktree 分别修改，没有 Git 冲突保护。
- `.specs` 内容保持本地，但 `.worktreeinclude` 本身是跟踪文件；提交规则会把规则推到远端，不会把本地 Spec 内容推到远端。
- 删除状态层后不再自动提供文档漂移检测、旧测试快照复用、唯一下一阶段或活跃任务列表；这是已经接受的取舍，不通过另一份状态文件补回。
- 多份本地 Spec 同时可能匹配且无法从分支、内容和差异确定时，必须询问用户，不能猜测活跃任务。
