# AI 助手与简历流程人工测试手册

## 1. 目的与适用范围

本文用于在 Local 或 Development 环境中人工验收以下已实现能力：

- AI 助手查询当前用户的简历、已解析资料和面试记录；
- 用户直接按简历名称或 ID 发起分析，无需把简历正文绑定到会话；
- 简历诊断与修改、整篇保真翻译、面试指南、职业规划和简历标题建议；
- 手工创建简历时拒绝同名，文件导入重名时自动追加数字后缀；
- 中文输入法组合态、真正的逐段流式输出、停止生成；
- 生成期间切换页面、切换会话或刷新后恢复运行状态和输出；
- 翻译提案的 `proposed_title`、确认后新简历和数据库迁移兼容。

本文给出的 AI 回答是“语义级期望”，模型措辞和段落顺序允许变化。验收时判断它是否使用了正确资料、是否遵守读写边界、是否出现可观察的流式增量，不要求逐字一致。

所有用例初始状态均为 `未执行`。执行后记录为 `通过`、`失败` 或 `阻塞`，不能把自动化测试通过等同于人工端到端验收通过。

## 2. 测试前准备

### 2.1 启动环境

根据要连接的中间件选择一个 profile：

```bash
# 全部使用本地中间件
npm run dev:local

# 本地代码连接共享 Development 中间件
npm run dev:development
```

不要用 `APP_ENV` 猜测实际加载了哪个配置文件；以启动器打印的“基础配置”和“共享私密覆盖”路径为准。默认端口是 Web `5173`、FastAPI `18000`、Pi `8010`，如果端口被覆盖，以启动日志为准。

确认以下条件：

1. Web 页面可打开；
2. `GET /api/health` 返回 HTTP 200；
3. Pi 的 `/health` 返回 HTTP 200；
4. Development 数据库已升级到 Alembic `0065`；
5. 管理端已为 `pi_agent` 绑定可用模型；
6. 浏览器已登录专用测试账号。

数据库版本可在加载相同 Development 配置的终端中查询：

```bash
LINKRESUME_ENV_FILE=.env.development uv run --directory apps/backend alembic current
```

输出应包含 `0065 (head)`。这只能证明 Alembic 记录，需要排查 schema 漂移时还要核对 `resume_change_proposals` 是否真实存在 `proposed_title` 和 `result_resume_id` 列，并确认 `agent_sessions` 已不存在 `resume_id`。不要在截图、文档或缺陷记录中粘贴数据库密码、Cookie、内部 Bearer token 或模型密钥。

### 2.2 建议的虚构测试数据

使用专用测试账号，数据中不要出现真实姓名、电话、邮箱或真实公司机密。建议准备：

| 类型 | 名称 | 用于断言的虚构内容 |
| --- | --- | --- |
| 中文简历 | `张三-后端开发` | Java、Spring Boot；“将订单接口 P95 延迟从 800ms 降至 420ms” |
| 另一份简历 | `张三-数据分析` | Python、SQL；不包含 Spring Boot |
| 资料 | `后端岗位JD.md` | 要求 Java、MySQL、接口性能优化 |
| 求职记录 | `示例科技-后端开发工程师` | 当前阶段为“一面待安排” |
| 面试记录 | `示例科技一面` | 虚构复盘：“事务隔离级别回答不完整” |

为测试导入重名，再准备三个文件，文件 stem 都是 `导入测试简历`，可以放在不同本地目录，内容分别写明“导入样本 A/B/C”。

### 2.3 浏览器观察方式

打开开发者工具的 Network 面板：

1. 勾选 Preserve log；
2. 发送消息后找到会话 `messages` 请求或 run 的 `events` 请求；
3. 确认响应类型为 `text/event-stream`；
4. 查看事件是否按时间先后出现，而不是请求结束时一次性出现；
5. 缺陷记录只保留事件类型、时间和安全化文本，不复制鉴权请求头。

## 3. 基础资源与权限

### TC-RES-01 查询本人资源目录

状态：`未执行`

步骤：

1. 进入“AI 助手”，点击“新建对话”。
2. 不通过 `@` 添加任何上下文。
3. 输入：`你好，我有哪些简历、资料和面试记录？`
4. 等待回答完成。

期望结果：

- 回答列出当前账号拥有的简历、已解析资料和面试记录，能看到准备数据中的名称；
- 列表可以包含 ID、状态、版本或更新时间等轻量元数据；
- 不直接倾倒简历正文、资料正文或面试复盘全文；
- 不要求用户先绑定会话或重新上传文件；
- 不出现其他账号的数据。

语义级期望回答示例：

> 你目前有 2 份简历：张三-后端开发、张三-数据分析；有 1 份已解析资料：后端岗位JD.md；有 1 条面试记录：示例科技一面。

### TC-RES-02 按名称读取简历且不绑定会话

状态：`未执行`

步骤：

1. 新建一个没有默认简历的对话。
2. 输入：`请分析简历「张三-后端开发」，重点看后端岗位匹配度。`
3. 等待回答完成。
4. 在同一会话继续输入：`现在改为分析「张三-数据分析」中的技能结构。`

期望结果：

- 第一轮直接解析并读取 `张三-后端开发`，不要求通过 `@` 绑定正文；
- 回答引用该简历独有的 Spring Boot 和 P95 延迟事实，不得把岗位要求写成用户已经具备的事实；
- 第二轮可以改用另一份简历，说明选择只作用于当前运行；
- 第二轮不得沿用第一份简历的 Spring Boot 或 P95 数据；
- 会话本身不被强制绑定或改写为某一份默认简历。

不应出现的回答：

> 请先在简历模块中用 `@` 绑定该简历正文，然后重新发送请求。

### TC-RES-03 历史同名简历的版本选择

状态：`未执行`

此前已经存在的历史同名简历不会被迁移自动改名。本用例需要一个保留有历史同名数据的 Development 测试账号；不要为了构造数据直接修改共享数据库。

步骤：

1. 输入：`请分析简历「同名测试简历」。`
2. 在助手返回的候选中记录两个版本的 ID 或更新时间。
3. 回复：`选择更新于 2026-09-13 的版本。`

期望结果：

- 首轮不能猜选，应该列出属于当前用户的同名候选；
- 用户给出足够明确的更新时间后，助手使用对应候选 ID 继续读取和分析；
- 不再次要求通过 `@` 绑定简历；
- 如果版本条件仍不能唯一定位，只追问一个会实质影响选择的问题。

### TC-PERM-01 用户数据隔离

状态：`未执行`

步骤：

1. 使用测试账号 A 记下一份简历名称和页面显示 ID。
2. 退出并登录测试账号 B。
3. 分别用该名称和 ID 请求分析。
4. 再询问：`我有哪些简历、资料和面试记录？`

- 资源目录只显示账号 B 自己的数据。

## 4. P0/P1 助手工作流

### TC-AI-01 整体简历诊断

状态：`未执行`

步骤：

1. 输入：`请对「张三-后端开发」做整体诊断，重点看岗位关键词、结果证据和表达问题。`
2. 如果助手要求选择方向，选择“整体全面诊断”。
3. 等待结果并展开引用资料或修改内容区域。

期望结果：

- 结论能追溯到简历正文和已选 JD；
- 关键词覆盖率只能描述文本覆盖，不声称是录用概率；
- 认可定性成果，也可以指出量化证据不足，但不能把“缺数字”一律判定为高风险；
- 只生成待确认的修改建议或提案，不直接改写简历；
- 前后差异展示目标简历名称和真实修改内容。

语义级期望回答示例：

> 已有证据：简历明确写有 Spring Boot 和订单接口性能优化，P95 从 800ms 降至 420ms。通用建议：补充 MySQL 优化中你实际负责的范围；在没有原始事实时我不会代填数字。

### TC-AI-01B 复合占位清理主动拆分

状态：`未执行`

前置数据：教育经历包含一个虚构占位字段 `asd`；LinkRag 项目末尾包含 3 条正文仅为 `1` 的 bullet，并另有至少一条真实 bullet。

步骤：

1. 输入：`帮我修改当前简历`。
2. 在结构化澄清中选择“清理占位内容”。
3. 等待运行完成，记录本轮生成的全部提案。
4. 在 Network 中检查同一 SSE 请求里的活动状态事件。
5. 依次确认这些提案，每次确认后检查简历和其余待确认提案。

期望结果：

- Agent 不把跨教育经历和 LinkRag 的多个目标归因为超出可写范围，也不要求用户手动逐条重新发起请求；
- 同一 run 为教育字段和 3 个 LinkRag 列表节点生成 4 张独立待确认提案，最终回复准确说明提案数量；
- 活动顺序严格按任务逐项出现，每个 `callKey` 从 `running` 原位更新为 `succeeded` 或 `failed`，页面不重复堆叠“定位/读取/创建提案”；前一目标完成前不会开始下一目标；
- 删除 `asd` 使用字段清空，删除 3 条 `1` 使用结构化节点删除，确认后不留下空 bullet；
- 确认第一张提案导致简历版本变化后，其余目标未变化的提案仍可依次确认；若测试中手工改写某个待删目标，只有对应提案返回 `TARGET_STALE`；
- 任一工具失败不得被错误展示为笼统的“当前模型请求失败”，日志可按同一 run ID 定位到具体工具和稳定错误码。

### TC-AI-01C 已打开简历作为隐式上下文

状态：`未执行`

步骤：

1. 在独立 AI 助手中通过“我的简历”打开一份虚构测试简历。
2. 不输入 `@`，连续发送两轮普通问题。
3. 刷新页面并重新打开该历史会话。

期望结果：

- 前两轮请求的 `contexts` 都包含当前打开简历且标记为 `presentation=implicit`，FastAPI 仍按本人归属和最新版本读取 canonical 简历；
- 输入框和发送后的两条用户消息只显示用户输入正文，不在开头增加简历引用单元，刷新历史后仍保持不显示；
- 手工 `@` 选择的资料继续在输入框和历史用户消息原位置显示引用单元；
- 关闭简历后，后续未显式选择简历的请求不再自动附带该简历上下文。

### TC-AI-05 整篇保真翻译与 `proposed_title`

状态：`未执行`

步骤：

1. 记录 `张三-后端开发` 当前内容和版本。
2. 输入：`把「张三-后端开发」整份翻译成英文，保留原稿。`
3. 检查页面生成的待确认翻译提案。
4. 在确认前回到“我的简历”，确认没有新增简历且源简历未变化。
5. 返回会话，确认提案。
6. 再次打开“我的简历”，打开新简历和源简历进行对照。

期望结果：

- 提案模式是整篇翻译，不混入润色、压缩、扩写或 STAR 重写；
- `proposed_title` 是确认后新简历使用的候选标题，它不是对话标题，也不会在提案创建时立刻改名；
- 确认前源简历不变且没有创建新简历；
- 确认后创建一份独立、可编辑的新简历，源简历仍不变；
- 日期、数字、联系方式、URL、节点结构和样式保持不变，仅面向读者的自然语言被翻译；
- 重复确认同一提案返回同一份结果简历，不重复创建。

## 6. 输入、流式输出与运行续接

### TC-INPUT-01 中文输入法组合态

状态：`未执行`

步骤：

1. 将系统输入法切换到中文拼音。
2. 聚焦助手输入框，依次键入 `ni`，不要按发送。
3. 继续选择候选词“你”，再键入 `hao` 并选择“好”。
4. 在另一次输入中键入拼音并按 Enter 选择输入法候选。

期望结果：

- `ni` 组合期间不会被提前提交或截断为 `i`；
- 候选确认后输入框显示“你”，继续输入后显示“你好”；
- 输入法组合期间 Enter 只用于候选选择，不触发消息发送；
- 光标不会被程序重置到错误位置。

### TC-STREAM-01 验证真正的增量流式输出

状态：`未执行`

步骤：

1. 打开 Network 面板并清空记录。
2. 输入：`请基于「张三-后端开发」给出一份详细的后端面试指南，至少包含 6 个问题及回答骨架。`
3. 同时观察消息区域和对应 SSE 请求。
4. 在回答未结束时记录至少三个时间点的页面文字长度。
5. 检查 SSE 事件顺序。

期望结果：

- 页面在运行完成前多次增长，而不是长时间空白后一次性出现全文；
- SSE 中出现多个 `assistant.delta`，随后才出现唯一的 `run.completed`；
- 每个可见文本 delta 到达后立即追加到当前回复；
- 思考内容和工具调用参数不混入回复正文；
- 一次成功流只能有一个 `run.completed`、`run.cancelled` 或 `run.failed` 终态。

判定失败的典型现象：Network 中已有多个 `assistant.delta` 但页面不更新，或服务端直到 `run.completed` 前才一次性发出全部正文。

### TC-STREAM-02 停止生成与部分输出

状态：`未执行`

步骤：

1. 发起一个较长请求。
2. 页面已经出现部分文字后点击“停止生成”。
3. 刷新当前会话。

期望结果：

- 页面立即进入取消中并最终显示“已停止生成”；
- 当前页面保留已经显示的部分文字，便于用户理解停止位置；
- 未完成的部分回答不能作为一条成功的历史助手消息持久化；
- 已发送 query 只保留在消息历史，输入框和上下文引用保持清空，不自动复制 query；用户需要重试时自行重新输入或复制历史消息。

### TC-CONT-01 生成中切换业务页面

状态：`未执行`

步骤：

### TC-DB-01 `0065` schema 与提案列表

状态：`未执行`

步骤：

1. 确认目标数据库 Alembic revision 为 `0065`。
2. 核对 `agent_sessions` 不再包含 `resume_id` 列和 `idx_agent_sessions_resume_pinned_updated` 索引；确认升级前已有对话仍存在，且原来只有会话绑定、没有消息上下文的历史用户消息已经得到对应简历快照。

期望结果：

- 普通问候不会因为加载提案列表而出现“智能助手没有完成这次请求，请稍后重试”；

- 提案列表可读取 `proposed_title` 和 `result_resume_id`；
- 未确认时 `result_resume_id` 为空；确认翻译后它指向新创建的简历；
- 辅助提案列表加载失败不得把一个仍在进行或已经完成的模型运行误报为失败。

## 10. 常见失败定位

| 现象 | 优先检查 |
| --- | --- |
| 普通问候后出现“智能助手没有完成” | Development 数据库是否实际升级到 `0065`；提案列表请求是否查询缺失字段 |
| 回答结束后一次性出现 | Pi 是否逐个转发 `text_delta`；SSE 是否有多个 `assistant.delta`；Web 是否即时追加 delta |
| 切页或刷新后会话为空 | 当前会话 URL、最近会话恢复、`active-run` 查询和 run 事件重放 |
| 切页后生成被取消 | 页面卸载时是否错误调用 cancel，而不是仅断开浏览器订阅 |
| 取消后 query 又出现在输入框 | `cancelCurrentRun`、`run.cancelled` 和流结束分支是否都清空 composer 与持久化 draft |
| 修改活动重复出现或一直“运行中” | `assistant.activity.status` 是否按稳定 `callKey` 原位更新终态；旧 `activity.delta` 是否已与结构化活动去重 |
| 拼音 `ni` 被截断或提前发送 | `compositionstart`/`compositionend` 与 `isComposing` 处理，组合期间是否重写编辑器 DOM |
| 指定简历后仍要求绑定正文 | 是否先按名称/ID调用本轮简历解析，再读取该目标；不要把 `@` 当强制入口 |
| 导入后出现完全同名卡片 | Worker 是否在持久化事务内计算最小可用数字后缀，页面是否展示最新结果 |
| 翻译确认覆盖源简历 | 提案是否为 `translate_resume`，确认分支是否创建独立 Resume 并写入 `result_resume_id` |
