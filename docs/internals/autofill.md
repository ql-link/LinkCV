# 浏览器网申填写

网申填写已合并到统一 LinkResume 求职助手 `apps/extension`，与岗位采集共用扩展身份、登录客户端、Manifest、版本和发布渠道。用户先在对应环境的 Web 登录，然后从侧边栏选择简历导入；也可在 Web 简历卡片菜单点击“用于插件网申”。Web 命令只携带简历 ID，后台通过受保护 API 获取资料并再次校验账户归属。

## 数据投影

FastAPI `modules/browser_extension` 提供本人简历轻量列表及 `autofill-profile` 投影，不返回版式、图片、布局或其他简历内容。姓名、联系方式、教育、工作、项目、技能等来自所选 canonical 简历；意向城市、薪资范围、工作年限和工作性质来自本人求职画像。账号昵称和登录邮箱不推断为投递姓名或联系方式。工作模块只有标题明确包含“实习”或 internship 时进入实习分组；其他保留工作分组。经历保持文档顺序，包括空条目。未知字段和无法确定的日期保留缺失提示，不生成个人信息。

投影版本为 1，带账户 ID、简历 ID、简历及画像锁版本。个人资料缓存于 `browser.storage.session`，绑定 Origin 和账户，内容脚本无权直接读取；退出或账户变化被检测到时清理。开始填写前重新拉取所选简历，执行前再次核实身份，本次使用固定快照。浏览器重启、扩展更新或禁用后缓存清空。首版没有离线填写和 Web 网申补充资料持久化；缺失资料由用户在招聘页面补充。

导入可选语义增强缺失、经历只有正文时，投影在读取阶段仅识别有明确分隔符和有效日期区间的学校或单位头部；不推断学历、学习性质或未写出的个人资料。不明确的经历头保留空位置，不把后面的经历前移；工作正文只归属相邻的明确头部。项目正文仅使用明确的项目名称或带技术架构/描述提示的紧凑首标题，不把可能混合的项目描述归到同一个项目。明确的“中文姓名 - 职位”标题在投影里分离姓名。现有结构化条目优先，读取不改写原简历，保守提取和缺失结果通过 `warnings` 提示。

画像 `application_data` 提供用户确认的补充事实，仅限明确关联的当前简历。基础资料按适用简历列表限制；经历按原投影条目下标与完整指纹共同验证，变化时跳过并提示重新确认。来源重复或字段冲突跳过，未关联条目不参与填写；用户明确关联的手动补充作为额外条目，不与已有数组按位置合并。补充条目至少有明确学校、单位、名称或语言考试；不确定的零散分数不能作为额外经历。校园经历新增 campus 分组。学习形式 studyMode 与培养方式 trainingMode 分开，籍贯 hometown 不替代高考生源地 gaokaoOrigin。语言考试名称不替代分数；护照/身份证号码字段还须与明确的证件类型对应。输入限制和接口见[HTTP 契约](../api/http-contracts.md#用户中心)。

## 代码与调用链

- `entrypoints/sidepanel`：账户连接、简历导入、任务进度和字段结果。
- `src/api/autofill.ts`：版本化投影、本人列表与会话缓存。
- `src/autofill/profile`、`decide/plan.ts`：字段目录、取值、格式转换和保留已有内容规则。
- `src/autofill/decide/jev.ts`：调用 LinkResume 识别接口，最多四个并发请求，不持有第三方密钥。
- `src/autofill/scan`、`writer`：招聘页面扫描、经历补齐与组件适配。
- `entrypoints/autofill.content.ts`：用户点击后按站点授权并注入。

填写链为授权、读取最新快照、注入、补齐经历、扫描、后端判断字段、核实账户、本地生成计划、写入和标记。页面消息绑定文档 token 与 URL，跳转、切换标签页、关闭侧栏或停止时取消后续操作；已经写入的内容保留，停止不能撤销当前正在执行的单个控件操作。默认保留已有内容，写入每个字段前再检查用户是否已输入，低置信度、缺失值和失败字段留给用户核对，不自动提交，也不更新求职记录投递状态。

自动填写只接受明确事实字段：标签/提示与字段目录一致，且概率至少为 0.9（用户设置更高时使用更高阈值）。第一志愿、应聘岗位、意向部门、调剂、历史经历工作性质和多选控件跳过，跳过的选择字段不调用模型。求职画像不能替代历史工作性质。字段标签不跨表单项查找；自定义选择框使用自身有界提示，区分证件类型和号码。多个选择值不擅取第一项，年月资料不补造具体日期，中文姓氏和年龄不从其他字段猜测。工作/实习模块采用一致的计数键，紧邻同名公司框仍是不同经历；本类资料为空时才使用另一类来源，不把两类资料无条件拼接。混合模块同时有工作和实习两组来源且顺序不明确时留给用户。补齐经历必须先识别已有容器；旧选择器未命中或合并顺序不明确时不点击添加按钮。日期只用明确的开始/结束提示，不因两个相同标签相邻而改写日期含义。

普通可编辑文本和受支持的选择组件必须在写入后读回目标值才能统计为“本轮已填”。选择只使用唯一精确文本、归一化等值或已定义的同义选项，不采用包含关系或相似度选择学校/公司。美团及 Ant Design 远程搜索匹配失败时恢复原搜索词，搜索输入不作为选中结果；未知自定义控件不再使用文本兜底。日历需要具体日而来源只有年月时不选择默认 1 日；Ant Design/atsx 区间控件尚无同一控件两个端点的确定调用契约，暂时跳过。缺失资料、无法精确匹配和不支持的控件保留待处理原因，用户选择项显示为“跳过”。

侧栏分别统计“本轮已填”和“保留已有”，保留页面原值不算本轮写入。“清除标记”只移除高亮和本轮结果；“全部清除”在用户确认后重新扫描当前页面，清空可编辑的文本、原生选择框及有清空入口的自定义组件，并取消可操作的勾选项，包含手动输入和之前各轮填写的内容，无需先选择简历或连接账户。清除仅申请当前站点权限，绑定当前文档与 URL，切换页面、停止或关闭侧栏会取消后续操作。附件、隐藏字段、密码、验证码、禁用及只读文本保留，不删除经历容器、不提交表单；不能清空或被组件恢复的选项会列为未清空，不以输入框表面为空判定下拉选择已清除。

## 模型与权限

后端统一 LLM 场景 `browser_autofill` 支持 OpenAI Chat 结构化识别和 System One 原生决策，管理员在能力配置中绑定、探测并启用。探针必须识别虚构学校字段，通用连通性不能替代。密钥仅存在后端；发送给模型的内容为有界标签、模块、提示、控件类型、最多六个选项与固定字段目录，不包含简历值或完整 DOM。服务端目录与插件字段目录有一致性测试。

Jev 通过 AIHubMix 连接使用 `jev-1.13` 或 `jev-latest` 调用目标，能力绑定协议必须为 `system_one`（管理台显示“原生决策（System One）”）。后端发送 `model`、`state` 和带固定候选目录的 `questions.slot` 到 `/v1/systemone`，将 `answers.slot.choice` 和 `probabilities` 转换为插件的 `choice`、所选项概率 `prob` 与概率前三项 `ranked`；`confidence` 不替代所选项概率。管理台为 Jev 自动选择原生协议，服务端拒绝把它绑定到 Chat 协议。先加入“网申字段识别”能力，再启用并通过专用探针；线路、能力绑定和连接全部有效后才可调用。修改连接密钥会使旧探针失效，需要重新启用验证。

单页最多 200 个字段，每用户识别接口每分钟最多 240 次，Redis key 为 `browser-autofill:decisions:<user_id>`，TTL 60 秒。服务端单次预算 20 秒，插件 25 秒；未配置模型、限流、认证失败或服务不可用有明确反馈，不无限重试。现有模型路由、计量与日志治理继续复用。

Manifest 声明 storage、scripting、activeTab、tabs 和 sidePanel。`tabs` 用于读取当前标签页 URL，使尚未授权的 HTTP/HTTPS 网申页面也能启用填写入口；侧栏按钮不会触发 `activeTab`，不能依靠它获取首次授权所需的 URL。固定主机权限仅 BOSS 和对应 LinkResume 源站；用户点击“开始填写”后首先通过可选主机权限申请当前 Origin 的访问权，允许后才读取最新简历并注入内容脚本。拒绝授权时不注入、不扫描、不写入；授权弹窗期间刷新或切换标签页会取消本次任务。未声明第三方模型的固定主机权限。

## 开发与验证边界

安装与开发见 [统一插件 README](../../apps/extension/README.md)。字段格式见 [字段说明](../../apps/extension/docs/profile.md)，写入层见 [适配说明](../../apps/extension/src/autofill/writer/README.md)。旧独立插件存储不会跨扩展身份迁移，需重新从 Web 导入资料。

当前只扫描顶层文档，不进入 iframe。读回验证控件当前展示的值，不代表招聘网站服务端已保存或接受投递；真实 Chrome Cookie、权限弹窗、招聘网站控件及 Web 桥接完整链路需要人工验收，单元与接口测试不能替代。
