# Web 模块

## 功能与架构导航

本页维护 Web 运行入口、路由、共享 UI、视觉交互和前端测试边界。跨端业务规则分别见[账号](../features/identity-account.md)、[简历工作台](../features/resume-workbench.md)、[求职中心](../features/career-center.md)、[AI 助手](../features/ai-assistant.md)和[资料集](../features/datasets.md)；系统日志与插件制品属于独立[可观测性](observability.md)和[插件制品](plugin-delivery.md)架构。

## 职责与入口

- `apps/web/src/main.tsx`：React 启动入口。
- `apps/web/src/App.tsx`：页面状态与主要功能组合。
- `apps/web/src/features/`：鉴权、首页、编辑器、预览、临时 JD 管理和管理端功能。
- `apps/web/src/store/resumeStore.ts`：简历编辑状态。
- `apps/web/src/api/client.ts`：鉴权、模板、简历与异步导入、智能助手 SSE、JD、资源、日志上报和管理员查询 API 客户端。
- `apps/web/src/api/resumeContract.ts`：语义简历 TypeScript 契约，以及领域 JSON、Markdown 和现有 Tiptap 编辑器之间的过渡适配。
- `apps/web/vite.config.mjs`：开发服务器、FastAPI 代理和本地图片预览插件。

生产构建按页面路由拆分 React 功能包，公共 HTML 不依赖 Google Fonts 等境外样式服务；入口只加载应用壳和当前页面所需代码。简历字体随应用发布，霞鹜文楷使用 Medium 字重，思源宋体和 Noto Sans SC 使用 Regular 字重，三者均来自固定版本的本地字体文件；PDF CLI 复用这些完全相同的字体文件，并等待 `document.fonts.ready` 后才测量分页。

## API 调用

API 客户端只发送相对 `/api/...` 请求并携带 cookie，不在业务组件中写死后端主机。每次请求附加 `X-Request-ID`，错误对象保留服务端回传的追踪值；API 5xx 会异步上报稳定错误码和追踪值，不发送原响应 body。开发期全部 `/api` 请求由 Vite 代理到 FastAPI，见 [架构文档](architecture.md#本地请求路径)。短 access 过期后，受保护请求会复用单个 `/api/auth/refresh` 请求轮换双 Cookie，并重试一次原请求；应用启动时 `/api/auth/me` 返回空用户也会先尝试 refresh，再判定为访客。

React 根入口用 Error Boundary 和 `error` / `unhandledrejection` 监听器捕获登录态页面的未处理异常，通过 FastAPI 受保护入口进入统一日志链路；上报失败被吞掉，不能形成递归上报或替代原始页面错误。上报内容限制为错误类型、消息、栈和可选 request ID，不发送 Store、表单、简历正文或浏览器 Cookie。

普通登录页 `/login` 先读取 `/api/auth/capabilities`。Local/Development 根据路由模式展示邮箱密码登录或注册表单，两者可以互相切换，也可以切换到 `WechatQrLogin`；Production 对登录与注册链接都不渲染邮箱密码表单，直接请求二维码并每 2 秒轮询 scene。`success` 时后端设置双 Cookie 并进入工作区，`cancelled/expired` 或生成失败时停止轮询并提供刷新。Landing 的“登录”进入登录模式，“开始使用”进入注册模式。个人资料页不显示改密或微信绑定操作；管理员密码表单仍只保留在 `/admin/login`。

新增或迁移接口时同时检查：

1. `src/api/client.ts` 的路径和响应类型；
2. `vite.config.mjs` 的路由归属和目标；
3. FastAPI 的真实路由；
4. [HTTP 契约](../api/http-contracts.md)。

简历 API 已统一使用 `snake_case`、唯一 `ResumeDocument data` 和 `ResumePresentation style`，运行期不再保留版本联合类型。`data.semantic_sections` 保存显示标题、稳定语义和真实内容引用，`style.manifest` 保存受控区域、插槽、兜底区和头像策略。编辑器以 Tiptap JSON 作为已编辑正文的唯一持久化真值，保存时先移除模板列和系统头像，再按二级标题及其 `blk_*` 锚点拆成独立 `custom_sections`；具有业务语义的节点、marks、对齐、信息行和图片属性原样进入 `{format: "tiptap-json"}`，不经过 Markdown 降级。持久化边界会移除受支持 Tiptap 版本产生的已知无语义默认属性，当前包括 `orderedList.attrs.type: null`；前端保存转换和后端 `RichText` 校验都会执行同一规范化，滚动发布期间的旧前端请求也不会因此失败，非空或未知属性仍由后端严格拒绝。历史 Markdown 和导入 typed sections 继续可读，并在首次正文保存时转成同一规范结构，不再额外保存整篇 `custom_section_editor` 副本。标题重命名只更新 `display_title`，语义类型继续由稳定章节 ID 关联；新增章节获得新 ID 并进入待分类链路。

简历主页卡片使用后端摘要中的真实 `data/style` 只读预览；编辑工作台只在内存中把规范编辑树投射到当前 `TemplateDefinition`，模板切换先反投影回全局语义顺序，再生成目标区域、插槽、双栏和头像，空插槽提示不写入正文。反投影会按模板 LayoutPlan 的全局规范顺序合并 columns 区域，避免把教育等侧栏章节追加到末尾。预览纸张、分享页和 PDF 对规范 Tiptap 内容直接使用同一棵投影树和只读渲染器；只有历史 Markdown 走兼容渲染。历史 typed 联系信息在适配时合并为同一个 Markdown 段落，电话、邮箱、地址与个人网站保持一行，网站继续使用受控 HTTP 链接；历史 Markdown 列表只清理行首重复的无序标记及空白实体，保留负数、年份范围、有序列表起始值和嵌套层级。canonical 正文的 `row` 是模板无关的章节内结构：`pair` 固定两格并保留比例，`meta` 四格、`trio` 三格；旧 `::: left/right` 与 `:::: meta/trio` 只在 cutover/兼容输入中解析，规范正文和新保存不包含原始标签，模板级 `sidebar/main` 不作为用户正文跨模板继承。`TemplateDefinition.avatar` 决定头像是否显示、尺寸和 region；用户头像始终保留在 identity，系统猫咪 fallback 只存在于工作台、预览和 PDF 的投影，不写回正文，隐藏模板也不删除用户头像。切换请求把当前标题、规范内容、目标模板和锁版本一次提交，避免预保存与切换之间出现并发半状态。白名单内图标在 canonical 中保存为 `InlineIcon` 或章节 `title_icon`，投影到 Tiptap 时恢复成真正的 `inlineIcon` 节点；`:icon[Name]:` 只在 Markdown/Agent 兼容边界出现，未知标记仍按普通文本显示。历史结构无效时显示“预览不可用”，不阻断列表。正式简历卡片可打开、重命名、分享或删除；重命名只更新列表识别用的标题，不会写入简历正文。主页只展示简历和导入任务；工作区导航中的“简历模板”进入独立 `/templates`，读取当前启用模板并提供只读预览；用户从模板卡片点击“创建简历”后在弹窗内填写名称，确认后直接创建并进入编辑器，不再经过 `/resumes/new`。旧的 `/resumes?view=templates` 仍按普通简历列表处理。独立 `/resumes/new` 仍承载从简历主页进入的创建与导入流程：创建模式要求选择启用模板并输入名称，导入模式要求选择 Markdown、DOCX 或 PDF 文件并使用生产保留的 `classic-technical-cn` 默认版式；如果该模板不可用则回退到第一套非 `blank-cn` 的启用模板。`blank-cn` 已退出可选产品目录；数据库只会在仍有历史引用时保留 `is_active=0` 的身份 tombstone，Web 模板列表、新建、导入回退和切换均不会把它作为可选项。注册成功后只进入空主页，不自动创建第一份简历。

模板的 `accent_color` 通过同一个 `--preview-accent` 呈现变量进入编辑工作台、只读预览、公开分享和 PDF 文档；经典技术模板的标题、章节标题、链接和分隔线因此在四个消费面保持一致，不再由各页面各自使用固定颜色。

主页的“导入简历”在当前列表上打开短流程弹窗，不跳转到新建页。弹窗只选择 Markdown、DOCX 或 PDF 并确认简历名称，不展示模板选项；前端内部使用生产保留的经典单页技术版式，并把确认后的名称与原扩展名组合成 multipart 文件名，后端继续按上传文件名生成正式简历标题。每次提交生成新的 UUID `Idempotency-Key`，access 刷新重放保持同一个 Key。受理成功后弹窗关闭，主页显示上传中、解析中和失败导入任务。只有上传成功且仍在解析的任务会挂载独立轮询器，每个任务每秒调用一次单任务状态接口；慢请求不会重叠，多个文件分别轮询，任务进入成功或失败终态后对应轮询器卸载。成功终态会一次性刷新 overview 以展示正式简历，失败任务可删除。前端不持有 MinIO、LinkParse 或结构化模型凭据。

资料库 `/datasets` 在工作台页头复用 `ExpandableSearch`，下方使用单一正式列表展示资料名称、上传时间、大小和解析状态，不按源文件格式分类，也不显示扩展名、格式标签或行首图标。上传弹窗只保存尚未受理的本地文件、上传进度和可重试失败；每个本地文件创建一个 UUID 幂等键，同一次不明确结果重试复用该键，明确开始新尝试时才换键。后端返回受理成功后弹窗立即移除该项并将记录写入正式列表，列表把 `queued/processing/succeeded/failed` 映射为“等待解析、正在解析、解析完成、解析失败”并轮询活动任务。单批文件数、单文件大小和并发上限读取后端 `limits`，不在前端形成第二套固定契约。解析成功资料点击整行直接按资料 ID 请求 `/api/datasets/:id/content`，在带焦点约束的阅读弹窗中渲染 Markdown；原始 HTML 不执行，图片只显示文字占位，不由浏览器加载转换内容中的外部资源。带 `mermaid` 标识的代码块在内容挂载后按需加载 Mermaid 并以严格安全配置渲染，单图失败时保留转义后的源码，不影响其余正文和图表。行尾菜单提供重命名和永久删除，解析失败资料还可复用源对象重新排队；页头批量操作模式支持选择当前筛选结果，并在二次确认后逐条调用既有删除接口，部分失败时仅移除成功项并保留失败资料。写操作成功后就地同步列表，失败时显示稳定错误反馈。

版本记录入口与页面设置并列在右侧编辑面板顶部，顶部工作栏只保留统一的“设计”入口；用户可以在同一抽屉中切换两个面板而不关闭抽屉。版本列表只读取后端正式版本，不展示当前草稿；每个版本卡片以版本名称为主标题，并在名称旁提供铅笔图标。点击后名称变为行内输入框，按 Enter 调用版本重命名接口保存，按 Esc 取消；重命名只更新该版本的名称，不改变简历正文、当前简历标题或版本数量。列表同时补充版本号、时间和系统原因。自动保存请求串行执行，并在每次成功后接续服务端返回的 `lock_version`；顶部“保存简历”按钮立即调用同一保存链路，把当前标题、正文和页面样式写回简历主记录。版本记录中的“保存版本”先打开命名对话框，确认有效名称后再保存当前简历并调用版本创建接口，取消或名称无效不会触发保存。点击恢复后，工作台先通过版本详情接口读取完整 `data/style`，展示正文行级差异和页面设置差异；只有再次确认才调用恢复接口，取消、关闭和无差异状态不写数据。恢复只用目标快照替换当前编辑内容，不创建新版本或占用版本额度；恢复期间临时禁止编辑，成功后使用后端快照刷新。`smartOnePage` 作为 `ResumePresentation.smart_one_page` 随当前快照和历史版本持久化。编辑器图片上传使用当前简历的私有资源接口。

工作台使用简历画布右下角的白底蓝色星芒胶囊入口打开独立右侧抽屉，页头不重复放置助手按钮；入口与抽屉共用同一 AI 标识，并在抽屉打开后保留收起状态，移动端沿用工作台侧栏的覆盖布局。编辑器为每个文本块维护不可见且随 Markdown 持久化的稳定块 ID；选中文字后在选区上方显示精简格式浮层，其中的“AI 修改”提供“优化表达、生成亮点、调整专业度、解释内容、继续改写”快捷入口，把块 ID、范围、所选正文和 SHA-256 作为可移除上下文带入同一个助手侧栏，不把正文拼接进用户消息。带选区发送前先保存当前草稿，确保 FastAPI 能在同一版本解析 locator；保存失败不发起 Agent Run。`AgentPanel` 使用带副标题的简洁页头、浅蓝对话气泡、带图标的快捷操作和内嵌圆形发送按钮，自带新建对话与关闭操作；它通过 POST SSE 展示定位、读取、资料召回、诊断和提案工具状态，并提供重新生成。关闭或停止时取消当前请求，正常 EOF 前未收到完成、失败或取消终态会显示连接中断，而不把半条响应当作成功。范围化提案卡优先按 operation 展示 before/after 和修改依据，旧快照提案继续按发生变化的简历区域展示；用户确认前仍会再次保存当前草稿。保存失败、目标失效、提案冲突或 Agent 不可用都保留现有编辑内容。确认成功后重新读取简历和版本列表。浏览器只持有用户 Cookie，不读取 Pi 服务地址、服务 token 或模型 API Key。

工作区一级导航的 `/assistant` 是独立“AI 求职助手”工作区，其中 `/assistant` 表示新建对话，已有会话使用 `/assistant/:sessionId` 独立地址；点击历史会话会更新地址，刷新或直接打开该地址会重新读取同一会话。工作区复用同一用户会话、POST SSE、结构化澄清和提案确认协议。左侧显示最近会话并支持新建，主区域提供快捷任务、对话、停止/失败保留、阶段状态和输入框；移动端把会话列表折叠为覆盖菜单。用户可从简历、历史版本、岗位、求职进程和面试复盘中各选择至多一项作为当轮上下文，浏览器只提交服务端返回的轻量引用和版本标记，不把正文拼入消息；用户消息以标签展示实际引用。页面通过 `/api/agent/readiness` 显示检查中、已连接或不可用，只有用户仍靠近消息底部时才自动跟随新增内容。独立会话在第一次成功发送带简历归属的上下文后绑定该简历，后续不能静默改绑。

工作区顶部一级导航使用“求职中心”统一承载岗位、求职进程和面试，不再并列展示“JD 中心”和“面试中心”。求职中心在顶部导航下提供“岗位库、求职进程、面试排期、记录复盘”四个横向子导航，对应受保护路由 `/career/jobs`、`/career/applications`、`/career/schedule` 和 `/career/reviews`；顶部“求职中心”和兼容入口 `/career` 默认进入岗位库。岗位新建、详情和编辑使用 `/career/jobs/new`、`/career/jobs/:jobId`、`/career/jobs/:jobId/edit`，求职进程详情使用 `/career/applications/:id`；详情链接附带 `session` 查询参数时直接打开记录复盘并定位到该场面试。旧 `/jobs` 路由族和 `/interviews?view=overview|applications|schedule|records` 重定向到对应新路由，其中已移除的面试总览进入岗位库，保留历史收藏和插件入口兼容性。

岗位库复用最新版 JD 管理页面的列表、搜索、游标加载、直接删除、智能文字或图片导入、手工新建、来源重复解决和采集插件入口，不恢复 `0034` 已移除的 JD 归档语义。列表与详情额外读取分页求职进程集合，在每个岗位上显示仅收藏、当前阶段或最近历史结果，并提供开始求职、查看进程或再次求职；读取失败时不提供开始入口，避免在未知状态下重复创建。详情继续支持字段就地编辑。浏览器采集插件仍是独立的 `apps/extension` 应用，通过相同 Cookie 会话调用后端导入接口。

求职进程、排期和复盘均读取 FastAPI 的真实求职进程与面试接口。求职进程同时提供看板和列表，覆盖筛选、各轮面试、HR、Offer、已结束与已归档；创建进程必须先选择已有岗位，可选用某个正式简历版本，初始进入筛选阶段。快速新建面试仍按“选择或创建岗位、选择或创建求职进程、创建面试排期”的顺序执行，不生成孤立面试。排期使用按公司共享的七色标记，周视图只绘制整点横线，但拖动与键盘移动按 30 分钟吸附并保持时长；记录复盘按单场面试展示题目、总结和素材，并通过接口持久化完成、取消、调色、复盘与上传结果。

管理端入口为 `/admin`，模型配置页使用 `/admin/llm/models`，日志中心使用 `/admin/logs/system`、`/admin/logs/audit` 和兼容原 LLM 页的 `/admin/logs`。模型页展示 Chat、简历结构化、Pi Agent 和 JD 图片解析四项系统能力；候选模型不再携带能力字段，管理员只填写模型供应商、模型名称、可选 API Base 与 API Key，不填写优先级或价格。供应商选项展示用户可识别的名称，不暴露 LiteLLM adapter 代码；当前支持列表包含以 `dashscope` 路由调用的阿里云百炼（千问）。保存普通候选不改变任何能力绑定，绑定其他能力前会执行对应验证；Pi Agent 运行固定 Tool 探针，JD 图片解析运行真实图片探针，只有对应验证成功才更新绑定。密钥字段只写，编辑留空时不进入 PATCH，显式清除才发送 `null`。模型卡片提供二次确认的删除入口；被任一能力绑定的候选不可编辑或删除，未绑定候选可删除配置、密钥和验证证据，历史调用日志保留模型快照，失败时保留弹窗并显示后端稳定错误。

日志中心的系统页支持按级别、依赖、request ID 和关键词筛选；审计页支持按固定动作、操作者、目标和结果筛选；两者展示最近 24 小时摘要、部分脏行提示和游标分页。LLM 页继续读取 MySQL 中的真实调用记录，支持来源、状态、模型、用户、精确 `callId` 和时间范围筛选。三个页面都只通过 FastAPI 查询，不直连 Loki，也不轮询。后端保留既有 `resume.pdf_export` 客户端审计契约以兼容已有调用方；当前工作台的文字版 PDF 下载链不调用该接口。

管理端新增 `/admin/templates` 模板工作区，可查看启用、停用和结构无效模板，上传严格 JSON 包、真实预览并幂等启停；不提供覆盖或删除。`/admin/plugins` 提供插件发布管理。

## 视觉与交互基线

- 登录后功能区的视觉语言与机器可读 Token 见根目录 [`DESIGN.md`](../../DESIGN.md)。`src/design-system/tokens.css` 是浏览器运行实现，`tailwind.config.cjs` 提供语义 utility 映射，`src/design-system/utilities.css` 是 Tailwind utilities 的全局入口；保持 `preflight: false`。
- shadcn primitive 与 LinkCV 通用组合组件只放在 `src/components/ui/`，页面统一从 `@/components/ui` 导入；`components.json` 保存 shadcn CLI 与 Registry 配置，MCP 连接由 Codex 配置管理。UI 目录不保存 API、权限和页面状态，也不另建 `components/product`。
- 用户侧页面首次加载统一使用 `src/components/ui/page-loading.tsx`：应用级状态占满视口，工作区模块在页面标题下方使用同一高度和居中位置，弹窗与侧栏使用紧凑面板高度；分页、上传、保存和删除等局部进行中状态仍留在对应操作附近。管理后台保持独立视觉边界。
- 简历、资料、模板 JSON 和插件 ZIP 等文件导入入口统一使用 `src/components/ui/file-upload.tsx`：保留各业务自己的格式、大小和提交规则，共享点击选择、拖放、焦点、禁用与响应式上传区视觉；头像和编辑器正文图片等媒体编辑操作不使用该组件。
- 普通工作区在 `WorkspaceLayout` 上显式使用 `data-ui-theme="light"`，保持既有浅色行为；入口层和管理端沿用各自主题。新增主题必须在 Token 层定义，不能在页面重复声明整套颜色。
- 前端实现优先复用 `src/components/ui/`、现有业务组件、`DESIGN.md` 和运行时 Token。视觉方向未决时才使用 `frontend-prototype` 探索原型；运行时交互或响应式行为需要观察时才使用 `frontend-browser-check`；存在已确认的 Figma、截图或原型时才使用 `frontend-visual-check` 进行视觉对照。三项能力彼此独立，不构成固定前置流程。
- 页面完成后按实际差异运行相应验证；纯 Web 改动运行 `npm run check:web`。只有本次改动需要真实运行行为或视觉依据才能确认时，才补做对应的浏览器或视觉核对；前端实现若涉及 FastAPI、数据、公共契约、权限、共享配置或部署行为，则进入 `flow-router` 确认后端范围。
- 公共欢迎页位于 `src/features/landing/`，由 `/` 与 `/home` 共同访问，登录状态不会把这两个地址重定向到工作台；未登录时顶部和页尾 CTA 通过现有 `LandingPage` 回调进入 `/login`，已登录时 CTA 进入 `/resumes`，营销组件本身不持有鉴权状态。顶部可在中文和英文间切换，选择仅保存在浏览器本地并在下次访问时恢复。欢迎页使用 `.marketing-landing` 样式边界承载深浅主题、响应式营销区块与产品模拟图。登录/注册页使用独立 `features/auth/auth.css` 保留入口构图和 Shader，表单的 TextField 与 Button 来自集中 UI；入口不再导入 `landing.css`。Local/Development 提供邮箱密码登录、注册和微信扫码切换，Production 只展示微信小程序码。
- 默认简历使用虚构示例，当前姓名为“张三”。默认中文衬线栈使用思源宋体与系统宋体回退，不包含已移除的 Google CJK serif 字体族；UI 中的霞鹜文楷由 Web Font 依赖提供，不能依赖用户系统安装。工作台页面设置的字体选择器在当前值和展开选项中只显示候选字体名称，并用对应候选字体渲染名称，不混入简历示例内容。“经典单页技术简历”使用独立主题键，在创建页、列表预览、编辑器和 PDF 中保持居中身份信息、细分隔线、高密度编号条目与非斜体右侧职位日期行。四套职能与设计模板分别使用 `administrative-sidebar-cn`、`campus-professional-cn`、`civic-service-cn` 和 `creative-orange-cn`；其深蓝双栏、蓝色折角、政务蓝页眉和橙色弧形页眉由主题样式实现，共用项目内置猫咪头像，默认虚构内容按一页 A4 的阅读密度编排。深蓝行政双栏的兴趣爱好使用带最小宽度的横向浅灰胶囊标签，预览与编辑器保持一致。
- 简历标题用字号、间距和分隔线建立层级，不自动加粗；显式 Markdown 粗体使用中等字重和略浅于正文的墨色，并在网页预览和 PDF 中保持可见。邮箱地址始终按普通正文显示，不自动生成 `mailto:` 链接，也不使用链接的蓝色或下划线；普通网址仍可作为链接保存和导出。
- 左右结构不自动加粗左侧内容。编辑器继续读取旧版 `::: left` / `::: right` 并投射为 canonical `pair` 行：把当前正文行转换为左右行时默认左右各 50%，保留整行原内容到左侧，非空行的光标进入右侧，空白行从左侧开始输入；已保存的明确比例保持原值，旧无比例 Markdown 继续按 70% 兼容读取。规范保存只写 row/cell JSON，聚焦提示和分栏拖动控件只用于编辑，不进入导出结果。
- 工作台在空白行输入 `/`，或点击正文行左侧的方框加号时打开同一命令面板；右键保持浏览器默认行为。普通段落和列表项各自生成入口，左右分栏、四列信息行和三列信息行等视觉结构行整行只生成一个入口，固定在最左侧并定位到首个可编辑段落；加号默认透明，只在对应行悬浮或按钮聚焦时显示。面板提供正文、标题、列表、左右分栏、块级图片、行内图片和行内图标，不提供上传或更换头像入口。只有简历快照中已经存在头像节点时，左键点击头像才显示蓝色圆形选中描边、右上角的 `Command/Ctrl + 滚轮` 缩放提示和右下角的“更换头像”按钮；鼠标位于头像范围内时按住修饰键滚动可在 56–220px 范围内调整尺寸，不显示通用图片拖拽缩放点，也不触发文字选区格式栏。更换头像继续通过现有简历资源上传链替换图片；没有头像节点时不提供新增入口。“左右分栏”固定在正文后的第二项，直接显示名称和“同一行左 / 右独立输入”说明，不使用额外图标。左右分栏把一个顶层普通正文行转换为默认 50% / 50% 的两个可独立编辑段落：已有文字完整保留在左侧并聚焦右侧，空白行先聚焦左侧。两栏中线保留 14px 的透明拖动命中区，静止时不显示灰色竖线；悬浮、键盘聚焦或拖动时才显示蓝色操作线，拖动时实时显示左栏百分比，松手后更新节点属性。键盘聚焦后可用方向键、Shift、Home/End 调整，双击恢复 50%。普通的左对齐、居中和右对齐按钮仍按整个段落生效，不承担拆分左右内容的职责。比例通过 `::: left <width>` 受控 Markdown 块保存，旧 `::: left` 内容按 70% 兼容读取并继续作为用户正文保存；只有模板级外壳由当前 Manifest 重建。标题、列表内部和已转换行不重复嵌套。图标命令进入二级选择器，支持学校、电话、邮箱等固定类型，在当前光标处插入图标和一个后置空格，因此也可在已有文字行头输入 `/学校` 后把图标放在原文字前。图标使用受控 Markdown 标记保存并恢复，文字版 PDF 用可辨识字符降级；块级图片仍使用独立媒体节点与对齐控制。工作台不显示底部常驻格式栏；只有选中文字时才在选区上方显示加粗、斜体、下划线、文字颜色、高亮、无序列表、增加缩进和 AI 修改八个工具，其他插入能力继续从 `/` 命令面板进入。空白行加号属于编辑装饰，不进入保存内容、分页或导出。
- 工作台不提供章节、分点或其他内容块的整体拖动排序，不渲染拖动手柄、落点占位或拖动副本，也不在分页测量中保留拖动专用分支。作者仍可使用编辑器原生选取、剪切和粘贴调整内容顺序。
- 标准模式由编辑器 DOM 测量产生 A4 分页边界，每页显示为具有完整白底边界和轻微阴影的独立纸张，页间只露出工作台背景空隙，不显示分隔线或页码。多行分点在页尾按自然文本行跨页续排，续页不重复圆点并保持文字缩进；其他普通块放不下时整体换页，无法拆分的单个超高块允许溢出。桌面工作台不再显示左侧导航栏；返回简历列表与“简历编辑”位于顶部左侧，顶部右侧按“设计、模板”和“导出 PDF、保存简历”两组展示操作。“设计”打开右侧编辑面板，面板顶部在“页面设置”和“版本记录”之间切换；小屏沿用同一入口并把文字按钮收敛为图标。页面设置按页面排列、页边距和排版纵向组织；排版分组内的字体、正文字号和正文行距按同一层级展示。上下排列、左右排列与智能一页使用同组三栏互斥的可视化选项，点击任意一项会直接切换，不需要先取消当前布局。版本记录展示正式版本保存、比较、恢复、重命名和删除。所有设置修改后立即更新，不提供“应用设置”或批量提交按钮；工作台页头不显示缩放按钮，用户通过 `Command/Ctrl + 滚轮` 调整预览缩放，比例变化时短暂显示在屏幕中央。编辑器的模板入口与 `/templates` 复用同一个大尺寸预览组件，中央完整展示当前模板，左右展示相邻模板，并支持缩放、方向键和上一个/下一个模板切换；底部操作在编辑器中为“当前模板 / 应用模板”。应用模板前先串行保存当前草稿，再调用原子切换接口；成功响应同时返回目标 `template_id`、`style` 和新锁版本，失败则保留当前编辑状态与预览弹窗。编辑器、只读预览、分享和 PDF 共同清除旧布局外壳，并按目标 `TemplateManifest` 的区域、插槽接受类型、顺序和唯一兜底区重新投射全部内容；章节进入哪个插槽以稳定章节 ID 关联的语义为准，显示标题只负责展示，不依据模板 key 或标题字符别名。目标隐藏头像时只隐藏展示，目标展示头像但用户没有头像时使用不持久化的系统默认头像。模板往返不得丢失或重复正文、图片和用户头像。切到左右排列后，预览自动缩放到工作区正好容纳两张 A4 与中间空隙，窗口变化时重新适配，切回上下排列恢复此前手动缩放；用户仍可通过 `Command/Ctrl + 滚轮` 调整当前预览缩放。切换前以视口中心记录当前页和页内垂直位置，重排后恢复到同一内容区域，并用可中断的方向性滑动、缩放和淡入淡出解释空间变化；系统要求减少动态效果时只恢复位置、不播放动画。排列选择只保存在当前浏览器，过渡和左右排列的自动适配缩放不写入简历快照或触发正文保存。左右排列使用隐藏的纵向副本持续测量分页并允许横向滚动。智能助手的悬浮入口可点击打开或收起侧栏，也可拖动到当前工作台会话内的新位置；宽屏打开智能助手时，可拖动侧栏左边缘在 320–640px 范围内调整宽度，键盘方向键、Home 和 End 提供同等操作，宽度保存在当前浏览器，可用宽度不足时自动收窄，720px 及以下使用覆盖式抽屉。宽屏打开页面设置或版本记录时仍使用固定抽屉宽度，简历画布随面板平滑收窄并向左移动。系统要求减少动态效果时取消这段布局过渡。智能一页被选中时隐藏分页空隙并保持连续单页；改选上下或左右排列会同时关闭智能一页并立即进入对应排列。
- 编辑器行首“+”工具只为原本没有定位上下文的普通段落和标题建立低优先级锚点，不覆盖模板主题自己的定位规则。依赖绝对定位的蓝色政务和橙弧创意页眉继续把姓名、联系方式和头像放在页首，行首工具不能把它们推回正文流。
- 工作台顶部的导出操作只提供“导出 PDF”，与“保存简历”并列，不使用下拉菜单，也不提供 Word 或图片版 PDF。点击后先完成现有串行保存，再以最新 `lock_version` 请求 `/api/resumes/:id/pdf`；保存失败、版本过期或渲染失败都不触发文件下载。页面最终只读预览和 PDF CLI 都调用 `renderResumePrintDocument`，并共同消费 `styles.css`、`app.css` 中的正文与主题规则；打印专用 CSS 只负责纸张、分页和全出血边界，不复制模板排版。标题、段落、标记、链接、列表、左右栏、行内/块图片与头像都从同一 `ResumeDocument/ResumePresentation` 快照生成；编辑器工具、选区、浮动菜单和行加号不进入打印 DOM。固定模式按 A4 分页；智能一页保持 210mm 宽、最低一张 A4，并按内容高度增长。浏览器不调用 `window.print()` 或维护第二套 React-PDF 节点树。
- 页面设置中的字号、行距和页边距使用带当前值的步进按钮即时调整。编辑器聚焦时不显示包围整张 A4 的浏览器默认外框，但保留光标、选区和当前行左右对齐提示。
- 登录、简历主页和编辑器使用可恢复 URL：`/login`、`/resumes`、`/resumes/:resumeId/edit`；刷新、收藏及浏览器前进后退保持当前简历定位。
- “智能一页”在工作台保留可操作入口和选中状态；PDF 导出保持当前排版密度和 A4 宽度，把原本的多页高度合成一张连续长页面，不裁切内容。
- 工作台支持 `Command/Ctrl + 滚轮` 缩放纸张预览；普通滚轮只滚动，预览缩放不改变 PDF 的实际页面尺寸。
- 管理端以黑白中性设计为基线，使用按下反馈、可中断的弹簧动效和半透明材质，并为减少动态效果、减少透明度和键盘焦点提供降级。登录页保持内部工具气质，不使用巨型营销口号或宣传式数据堆叠。

## 本地资源预览

Vite 插件在 `/__local_asset__` 提供开发期本地图片读取，只允许工作区和用户 `Documents` 目录内的文件。它不是生产 API，不应扩大允许目录或用于暴露任意本地路径。

## 当前测试边界

- 单元和组件测试使用 Vitest、React Testing Library 与 jsdom；配置入口为 `apps/web/vitest.config.ts`，公共初始化在 `src/test/setup.ts`。
- 测试文件与被测源码相邻，命名为 `*.test.ts` 或 `*.test.tsx`，优先验证可见行为和公开接口。
- 前端测试不得访问真实后端、数据库或对象存储，跨模块依赖在 API Client 边界使用受控 Mock。
- 岗位库页面测试覆盖无状态列表搜索、求职进程入口、直接永久删除确认、重复来源更新和编辑来源只读契约。
- 管理端组件测试在 API Client 边界使用 Mock，覆盖多能力绑定、候选管理与真实日志渲染、错误与空状态、密钥更新语义、测试后启用、筛选和游标交互。
- 当前没有自动化 E2E；涉及 Web、FastAPI、MySQL 和 MinIO 的完整浏览器流程仍需人工验证。

## 组件与 Pattern 核对

共享组件和布局 Pattern 以真实消费页面作为可视依据。新增或调整组件时优先在实际业务路由观察它；只有本次改动涉及运行时交互或响应式行为时才使用浏览器检查，存在已确认的 Figma、截图或原型时才做视觉对照。普通逻辑和局部修改不补做这些步骤，不额外维护组件目录或截图回归基线。组件暂无稳定业务消费者时保留在组件目录中，待首次真实页面使用时再核对。
# 插件安装与发布入口

岗位库页头提供“安装岗位采集插件”入口。`PluginInstallDialog.tsx` 只向普通用户展示开发者模式安装、使用、手工更新说明和统一下载按钮，不展示版本、Manifest、发布时间、大小或 SHA-256；只有后端返回可用版本时才渲染同源下载入口，未发布、下架或存储故障时不猜测地址。

管理台 `/admin/plugins` 由 `PluginReleasePanel.tsx` 承担，并按无插件、已上架、已下架三态显示卡片。无插件时只显示“上传插件”；已上架时显示“更新插件 / 下架插件 / 删除插件”；已下架时显示“更新插件 / 重新上架 / 删除插件”。管理员选择单个 ZIP 后，客户端先检查扩展名与 20 MiB 上限，二次确认后以 multipart 上传；后端继续校验 ZIP 安全结构、Manifest V3 和三段数字版本，但不检查安装说明、站点权限、IP 或端口。校验失败的文件可显式清除并重选。更新成功后后端自动删除旧版本 ZIP；下架保留当前 ZIP，重新上架无需上传；永久删除经二次确认后物理删除 ZIP 和发布指针。面板不编译源码，也不提供历史版本或回滚。
