# Web 模块

Featured 系列在 `api/featuredThemes.ts` 注册十一套参考版式，其中卡片虚线使用全宽虚线章节，卡片分栏使用左侧章节索引与右侧履历正文，经典商务使用浅蓝居中肖像页眉，活力使用暖橙卡片与右侧能力栏；共享 `app.css` 负责可编辑与打印布局，双栏在 PDF CLI 中保留纸面内边距并取消旧的整页列最小高度，避免空白续页。来源与重复项对应关系见[模板来源](resume-template-sources.md)。

## 功能与架构导航

本页维护 Web 运行入口、路由、共享 UI、视觉交互和前端测试边界。跨端业务规则分别见[账号](../features/identity-account.md)、[简历工作台](../features/resume-workbench.md)、[求职中心](../features/career-center.md)、[AI 助手](../features/ai-assistant.md)和[资料集](../features/datasets.md)；系统日志与插件制品属于独立[可观测性](observability.md)和[插件制品](plugin-delivery.md)架构。

## 职责与入口

- `apps/web/src/main.tsx`：React 启动入口。
- `apps/web/src/App.tsx`：页面状态与主要功能组合。
- `apps/web/src/features/`：鉴权、首页、编辑器、预览、求职、资料库和管理端功能。
- `apps/web/src/v3/`：V3 共享侧栏、图标、控件、插图与样式；正文沿用思源黑体，标题使用本地 Noto Serif SC，数字使用 Inter。
- `apps/web/src/store/resumeStore.ts`：简历编辑状态。
- `apps/web/src/api/client.ts`：鉴权、模板、简历与异步导入、智能助手 SSE、JD、资源、日志上报和管理员查询 API 客户端。
- `apps/web/src/components/ui/feedback-notice.tsx`：全局操作反馈入口；浮层模式通过 Portal 挂载到页面根层，固定在视口上方居中，并统一在 3 秒后通知业务清理状态。
- `apps/web/src/api/resumeContract.ts`：语义简历 TypeScript 契约，以及领域 JSON、Markdown 和现有 Tiptap 编辑器之间的过渡适配。
- `apps/web/vite.config.mjs`：开发服务器、FastAPI 代理和本地图片预览插件。

生产构建按页面路由拆分 React 功能包，并把 React、React DOM 与 Zustand 放入稳定的 `vendor-react` 缓存分包；公共 HTML 不依赖 Google Fonts 等境外样式服务，入口只加载应用壳、稳定运行时和当前页面所需代码。Vite 的 `VITE_ASSET_BASE_URL` 为空时继续生成同源 `/assets/*`，只接受不带凭据、查询和片段的 HTTPS 绝对地址；Production 镜像由发布脚本把 `.env.production` 中的 `WEB_ASSET_OSS_URL=https://qingluo-public.oss-cn-shanghai.aliyuncs.com/LinkResume/` 显式传入，因此生产 HTML、动态 import、CSS 和字体直接引用 OSS 的 `LinkResume/assets/` 前缀，不依赖 CDN、自定义静态域名或证书，页面路由与 `/api/*` 仍保持 `linkresume.cn` 同源。发布脚本还会从最终 Web 镜像提取 `favicon.png`，上传到 OSS 的 `LinkResume/favicon.png`，并在数据库迁移与应用切换前通过 HTTPS 验证其返回 2xx 与 `image/png`，避免入口 HTML 引用的 favicon 因未随静态资源发布而缺失。用户通过鉴权后，浏览器在空闲阶段预加载 `/templates` 与 `/datasets` 页面包，导航鼠标移入或键盘聚焦仍会即时预加载目标模块，触摸点击则复用已经完成的空闲预热。V3 产品正文、输入、按钮与导航沿用思源黑体可变字体，页面标题使用 Noto Serif SC 600，数值使用 Inter；新增两项 @fontsource 依赖用于还原设计字体并随构建本地分发，避免依赖外部字体服务。独立 AI 助手和简历编辑器侧栏的消息正文也复用同一字体栈，以保持紧凑的对话排版。简历画布仍以用户选择的版式字体为准。简历可选字体随应用发布，来自固定版本的本地字体文件；霞鹜文楷在编辑器、分享页与 PDF 导出均使用 Medium 字重，思源宋体和 Noto Sans SC 均使用 Regular 字重，思源黑体在浏览器与 PDF 中均使用同一可变字体；PDF CLI 复用同一批字体文件，并等待 `document.fonts.ready` 后才测量分页。

搜索引擎只收录生产主域名 `https://linkresume.cn/` 的公共落地页，兼容入口 `/home` 使用同一个 canonical。`index.html` 提供标题、简介、Open Graph、Twitter Card 和 `Organization`/`WebSite` JSON-LD，组织 Logo 复用公开的 256×256 `favicon.png`；根目录 `robots.txt` 声明 `sitemap.xml`，站点地图只列 canonical 首页。React 路由切换会同步页面标题和 robots meta，FastAPI 的 SPA 静态回退还会为除 `/`、`/home` 和 `/index.html` 外的 HTML 深链返回 `X-Robots-Tag: noindex, nofollow, noarchive`。因此登录、管理、用户工作区、未知地址和带 token 的简历分享页都不会作为公开搜索结果入口；`/api/` 另由 `robots.txt` 禁止抓取。

## API 调用

API 客户端只发送相对 `/api/...` 请求并携带 cookie，不在业务组件中写死后端主机。每次请求附加 `X-Request-ID`，错误对象保留服务端回传的追踪值；API 5xx 会异步上报稳定错误码和追踪值，不发送原响应 body。开发期全部 `/api` 请求由 Vite 代理到 FastAPI，见 [架构文档](architecture.md#本地请求路径)。模拟面试语音通道 `/api/mock-interviews/{id}/speech` 在 Vite 中单独启用 WebSocket 代理并保留浏览器的 `Host`，使后端的 `Origin` 同源校验成立；代理读写等待上限为 600 秒。短 access 过期后，受保护请求会复用单个 `/api/auth/refresh` 请求轮换双 Cookie，并重试一次原请求；应用启动时 `/api/auth/me` 返回空用户也会先尝试 refresh，再判定为访客。

React 根入口用 Error Boundary 和 `error` / `unhandledrejection` 监听器捕获登录态页面的未处理异常，通过 FastAPI 受保护入口进入统一日志链路；上报失败被吞掉，不能形成递归上报或替代原始页面错误。上报内容限制为错误类型、消息、栈和可选 request ID，不发送 Store、表单、简历正文或浏览器 Cookie。

普通登录页 `/login` 先读取 `/api/auth/capabilities`。Local/Development 根据路由模式展示邮箱密码登录或注册表单，两者可以互相切换，也可以切换到 `WechatQrLogin`；Production 对登录与注册链接都不渲染邮箱密码表单，直接请求二维码并每 2 秒轮询 scene。`success` 时后端设置双 Cookie 并进入工作区，`cancelled/expired` 或生成失败时停止轮询并提供刷新。Landing 的“登录”进入登录模式，“开始使用”进入注册模式。个人资料页展示改密与微信绑定的“需后端”本地模拟交互，不发送真实账号变更；管理员密码表单仍只保留在 `/admin/login`。

新增或迁移接口时同时检查：

1. `src/api/client.ts` 的路径和响应类型；
2. `vite.config.mjs` 的路由归属和目标；
3. FastAPI 的真实路由；
4. [HTTP 契约](../api/http-contracts.md)。

简历 API 已统一使用 `snake_case`、唯一 `ResumeDocument data` 和 `ResumePresentation style`，运行期不再保留版本联合类型。`data.semantic_sections` 保存显示标题、稳定语义和真实内容引用，`style.manifest` 保存受控区域、插槽、兜底区和头像策略。编辑器以 Tiptap JSON 作为已编辑正文的唯一持久化真值，保存时先移除模板列和系统头像，再按二级标题及其 `blk_*` 锚点拆成独立 `custom_sections`；具有业务语义的节点、marks、对齐、信息行和图片属性原样进入 `{format: "tiptap-json"}`，不经过 Markdown 降级。持久化边界会移除受支持 Tiptap 版本产生的已知无语义默认属性，当前包括 `orderedList.attrs.type: null`；前端保存转换和后端 `RichText` 校验都会执行同一规范化，滚动发布期间的旧前端请求也不会因此失败，非空或未知属性仍由后端严格拒绝。历史 Markdown 和导入 typed sections 继续可读，并在首次正文保存时转成同一规范结构，不再额外保存整篇 `custom_section_editor` 副本。标题重命名只更新 `display_title`，语义类型继续由稳定章节 ID 关联；新增章节获得新 ID 并进入待分类链路。

简历主页卡片使用后端摘要中的真实 `data/style` 只读预览；编辑工作台只在内存中把规范编辑树投射到当前 `TemplateDefinition`，模板切换先反投影回全局语义顺序，再生成目标区域、插槽、双栏和头像，空插槽提示不写入正文。反投影会按模板 LayoutPlan 的全局规范顺序合并 columns 区域，避免把教育等侧栏章节追加到末尾。预览纸张、分享页和 PDF 对规范 Tiptap 内容直接使用同一棵投影树和只读渲染器；只有历史 Markdown 走兼容渲染。公开分享页只保留服务端“下载 PDF”按钮，不再调用 `window.print()`，因此下载文件不包含分享页品牌头部和操作区。历史 typed 联系信息在适配时合并为同一个 Markdown 段落，电话、邮箱、地址与个人网站保持一行，网站继续使用受控 HTTP 链接；历史 Markdown 列表只清理行首重复的无序标记及空白实体，保留负数、年份范围、有序列表起始值和嵌套层级。canonical 正文的 `row` 是模板无关的章节内结构：`pair` 固定两格并保留比例，`meta` 四格、`trio` 三格，`equal` 三或四格等分且不携带宽度；旧 `::: left/right` 与 `:::: meta/trio` 只在 cutover/兼容输入中解析，规范正文和新保存不包含原始标签，模板级 `sidebar/main` 不作为用户正文跨模板继承。`TemplateDefinition.avatar` 决定头像是否显示、尺寸和 region；用户头像始终保留在 identity，系统猫咪 fallback 只存在于工作台、预览和 PDF 的投影，不写回正文，隐藏模板也不删除用户头像。切换请求把当前标题、规范内容、目标模板和锁版本一次提交，避免预保存与切换之间出现并发半状态。白名单内图标在 canonical 中保存为 `InlineIcon` 或章节 `title_icon`，投影到 Tiptap 时恢复成真正的 `inlineIcon` 节点；`:icon[Name]:` 只在 Markdown/Agent 兼容边界出现，未知标记仍按普通文本显示。历史结构无效时显示“预览不可用”，不阻断列表。正式简历卡片可打开、重命名、分享或删除；重命名只更新列表识别用的标题，不会写入简历正文。主页只展示简历和导入任务；工作区导航中的“简历模板”进入独立 `/templates`，读取当前启用模板并提供只读预览；用户从模板卡片点击“创建简历”后在弹窗内填写名称，确认后直接创建并进入编辑器，不再经过 `/resumes/new`。旧的 `/resumes?view=templates` 仍按普通简历列表处理。独立 `/resumes/new` 仍承载从简历主页进入的创建与导入流程：创建模式要求选择启用模板并输入名称，导入模式要求选择 Markdown、DOCX 或 PDF 文件并使用生产保留的 `classic-technical-cn` 默认版式；如果该模板不可用则回退到第一套非 `blank-cn` 的启用模板。`blank-cn` 已退出可选产品目录；数据库只会在仍有历史引用时保留 `is_active=0` 的身份 tombstone，Web 模板列表、新建、导入回退和切换均不会把它作为可选项。注册成功后只进入空主页，不自动创建第一份简历。

模板的 `accent_color` 通过同一个 `--preview-accent` 呈现变量进入编辑工作台、只读预览、公开分享和 PDF 文档；经典技术模板的标题、章节标题、链接和分隔线因此在四个消费面保持一致，不再由各页面各自使用固定颜色。

主页的“导入简历”在当前列表上打开短流程弹窗，不跳转到新建页。弹窗只选择 Markdown、DOCX 或 PDF 并确认简历名称，不展示模板选项；前端内部使用生产保留的经典单页技术版式，并把确认后的名称与原扩展名组合成 multipart 文件名，后端继续按上传文件名生成正式简历标题。每次提交生成新的 UUID `Idempotency-Key`，access 刷新重放保持同一个 Key。受理成功后弹窗关闭，主页显示上传中、解析中和失败导入任务。只有上传成功且仍在解析的任务会挂载独立轮询器，每个任务每秒调用一次单任务状态接口；慢请求不会重叠，多个文件分别轮询，任务进入成功或失败终态后对应轮询器卸载。成功终态会一次性刷新 overview 以展示正式简历，失败任务可删除。前端不持有 MinIO、LinkParse 或结构化模型凭据。

资料库 `/datasets` 在工作台页头复用 `ExpandableSearch`，下方使用单一正式列表展示资料名称、上传时间、大小和解析状态，不按源文件格式分类，也不显示扩展名、格式标签或行首图标。上传 Hook、文件选择器与冲突处理弹窗只在用户打开上传入口或拖入文件后加载；页面级重试身份缓存跨弹窗挂载保留，确保网络结果不明确时继续复用原幂等键。上传弹窗只保存尚未受理的本地文件、上传进度和可重试失败；每个本地文件创建一个 UUID 幂等键，明确开始新尝试时才换键。后端返回受理成功后弹窗立即移除该项并将记录写入正式列表，列表把 `queued/processing/succeeded/failed` 映射为“等待解析、正在解析、解析完成、解析失败”并轮询活动任务。单批文件数、单文件大小和并发上限读取后端 `limits`，不在前端形成第二套固定契约。解析成功资料点击整行后按需加载阅读弹窗和 Markdown 渲染模块，再按资料 ID 请求 `/api/datasets/:id/content`；卡片缩略图也只在取得本地或近视口正文后加载 Markdown 渲染。原始 HTML 不执行，图片只显示文字占位，不由浏览器加载转换内容中的外部资源。带 `mermaid` 标识的代码块在内容挂载后按需加载 Mermaid 并以严格安全配置渲染，单图失败时保留转义后的源码，不影响其余正文和图表。行尾菜单提供重命名和永久删除，解析失败资料还可复用源对象重新排队；页头批量操作模式支持选择当前筛选结果，并在二次确认后逐条调用既有删除接口，部分失败时仅移除成功项并保留失败资料。写操作成功后就地同步列表，失败时显示稳定错误反馈。

编辑器的右侧工具轨切换大纲、模板、排版和简历检查，不提供已退休的历史版本操作。自动保存串行执行，并在每次成功后接续服务端 `lock_version`；顶部标题、正文和页面样式共用保存链路。图片仍使用当前简历的私有资源接口，`smart_one_page` 保存在当前快照。

工作台使用简历画布右下角的白底蓝色星芒胶囊入口打开独立右侧抽屉，页头不重复放置助手按钮；入口与抽屉共用同一 AI 标识，并在抽屉打开后保留收起状态，移动端沿用工作台侧栏的覆盖布局。编辑器为每个文本块维护不可见且随 Markdown 持久化的稳定块 ID；选中文字后在选区最后一个字的右下角显示精简格式浮层，浮层跟随简历画布缩放并在滚动、窗口尺寸或缩放变化后重新定位。AI 修改从助手入口操作，把块 ID、范围、所选正文和 SHA-256 作为可移除上下文带入助手侧栏，不把正文拼接进用户消息。带选区发送前先保存当前草稿，确保 FastAPI 能在同一版本解析 locator；保存失败不发起 Agent Run。`AgentPanel` 使用带副标题的简洁页头、浅蓝对话气泡、带图标的快捷操作和内嵌圆形发送按钮，自带新建对话与关闭操作；它通过 POST SSE 展示定位、读取、资料召回、诊断和提案工具状态，并提供重新生成。关闭或停止时取消当前请求，正常 EOF 前未收到完成、失败或取消终态会显示连接中断，而不把半条响应当作成功。范围化提案卡优先按 operation 展示 before/after 和修改依据，旧快照提案继续按发生变化的简历区域展示；用户确认前仍会再次保存当前草稿。保存失败、目标失效、提案冲突或 Agent 不可用都保留现有编辑内容。确认成功后重新读取当前简历。浏览器只持有用户 Cookie，不读取 Pi 服务地址、服务 token 或模型 API Key。

共享侧栏通过首页和最近对话进入 `/assistant` 或 `/assistant/:sessionId`。首页、会话、右侧多标签预览、截图和本地生成文档交互见 [AI 求职助手](../features/ai-assistant.md)。模型选择、上下文归属、SSE、后台运行恢复和提案确认继续使用原有契约；本地模拟产物不进入服务端消息或资料库持久化。

工作区使用 `V3Shell` 左侧导航：首页、我的简历、简历模板、岗位看板、面试日程和资料库，底部为设置与账号。简历、进行中的求职记录等数量读取真实接口；无 API 的示例指标使用“需后端”标记。主要路由分别为 `/assistant`、`/resumes`、`/templates`、`/career/applications`、`/career/schedule`、`/datasets`、`/account`。旧链接继续由 `routing.ts` 兼容，登录回跳允许站内分享地址。

岗位看板保留视图、排序、分类和列显隐能力；页面设置不改写业务数据。岗位、进程、阶段、排期与复盘的呈现和模拟边界见 [求职中心](../features/career-center.md)。

求职记录页直接承载智能文字、图片、手工填写、来源重复解决和采集插件入口，不再维护独立岗位列表页，也不恢复 `0034` 已移除的 JD 归档语义。岗位表单可填写并编辑公司 Logo HTTPS URL；阶段看板按左侧 32×32 Logo、右侧公司与岗位文字展示求职快照，加载失败时回退公司首字。列表和阶段看板以求职进程为主对象，点击记录进入进程详情，再从其中打开原 JD 详情页查看或就地编辑完整岗位。浏览器采集插件仍是独立的 `apps/extension` 应用，通过相同 Cookie 会话调用后端导入接口。

求职进程、排期和复盘均读取 FastAPI 的真实求职进程与面试接口。岗位 JD 创建或导入成功时，后端同时创建或复用一条未结束求职进程，前端直接进入该待投递记录；路由切换到新求职进程后，在该 ID 对应的数据请求完成前保持统一加载态，只有成功响应确认列表中不存在该记录时才显示不可访问空态。看板和列表覆盖待投递、筛选中、测评、笔试、AI 面试、用户自定义普通面试、Offer 和已终止。待投递记录可以直接追加任一业务阶段，这次操作隐式完成投递，不再经过独立“标记已投递”或“等待后续通知”状态；投递时间允许补填，未填写时由后端使用本次操作时间。简历可以不选；前端只有在用户选择简历时才提交 `resume_id`，由服务端校验归属并绑定该简历最新正式版本，旧的 `resume_version_id` 请求仍兼容，两个字段不能同时提交。每次流转追加阶段历史，普通面试的展示名称由用户填写、轮次选填；“添加下一阶段”通过一条可直接切换的阶段轨道展示测评、笔试、AI 面试、普通面试和 Offer 的差异化表单，不再使用阶段分类下拉或独立排期勾选。测评要求开始时间和完成期限，其他可排期阶段在时间未知时允许先保存阶段再补充日程，筛选和 Offer 不创建排期。排期页的快速入口只接受已有待投递或已完成当前阶段的求职进程，不负责创建岗位或求职进程；具体候选条件见[求职中心业务规则](../features/career-center.md)。排期使用 `src/components/reui/event-calendar/` 中的受控事件日历统一承载周、月视图，并按公司共享七色标记；空白位置单击不执行操作，双击才按最近 15 分钟刻度打开新建流程，按住拖动仍可选择时间范围。周视图只绘制整点横线，移动和缩放均按 15 分钟吸附，上、下缩放手柄分别只修改对应端点。相互包含的事项缩进嵌套，交叉重叠事项等宽分栏。记录复盘按单场面试展示题目、总结和素材，并通过接口持久化完成、取消、调色、复盘与上传结果。

管理端入口为 `/admin`，由 `features/admin/AdminApp.tsx` 承担左侧分组导航与页面切换，各页面拆在 `OverviewPage`、`UsersPage`、`TemplatesPage`、`PluginReleasePanel`、`AnnouncementsPage`、`LlmPages`（接入连接、模型与线路、使用情况）、`CapabilitiesPage`（能力配置）和 `SecurityPages`（Agent 日志、Agent 排障、系统日志、LLM 调用、业务审计）中；共享的表格、指标条、弹窗、抽屉和骨架占位位于 `kit.tsx`，图表位于 `charts.tsx`，样式位于 `console.css`，视觉依据是 Figma 管理端 V4 页面（单栏、无卡片边框、lucide 图标）。页面路径为 `/admin`、`/admin/users`、`/admin/templates`、`/admin/plugins`、`/admin/announcements`、`/admin/llm/{connections,models,capabilities,usage}`、`/admin/agent`、`/admin/agent-operations`、`/admin/logs/{system,llm,audit}`；旧的 `/admin/logs` 进入 LLM 调用，其他未知的 `/admin/llm/*` 与 `/admin/logs/*` 分别进入模型与线路和系统日志。

查看详情、分类、筛选、新建和编辑都在当前页面打开弹窗或抽屉，不跳转新页面；抽屉是距视口 24px 的浮层卡片，弹窗和抽屉都有进入与退出动画，内部的取消、关闭按钮走同一退出路径，动画结束后才卸载。切换页面时内容按侧栏方向滑入（跨分组上下、同组子页左右），各区块依次淡入；侧栏共用一块随选中项滑动的高亮，子导航展开与收起带高度过渡，顶部搜索框（⌘K 聚焦）可按名称直达页面。页面内切换标签、分段筛选、搜索或翻页时，分段控件的滑块与标签下划线滑动到新选项，旧列表在加载期间变淡，新一组行或卡片依次上浮进入；同一组数据的原地修改（启停、重命名）不重放动画。系统要求减少动态效果时这些动画全部跳过。管理端只有浅色外观：`console.css` 在管理端外壳和弹层内把共享 UI Token 固定为浅色值，避免系统深色模式下模板缩略图等共享组件露出深色底色。各页单栏排布：指标是带淡色图标块的一行数字、列之间用细竖线分隔；列表是细分隔线的平铺行（公告、业务审计、今日关注用带图标的信息流，接入连接用逐行的连接架）；构成类数据用圆环图加带数值的图例（用户账号构成、Agent 结果构成、系统日志级别构成、使用情况的调用与费用占比），趋势类数据用细柱图。使用情况的两张圆环按调用量最多的前五个分组分配固定颜色，两图同一分组同色，其余合并为“其他”；分类色板经过色觉校验，橙、金两色对白底对比度偏低，因此圆环总是配带数值的图例。用户、模板、公告、Agent 日志与排障、系统日志、LLM 调用和业务审计的主列表放在 `kit.tsx` 的 `ListPanel` 中：列表在板块内部滚动，筛选栏和翻页或“加载更多”固定在板块上下，表头吸顶，板块填满内容卡剩余高度；上方内容过高时板块保持最小高度、改由整页滚动，900px 以下的窄屏统一回到整页滚动。模板卡片拖动排序在板块滚动时会补偿滚动位移。首次加载时每个页面按最终布局显示骨架占位，数据返回后原位替换，不使用整页转圈；接口失败时显示带错误码的重试状态，而不是空列表。

简历模板以卡片网格展示，按展示顺序排列，卡片可直接拖动或用排序手柄加方向键调整顺序：拖动时目标位置显示虚线占位，其余卡片平滑让位（落点按拖动开始时记录的卡片位置计算，避免重排导致落点抖动），松手后一次提交全部模板 ID；有筛选或搜索时不能拖动，避免只对部分模板排序。服务端返回列表已过期时恢复原顺序并重新加载。点击卡片打开模板详情弹窗，左侧大图预览可缩放，右侧可启停、选择风格与适用场景（选择后立即保存）并逐套切换上一个、下一个；页头可导出分类 JSON。导入模板使用弹窗内的严格 JSON 上传，导入后默认停用，不提供覆盖或删除。

模型管理按接入连接、逻辑模型与线路、能力配置三层维护。模型与线路页左侧按模型厂商（`developerName`）分组折叠：已知厂商标识映射成统一名称与标志（如 `qwen`、`alibaba` 归为同一组），按模型数排序，厂商为空的模型归入末尾“未标注厂商”组；厂商、接入商与模型的彩色标志来自固定版本的 `@lobehub/icons-static-svg`（MIT），映射在 `features/admin/brandIcons.ts`：模型先按名称识别模型家族（Qwen、Gemini、GPT 等），识别不到再用厂商标志，都没有时退回首字母；每组默认只列前几个，可展开全部，搜索时跨组展开命中项，右侧显示所选模型的线路、单价和使用场景。连接只能在六个固定接入商中选择，AIHubMix 可选默认或备用地址，阿里云百炼选择地域并在需要时填写 Workspace；Key 只写，更换 Key 或地址后关联绑定需要重新探测。线路创建后调用目标、模型和连接不可修改，只能调整标识类型、单价与启停；单价输入和输出需同时填写。能力配置左侧列出使用场景及其当前默认模型或缺失原因，右侧和后端解析规则一致地按模型分组展示：场景依优先级取第一个可用模型为默认，失败只在该模型自己的线路间切换，不换模型。每个模型一段，标题行只保留顺序、名称和用户可选开关，“添加线路”“移出场景”收进“⋯”菜单；其下的浅底面板列出主线路与备用线路，每行两行文字（连接名，下方是调用目标、单价、协议和探测时间），右侧只放状态、探测、启停和“⋯”；拖动模型或线路（也可用排序手柄加方向键）调整顺序，拖动效果与模板卡片一致：目标位置显示同尺寸虚线占位，其余模型或线路平滑让位，线路只能在所属模型内移动，松手后才写入。调整后，前端把优先级重排为 10、20、30…，并先把要移动的行挪到所有现有值之上再落到目标值，避免触发同一场景内优先级唯一约束，中途失败会重新加载显示实际顺序。“添加模型”可搜索已有模型并勾选它尚未加入的线路，也可新建模型和第一条线路；新加入的绑定排在末尾、默认停用，探测通过且启用才生效。用户对话页签在模型卡片上直接切换“用户可选”，隐藏的模型不会被选为默认。连接、模型和线路的删除都经过二次确认，被引用时展示后端返回的原因，建议改为停用。

系统日志和业务审计只通过 FastAPI 查询 Loki，不直连也不轮询：页面展示最近 24 小时汇总、7 天错误与警告热力图（仅系统日志）、级别或结果快速筛选、抽屉内的高级筛选和游标分页，行点击后在弹窗中查看完整字段与异常堆栈；部分脏行会给出提示。LLM 调用读取 MySQL 中的真实记录，支持场景、状态、错误码和时间范围筛选并逐页加载。后端保留既有 `resume.pdf_export` 客户端审计契约以兼容已有调用方；当前工作台的文字版 PDF 下载链不调用该接口。

## 视觉与交互基线

- 公共动效由 `src/components/ui/motion.tsx` 与 `motion.css` 管理，复用运行时的 100/180/260ms Token。工作区切换模块时保留当前内容直到目标模块就绪，白色外壳保持不透明；首页助手与普通工作区页面共用外层加载边界，首次打开首页模块不会卸载当前侧栏并露出整页加载图，直接打开这些路由时加载占位也保留工作区外壳。页面只轻微淡入一次，数据返回不重新播放。页内视图在原有 DOM 上切换，不重建表单或重置滚动；V3 与 Radix 弹窗、菜单、日期浮层提供进入和退出，预览抽屉从右侧进入，分段按钮平移选中背景。条件浮层使用 `MotionPresence` 保留退出画面，关闭立即移出可访问和交互范围，快速重新打开使用新的表单实例，退出清理有定时兜底。系统减少动态效果时，页面直接切换，浮层仅保留不超过 100ms 的淡入淡出。
- 登录后功能区的视觉语言与机器可读 Token 见根目录 [`DESIGN.md`](../../DESIGN.md)。`src/design-system/tokens.css` 是浏览器运行实现，`tailwind.config.cjs` 提供语义 utility 映射，`src/design-system/utilities.css` 是 Tailwind utilities 的全局入口；保持 `preflight: false`。
- shadcn primitive 与 LinkResume 通用组合组件只放在 `src/components/ui/`，页面统一从 `@/components/ui` 导入；`components.json` 保存 shadcn CLI 与 Registry 配置，MCP 连接由 Codex 配置管理。UI 目录不保存 API、权限和页面状态，也不另建 `components/product`。
- 用户侧页面首次加载使用 `src/components/ui/page-loading.tsx` 或页面已有骨架：应用级状态占满视口，工作区模块在页面标题下方使用居中占位，弹窗与侧栏使用紧凑面板高度。公共加载图及简历、资料库、求职中心的加载占位在挂载 180ms 后才开始显示，快速请求不闪现加载图；数据就绪立即展示，没有强制最短停留。分页、上传、保存和删除等局部进行中状态仍留在对应操作附近。管理后台保持独立视觉边界。
- 简历、资料、模板 JSON 和插件 ZIP 等文件导入入口统一使用 `src/components/ui/file-upload.tsx`：保留各业务自己的格式、大小和提交规则，共享点击选择、拖放、焦点、禁用与响应式上传区视觉；头像和编辑器正文图片等媒体编辑操作不使用该组件。
- 普通工作区在 `WorkspaceLayout` 上显式使用 `data-ui-theme="light"`，保持既有浅色行为；入口层和管理端沿用各自主题。新增主题必须在 Token 层定义，不能在页面重复声明整套颜色。
- 前端实现优先复用 `src/components/ui/`、现有业务组件、`DESIGN.md` 和运行时 Token。视觉方向未决时才使用 `frontend-prototype` 探索原型；运行时交互或响应式行为需要观察时才使用 `frontend-browser-check`；存在已确认的 Figma、截图或原型时才使用 `frontend-visual-check` 进行视觉对照。三项能力彼此独立，不构成固定前置流程。
- 页面完成后按实际差异运行相应验证；纯 Web 改动运行 `npm run check:web`。只有本次改动需要真实运行行为或视觉依据才能确认时，才补做对应的浏览器或视觉核对；前端实现若涉及 FastAPI、数据、公共契约、权限、共享配置或部署行为，则进入 `flow-router` 确认后端范围。
- 公共欢迎页位于 `src/features/landing/`，未登录时由 `/` 与 `/home` 共同访问；已登录访问 `/` 会以替换历史的方式进入 `/resumes`，`/home` 则始终展示落地页，作为登录用户回到欢迎页的固定入口；未登录时顶部和页尾 CTA 通过现有 `LandingPage` 回调进入 `/login`，已登录时 CTA 进入 `/resumes`，营销组件本身不持有鉴权状态。顶部可在中文和英文间切换，选择仅保存在浏览器本地并在下次访问时恢复。欢迎页使用 `.marketing-landing` 样式边界承载深浅主题、响应式营销区块与产品模拟图。登录/注册页使用独立 `features/auth/auth.css` 呈现双栏品牌区与表单，表单的 TextField 与 Button 来自集中 UI；入口不再导入 `landing.css`。Local/Development 提供邮箱密码登录、注册和微信扫码切换，Production 只展示微信小程序码。

Studio 批次的六套 `studio-*` 主题由 `api/studioThemes.ts` 注册，共用既有 canonical 区域与头像策略，样式仍由 `app.css` 同时服务编辑器、预览和打印。模块履历卡、能力卡片侧栏采用右侧资料栏；双色分区采用左侧身份区；肖像创意专栏将头像放入 sidebar、姓名放入 main；分层胶囊章节使用单栏；节点时间轴使用左侧能力栏和右侧经历节点。它们不依赖上游图片或样式文件，也不改变正文持久化结构。

## 本地资源预览

Vite 插件在 `/__local_asset__` 提供开发期本地图片读取，只允许工作区和用户 `Documents` 目录内的文件。它不是生产 API，不应扩大允许目录或用于暴露任意本地路径。开发服务器 Host 额外只允许 `.trycloudflare.com` 后缀，供临时预览隧道使用；该配置不放宽本地资源读取范围。

## 当前测试边界

- 单元和组件测试使用 Vitest、React Testing Library 与 jsdom；配置入口为 `apps/web/vitest.config.ts`，公共初始化在 `src/test/setup.ts`。
- 测试文件与被测源码相邻，命名为 `*.test.ts` 或 `*.test.tsx`，优先验证可见行为和公开接口。
- 前端测试不得访问真实后端、数据库或对象存储，跨模块依赖在 API Client 边界使用受控 Mock。

## 组件与 Pattern 核对

共享组件和布局 Pattern 以真实消费页面作为可视依据。新增或调整组件时优先在实际业务路由观察它；只有本次改动涉及运行时交互或响应式行为时才使用浏览器检查，存在已确认的 Figma、截图或原型时才做视觉对照。普通逻辑和局部修改不补做这些步骤，不额外维护组件目录或截图回归基线。组件暂无稳定业务消费者时保留在组件目录中，待首次真实页面使用时再核对。
# 插件安装与发布入口

岗位库页头提供“安装岗位采集插件”入口。`PluginInstallDialog.tsx` 只向普通用户展示开发者模式安装、使用、手工更新说明和统一下载按钮，不展示版本、Manifest、发布时间、大小或 SHA-256；只有后端返回可用版本时才渲染同源下载入口，未发布、下架或存储故障时不猜测地址。

管理台 `/admin/plugins` 由 `PluginReleasePanel.tsx` 承担，并按无插件、已上架、已下架三态显示当前发布，下方展示最近 30 天插件岗位导入趋势。无插件时只显示“上传插件”；已上架时显示“更新插件 / 下架插件 / 删除插件”；已下架时显示“更新插件 / 重新上架 / 删除插件”。管理员选择单个 ZIP 后，客户端先检查扩展名与 20 MiB 上限，二次确认后以 multipart 上传；后端继续校验 ZIP 安全结构、Manifest V3 和三段数字版本，但不检查安装说明、站点权限、IP 或端口。校验失败的文件可显式清除并重选。更新成功后后端自动删除旧版本 ZIP；下架保留当前 ZIP，重新上架无需上传；永久删除经二次确认后物理删除 ZIP 和发布指针。面板不编译源码，也不提供历史版本或回滚。

Open 系列六套主题由 `api/openThemes.ts` 注册，`app.css` 同时覆盖编辑器与打印 DOM；新增左侧章节索引、学术短线、青绿职业档案、黑白大字、编辑部双栏和蓝幕分区。完整 MIT 声明位于 `public/third-party/template-notices.txt`，来源与适配边界见[模板来源](resume-template-sources.md)。无远程图片、字体或新增依赖。

Original 系列由 `api/originalThemes.ts` 注册：首批朱砂编辑笺为带章节计数的单栏，横向分庭在通栏摘要下将工作与项目/教育/技能分到等宽两栏，墨绿档案签将 identity/教育/技能置于左栏。它们使用经用户确认的图像设计作为排版依据，正文仍为可编辑 canonical 节点而非图片；共享 `app.css` 同时服务编辑器和打印，无新增图片或字体依赖。

Original 的横向分庭、墨绿档案签、横轴履历、暖灰书页、非对称索引、错位页眉、折页边注和悬挂章节在 PDF CLI 下按布局计划保留左右纸面内边距，上下留白由打印正文的克隆内边距在每一页重复提供；`@page` 保持零边距，避免裁掉纸边装饰。流式模板沿用同一正文内边距，不再重复叠加。此规则不依赖主题名称清单。

「非对称索引」使用大姓名页眉、顶部 2:1 简介/技能区、全宽工作经历与页尾项目/教育分区；模板定义决定区域及顺序，CSS 消费语义锚点而非章节标题文本。自定义附加章节回到全宽内容流，正文长度不使用固定高度裁切。

「错位页眉」通过自适应网格错开姓名职业与右侧简介，工作与项目连续通栏，教育和技能在页尾分列；「折页边注」仅工作经历与简介/技能形成约 72:28 的短双栏，项目和教育恢复通栏；「悬挂章节」将章节标签放在窄边距，工作与项目正文沿统一缩进连续排版，页尾教育技能错列。三者均保留完整职业履历，消费既有布局计划与语义锚点，不引入新的 canonical 节点或接口。

Career 跨行业模板由 `api/careerThemes.ts` 登记主题，`app.css` 提供五种独立版式并由编辑器与打印共用；`career-kendall` 为带辅助栏的双栏，其余为单栏。模板内容使用现有语义章节，包含活动、证书及缺省接收插槽；切换模板不以章节显示名称识别内容，不新增 UI 或运行时依赖。

## Muse 共享渲染

`api/museThemes.ts` 注册 79 套主题与原型来源，`resumeContract.ts` 和 `resumeStore.ts` 识别这些稳定主题。独立 `muse-templates.css` 由正式入口、复现入口和 PDF CLI 共用，覆盖现有 `resume-content`、左右栏和头像 DOM，保持流式正文；不另建只读 HTML 模板或编辑器。模板库、编辑器、分享页使用同一主题，PDF CLI 同时注入此样式。Muse 的水平内边距由共享正文规则承担，CLI 在零边距 A4 画布上通过文档容器的 `box-decoration-break: clone` 重复正文上下留白，并取消 Muse 正文自身的上下内边距以避免重复叠加；自然分页保留正文原字号。主题装饰不写入 canonical 内容，也不覆盖用户的行内颜色、局部字号和图片；正文沿用字体设置，装饰标题可使用主题专属字体。

`muse-badge-cn`（蓝笺工牌）的织带、金属夹扣和卡套使用 CSS 内嵌 SVG，随头像尺寸等比缩放，不依赖外链资源。照片仍是独立可替换图层，编辑器与打印 DOM 共用卡套内的照片位置；装饰不接收鼠标事件。系统占位标记在编辑器 NodeView 中保持可见，上传替换头像后清除，避免用户照片继续被占位样式隐藏。

全目录的系统头像占位使用中性人像，用户上传后的头像不受占位规则影响。校园、卡片与商务主题的头像通过浮动或网格参与正文排版，避免覆盖姓名和经历；纸页、拍立得、折角与线圈装饰仍由共享 CSS 绘制，线圈使用内嵌 SVG。PDF CLI 对非 Muse 的列布局统一保留纸面内边距，打印标题尽量与下一段正文保持在同一页。密集模板通过章节和段落间距控制留白，不缩小用户字号或裁切长正文。

普通模板的头像默认使用一寸证件照的 5:7 竖向矩形比例，保留用户设置的照片宽度；工牌、拍立得、拱形肖像等特殊造型各自保留照片容器。通栏色块页眉中的照片设有内侧留白。相邻且连续同色的姓名、职位与联系方式由共享纸张装饰逻辑绘制为一块背景，避免缩略图缩放时出现细缝；不同颜色或具有间距的区域继续独立绘制。背景装饰不改动编辑正文或持久化数据。

整页双栏的装饰由 `features/preview/print/resumeSheetDecoration.ts` 在字体与纸张尺寸稳定后测量。它只延伸栏位的底色、边线与阴影至物理纸边，正文位置、栏宽和内边距保持原值；左右栏按真实几何位置识别，兼容右侧侧栏、缩放与独立四边留白。正文容器的整页外框与底纹另行绘制在纸张边界，头像和条目内部边框保持自身范围。模板预览、工作台、分享页和 PDF CLI 复用此测量逻辑。编辑器把装饰挂在纸张容器上，不修改 ProseMirror 子节点属性，避免触发正文重解析；横向排列只移动各页装饰，继续复用纵向测量结果。装饰只存在于 DOM，不写入简历数据。PDF 在每张物理页重复绘制背景和外框；零模板边距按零处理，不再回退为额外打印留白。


### 原生纸面资源与一致性边界

Mac WKWebView 和 Windows WebView2 的离线纸面由 `apps/native/scripts/build_renderer.mjs` 从共享 Web 渲染函数及基础、应用、打印、Muse 四组样式生成，并将同一份 HTML 复制至两端资源目录。原生显示连续可滚动纸面，等待图片和字体就绪后按实际高度扩展舞台；无效布局或图片失败显式提示。模板预览提示最终排版以 PDF 为准；内容、模块顺序、模板结构、配色、图片与关键布局需保留，字形、换行、分页及像素一致尚未作为跨引擎承诺。内置头像随包内联；私有 PNG／JPEG 图片由原生 HTTP 会话下载、校验并通过 assets 注入，使用现有桌面 Bearer 资源接口及后端所有权校验。图片仅保留在当前纸面内存，不写共享缓存；单张失败显示占位和提示，正文仍可预览。原生入口拒绝任意网页导航，退出与切换拒绝迟到图片写回。代表样例与 Chromium／WebKit／PDF 的检查命令见 `apps/native/README.md`。
