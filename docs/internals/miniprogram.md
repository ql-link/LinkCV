# 微信小程序架构

## 架构职责

`apps/miniprogram` 是独立原生微信客户端，适配账号、简历和求职中心领域：游客可查看一份内置虚构示例，登录用户可完成扫码确认、本人资料维护和本人简历只读浏览。它复用现有用户、简历和求职模型，不提供简历编辑、岗位导入或管理端。

账号业务规则见 [账号与身份功能](../features/identity-account.md)，接口见 [HTTP 接口契约](../api/http-contracts.md)，环境配置见 [本地开发](../ops/development.md)。

## 客户端组成

- `pages/`：简历列表/详情、统一登录、扫码确认、“我的”，以及求职中心列表、时间表、详情与表单。
- `services/`：认证、资料、简历与求职 API，以及正式版本预览缓存。
- `utils/request.js`：Bearer access、refresh、并发刷新与受控重试。
- `config/`：开发、体验和正式环境 API 地址选择。
- `custom-tab-bar/`：游客和登录态共用的“简历 / 求职 / 我的”渠道导航。
- `components/brand-navigation/`：所有页面共用的固定品牌栏，读取设备状态栏高度并保留微信原生胶囊区域。二级页在品牌栏下依次显示返回和标题；登录、扫码确认不显示自定义返回或关闭按钮。表单返回交由原有编辑行为处理。求职弹窗的遮罩与最大高度避开品牌栏，简历预览从剩余视口计算缩放区域。
- `components/company-logo/`：所有求职页共用的公司标识，按调用方给的尺寸渲染岗位快照 Logo；没有 Logo、不是 HTTPS 绝对 URL 或图片加载失败时，回落到公司名称首字加实心底色。底色取该条求职记录已有的 `calendar_color`，不新增字段。服务端的投影还会放行岗位自己托管 Logo 的相对地址（`/api/job-descriptions/{id}/logo?v=...`），但该端点需要 Bearer，而 `<image>` 带不了凭据，所以小程序只渲染 HTTPS 绝对 URL，托管地址同样按不可渲染处理并回落到首字。
- `components/career-date-popover/`：求职时间表的日期挂窗，复用面试时间选择器的月历排布但不做遮罩覆盖；它只上报选中的日期，收起由调用方负责。
- 登录与扫码确认复用同一套左对齐操作流：标题组、主操作和协议行在品牌栏下方整体垂直居中，标题组与主操作之间留 40px。

小程序在启动时载入页面及组件代码，避免首次切换才注入代码；启动、登录和三个主页首次渲染完成时使用 `wx.preloadWebview` 预热下一页面环境，公共品牌图片与底栏的两套状态图标通过 `wx.preloadAssets` 预加载。原生预加载不可用或失败时正常进入页面，不阻塞登录。登录与扫码确认成功后立即触发数据预取并跳转，不再使用固定延时。

已有登录会话时，小程序启动即预取个人资料、求职列表首页及当天安排首页；登录后回到简历页也会补充触发，无需等待简历列表返回。预取仅在内存保留 15 秒，按当前会话隔离、仅供首次进入消费一次；分页续取与后续刷新仍请求服务端，游客不预取。“我的”页个人资料与简历数量并行请求，数量不阻塞资料展示。底部导航点击后立即更新选中反馈，不弹出悬浮加载提示，失败恢复原选中项。

## 后端适配

`apps/backend/src/linkresume/modules/miniprogram/` 提供本人简历列表/详情、PDF、PNG 预览和本人资料适配；登录协议仍由 `modules/identity/wechat_routes.py` 和统一 session 服务负责。小程序 Bearer 依赖只允许访问明确白名单接口，不能复用 Web Cookie 权限面。启用管理员与普通账号都可使用这些本人业务接口和扫码确认能力，停用账号仍会被拒绝；扫码确认会建立独立的 Web Cookie 与小程序 Bearer 会话。

| 入口 | 职责 |
| --- | --- |
| `modules/miniprogram/routes.py` | 本人简历列表、详情、PDF 和 PNG |
| `modules/miniprogram/account_routes.py` | 小程序本人昵称和头像适配 |
| `modules/miniprogram/pdf_service.py` | 可读版本选择与 PDFium PNG 栅格化 |
| `modules/identity/wechat_routes.py` | 小程序登录、账号存在性、刷新和退出协议 |
| `services/auth.js`、`utils/request.js` | token 保存、刷新、重试和失效处理 |
| `services/resumePreviewCache.js` | 正式版本预览索引和本地文件缓存 |

## 预览与缓存链

详情选择最新手动版本，缺失时使用初始版本。FastAPI 复用 Web 打印核心生成智能一页 PDF，再由 PDFium 栅格化为 PNG；服务端不保存 PDF/PNG 成品。客户端按用户、简历和版本缓存在 `wx.env.USER_DATA_PATH`，退出、会话失效或账号切换会清理索引和文件。

游客首页使用双列画廊卡片展示一份明确标注“内容为虚构信息”的内置示例，点击进入完全本地的静态详情，不调用账号或个人简历接口。登录后列表展示真实简历并异步预取正式版本 PNG；页面内部 `scroll-view` 负责滚动和下拉刷新，底部导航位于滚动区域外并固定在安全区上方。真实详情在 `movable-area`/`movable-view` 中支持双指缩放与自由拖动。

## 网络边界

游客冷启动不请求身份或个人数据。用户从“我的”主动进入登录页并确认微信隐私保护指引后，后端才复用已有 openid 账号或在明确同意时创建普通账号；重试路径不能静默完成首次建号，`privacy_accepted` 也不等同于服务端持久化的同意审计记录。环境明确为 `develop` 时，开发者工具默认读取生成的 `local.js`，优先使用 `devtoolsApiBaseUrl` 的本机地址；真机开发版同样自动读取 `local.js` 中的局域网地址。开关为 `false` 可关闭自动本地联调，删除开关恢复平台默认。显式 `linkresume_api_base_url` 覆盖优先于自动配置，且同样只在 `develop` 生效。环境异常、本地文件不可用时回退 `https://linkresume.cn`；`trial/release` 完全不读取开发 storage、设备信息或 `local.js`，第三方平台覆盖也必须使用 HTTPS。启动器生成的端口跟随实际 profile：共享 Dev 使用 `LINKRESUME_LOCAL_BACKEND_PORT`（默认 18000），Local 使用 `BACKEND_PORT`（默认 8000）。配置在冷启动时解析，网络失败不会触发跨环境回退。新增小程序写能力必须先在所属业务功能建立权限与契约，再由该客户端做渠道适配。

## 个人资料交互

“我的”页游客态不请求账号资料，头像和“登录 / 注册 LinkResume”昵称文案分别作为明确的登录入口。登录态点击头像整块即可调起微信头像选择，不在头像上叠加编辑角标；点击昵称后才挂载可见的原生 `input type="nickname"`，静态昵称在编辑期间隐藏，避免透明原生输入框与展示文字叠加；键盘“完成”或失焦都会直接调用 `PATCH /api/miniprogram/account/profile`，无需额外保存按钮。confirm 与 blur 连续触发时由保存状态阻止重复请求；空昵称或接口失败会恢复最近一次服务端昵称并显示错误信息。昵称旁保留编辑提示图标，不再展示与编辑提示竞争空间的“微信已绑定”状态。

## 状态、降级与安全

- access 失效时请求层只允许一次受控 refresh；refresh 失败会清理凭据并回到游客态，不能循环重试。
- 列表可在基础数据返回后异步预取预览；单个预览失败不影响其他简历列表，但详情页应保留可重试错误。
- PDF/PNG 仅接受当前用户可读的最新手动或 initial 版本；客户端传入的 `version_id` 不能扩大可读范围。
- 渲染并发、PDF/PNG 大小、尺寸和像素均有限制；超限或渲染失败不写缓存索引。
- 本地缓存属于可重建派生数据，账号切换和退出必须清理，不能作为服务端版本真值。
- 求职状态文案与 Web 共用同一套产品词表，小程序不另立说法：结束原因区分未通过、已主动结束、已终止和已归档，阶段结束显示“已完成”，场次完成显示“已完成面试”，待排期显示“等待安排”。

## 修改联动与验证

修改登录、token、API 地址或页面行为时，需同步[账号功能](../features/identity-account.md)、HTTP 契约、`docs/ops/development.md` 和 `doc-sync-rules.yaml`；修改预览还需同步简历打印链。主要验证入口为后端 `test_miniprogram_account.py`、`test_miniprogram_resume_pdf.py`、`test_miniprogram_pdf.py`，以及小程序 `auth`、`account`、`request`、`resume`、`pages` 和 `env` 测试。

## 求职中心客户端

`pages/career/index` 默认展示面试安排，顶部透明文字导航按“面试安排 / 求职记录”排列，选中项使用蓝色、较大字号和下划线。切换两个 tab 时内容按方向淡入滑入（面试安排自左、求职记录自右，240ms 减速曲线），导航指示线缩放展开；两个 tab 各自引用不同的 `@keyframes`，类名一换动画才会重新播放，`prefers-reduced-motion` 下全部关闭。两栏外层白卡共用 `shared.wxss` 的 `.panel` 圆角（14px），外层内边距统一为 `8,20,12`，卡片内边距也统一为 14px——两栏按同样的 350 宽带 14px 内陷排版，内层内容宽度都是 322，切 tab 时不会出现横向错步。底部安全区由 `.career-home` 统一预留，不在滚动内容里重复叠加。时间表以北京时间显示所选日的真实场次，重叠场次分列，跨天和非工作时段安排仍可见。日期控件在“添加安排”左侧，由「前一天 / 日期 / 后一天」三段组成：两侧单角引号箭头各走一天并重新加载当天，中间显示“9月17日 · 周四”。点日期打开 `components/career-date-popover` 的月历挂窗——复用面试时间选择器同一套月历排布（周一起始的 6×7 格、黑底选中格、邻月灰字），但不铺遮罩、不做滑入，只是一张贴在工具栏下沿的浮层，所以选日期、点页面空白处或切 tab 都会收起，不锁背景滚动、不隐藏底部标签栏。原先的原生 `picker mode="date"` 和日历图标都已移除：箭头本身说明可以前后翻，日期本身也不再是看不出可点的纯文字。坐标轴只铺开当天真正有安排的那一段，前后各留 1 小时，跨度不足 5 小时时向两侧补齐：固定从 08:00 铺到最后一个场次会让一场 20:00 的面试把轴拖到 13 小时，每小时只剩 36.8px，连块内两行文字都放不下，文字被 flex 压扁。每小时保底 56px（112rpx），轴短于可用高度时仍填满底部导航上方的空间，长于可用高度时随页面滚动，不再把块压到文字以下；轴底边最远到 24:00，跨天的测评在当天铺满整根轴，不会溢出看板。不足 55 分钟的场次放不下两行，只留公司·阶段。场次块不加左侧色条或描边，状态只靠同色浅底（蓝=待面试、绿=已完成面试、橙=等待结果）区分。块内第一行是 24px 公司标识 + 公司名（13px/600）+ 阶段（12px），第二行是起止时间（12px）；常规时长的块内容垂直居中，超过两小时（测评这类铺满整天的）改顶对齐，避免标题被推到看板中段、滚动条还在顶部时看不到。标识按 24px 渲染（与求职记录卡 36/15、详情页头 48/22 的标识与文字比例一致），因此要 28px 块高才放得下，不足 30 分钟的场次和分列后的窄块都不渲染标识——24px 标识加 6px 间距要占掉 118px 窄块的四分之一，挤到阶段只剩两三个字，这两处都改为把空间让给公司名与阶段；阶段在窄块里也只保留阶段名，宽度足够时才追加面试方式。详情通过点击查看。当天存在互相重叠的场次时，在该组下方原位提示“两项安排时间重叠，请核对”；提示随场次位置浮动并限制在时间表范围内，重叠本身仍允许保存。求职记录卡片是一张白卡三行：36px 公司标识 + 公司名（15px/700）· 岗位（14px/600）+ 求职分类；然后「阶段 · 状态」合成一句，两者同字号同字重，状态用 tone 色、带状态图标，读的时候是一个完整的「当前状态」短语，而不是挂在行尾的小字；最后用一条细分隔线接下次安排或投递日期。求职详情页的面试记录卡用同一套「阶段 · 状态」短语写法（该卡阶段是 15px，状态就取 15px 同字号），两处读起来一致。两枚右侧标签都不带底色，只用文字颜色区分（中性 #566173、accent #145ed6、success #267a4d 等），去掉胶囊底后各色文字直接落在白卡上，对比度都在 5:1 以上。整卡可点并有按压反馈，和同页的日期选择、添加安排一致。不额外套灰底分组框——原先的灰块既没起到分组作用，还让两枚徽标的右缘错开一个内边距。列表支持公司/岗位搜索，以及待投递、已投递、Offer、已终止筛选。游客只显示主动登录入口，不请求本人求职数据。

`application` 展示当前阶段、有序历史、场次和岗位资料，页头是白色卡片：48px 公司标识、公司名与招聘类型，右侧是推进操作；`session` 展示排期、准备和文字记录；首页“添加安排”打开 `components/schedule-sheet` 同页弹窗，仅列出已投递、有效、未归档、非 Offer 且处于 `awaiting_result` 的流程，选择后填写下一阶段及排期。普通筛选阶段也可进入此入口安排首次面试；已有排期的阶段需显式完成当前场次。当前阶段待安排时，从求职详情添加安排，仅创建当前阶段场次，不出现在首页选择列表。类型限测评、笔试、AI 面试与普通面试；开始和结束时间均必填，保存后回到安排日期并刷新看板。普通面试、笔试和 AI 面试共用开始时间与持续时长选择器，生成结束时间；测评按整数天数生成完成期限。`components/career-time-picker` 提供按月日历和时、分滚轮，确认后才写回表单，取消保留原值。弹窗开启时隐藏底部标签栏并锁住背景滚动；关闭或更换流程会确认丢弃未保存内容，提交后的重试保持原请求标识和内容。`select` 保留旧路由兼容；`form` 按业务类型切换阶段、排期、记录、准备、Offer 和终止表单。填写或编辑面试记录的页面沿用冷灰页面背景与白色圆角卡片：顶部信息卡用 36px 公司标识加阶段、公司和时间摘要说明当前场次，下方表单卡按字段分组，底部是固定黑色保存栏。其余表单沿用连续白色信息面板与底部黑色主操作，状态文字与图标同时提供反馈。阶段与场次状态以服务端结果为准，保存记录不会自动完成场次，完成场次不会追加阶段。

`career_routes.py` 通过小程序 Bearer 依赖调用现有 interviews 应用服务，复用资源归属、乐观锁与阶段/排期幂等检查。独立表单与弹窗共用 `utils/careerEditor.js` 的保存行为。阶段成功而安排失败时保留阶段，客户端原位重试安排；排期与网页端一致，允许时间重叠，不要求 `allow_conflict` 确认。岗位内容读取这次求职保存的快照；投递简历通过求职专用 PNG 端点读取实际绑定的不可变版本，不能用当前最新版本替换，也不能由客户端指定其他版本。该预览只作临时文件使用，离开页面清理。简历中心原有“只读最新正式版本”规则保持不变。

### 共用详情与编辑入口

时间表与岗位详情的面试卡片都挂载 `components/session-sheet`，按 `sessionId` 读取同一场次。首屏是当前安排面板：36px 公司标识与阶段、公司同处身份头，状态徽标贴在阶段同行右侧，随后用一条分隔线接日期时间与会议方式；再下方是面试记录入口，次级操作贴近面板底部，主操作固定在弹窗底栏。弹窗提供会议链接/地点、记录入口及修改、取消、显式结束场次；结束或取消后的场次隐藏安排操作。填写记录在同一弹窗内展开表单，保存后重新读取场次；变更同时刷新来源列表，保留日期和筛选条件。

`components/schedule-sheet` 同时支持时间表的岗位选择入口、岗位详情传入 `applicationId` 的直接入口和传入 `sessionId` 的修改入口。流程选择列表按 44px 公司标识、公司与岗位、右侧当前阶段三列排布。首次投递可选择筛选中及关联简历；已投递不展示筛选中，详情入口允许记录 Offer。当前阶段待安排时仅创建该阶段排期，已有场次修改不新增阶段。筛选中和 Offer 不校验面试时间；其他排期使用共用日期时间选择器。

记录表单分别读写 `questions_markdown`、`review_summary`、`improvement_markdown`，准备编辑只写 `preparation_note`；保存文字不会结束场次或推进阶段。岗位详情与完整岗位页复用底部导航，完整岗位仅展示本次求职的快照，首卡为岗位摘要：56px 公司标识、公司名与岗位名，分隔线后依次是薪资、城市与招聘类型和“仅供查看”提示；其余卡片读取 `work_city`、学历/经验等结构化字段及公司、来源信息，空字段隐藏。关联简历继续读取本次求职绑定的版本。

小程序 PNG 预览与岗位资料 PDF 校验、简历导入 PDF 检查共用进程级 PDFium 互斥锁，覆盖文档打开、页面处理与资源关闭，避免多线程同时调用原生库导致进程崩溃。预览请求仍保留原有并发容量限制。
