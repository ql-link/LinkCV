# 求职中心功能

## 功能范围

求职中心覆盖岗位导入、一次求职尝试、阶段推进、面试排期、面试记录和素材。岗位资料可被多次求职尝试复用；一次 `JobApplication` 才是完整求职生命周期的聚合根。

字段、状态动作和错误语义见 [HTTP 接口契约](../api/http-contracts.md)，浏览器采集能力见 [浏览器插件架构](../internals/extension.md)。

排期页使用受控事件日历统一承载周视图和月视图，并逐场展示当前日期范围内的全部笔试、测评和面试安排；同一求职进程的一面、二面、三面等多轮安排不会合并成最新一场。单击排期卡片会进入强调选中状态，随后单击其他卡片、空白排期位置或页面其他元素都会清除原选中状态。固定场次继续放在小时网格内；测评和笔试还可保存为跨日 `open_window`，周视图把与当前周有交集的官方开放范围放在顶部“作答时段”只读区域，按截止时间排序，默认最多展示 3 条并以“还有 N 项待完成”展开其余窗口；当前周没有对应事项时不显示整个顶部区域。开放窗口可额外保存一组可空的“我的作答计划”，它只代表用户准备在哪个时间段完成任务，不改变官方起止时间；计划必须完整落在官方窗口内，在小时网格内使用与普通排期相同的公司、时间和阶段卡片显示并支持拖动。

空白位置单击不创建排期，双击才按最近 15 分钟刻度打开新建流程；按住空白位置拖动仍可选择时间范围。周视图支持按住未归档求职进程中的待进行固定场次或个人作答计划，在当天上下移动并保持原时长；拖动上、下边缘分别只修改开始、结束时间，另一端保持不变。官方作答时段保持只读。已经结束求职进程但仍为 `scheduled` 的历史安排也可调整；已完成、已取消或所属求职进程已归档的安排只支持查看，不显示缩放入口。每步调整 15 分钟，最短时长为 15 分钟，固定场次不能拖出当天，个人作答计划必须保持在官方窗口内。松手后通过对应排期接口保存，多个安排允许重叠；相互包含的安排缩进嵌套显示，交叉重叠的安排按同时段数量等宽并排，第三个及更多冲突继续增加分栏。卡片使用较深的左侧色条和同色浅背景；保存失败时重新读取服务端数据。求职详情、记录列表、完成确认和记录详情统一展示完整开始与结束时间；开放窗口笔试和测评在记录详情中区分官方作答时段与个人作答计划，未归档且仍为 `scheduled` 时可以设置或清除计划，完成后保留只读展示。尚未完成且仍在活动求职进程中的笔试、面试记录可以从求职详情页右上角修改开始时间、时长、方式及链接或地点；记录弹窗继续提供添加内容与完成当前阶段操作，已完成或已取消的历史记录保持只读。

固定笔试、AI 面试、普通面试和个人作答计划统一通过一个时间段选择器填写开始时间与持续时长，结束时间即时预览并由服务端推算保存；个人作答计划还会禁用官方窗口外日期，并拒绝结束时间越过官方窗口。

桌面端求职中心以标题导航和内容组成完整模块，页头与其他工作区模块从同一顶部位置开始，并复用 AI 助手外框的底部留白和最小高度；求职记录看板与面试排期在该模块内伸展，看板列和排期日历在各自容器内滚动。月视图在桌面内容区内纵向撑满可用空间，星期栏和当前月份实际需要的四至六周日期单元格使用浅色细网格，不固定补足六周；首尾只保留补齐所在星期所必需的相邻月份日期，跨月单元格保持白色并只弱化日期数字，当天使用深色日期标记和浅色底边提示。月视图事件使用至少 28px 的紧凑条目，同时展示标题和时间；事件超过单元格自动容量时会为“另有 N 项”入口保留完整一行，隐藏安排继续从极简列表弹层查看。该弹层不使用深色外框或嵌套灰色卡片，打开另一日期或点击弹层外任意位置会自动收起。窄屏继续使用移动端独立高度和页面滚动策略。

页面级操作错误使用顶部居中反馈卡片，不提供手动关闭入口，每次错误从最新一次出现起 5 秒后自动消失；会话失效显示可理解的中文提示，不直接暴露 `UNAUTHORIZED` 错误码。需要用户做出选择的确认弹窗保留明确操作按钮，不参与该自动消失逻辑。

## 用户入口

- `/career/applications`：默认展示阶段看板，并可切换到求职记录列表；同时提供岗位导入、采集插件入口、求职进程创建和详情。
- `/career/schedule`：面试排期。
- `/career/applications/:id`：一次求职进程的阶段、面试记录和岗位快照；从这里可下钻到完整岗位。
- `/career/jobs/:jobId`：复用原 JD 详情页展示并就地编辑完整岗位，顶部保留开始或查看求职进程的操作入口；详情正文不重复展示该岗位的求职进程历史，也不提供独立岗位列表入口。
- `/career/reviews`：面试记录和素材的内部入口。
- `/career/jobs`、`/jobs` 与旧 `/interviews` 只承担兼容跳转并回到求职记录；旧岗位新建入口打开求职记录内的岗位导入弹窗，旧岗位详情链接继续兼容。

## 核心对象与规则

- `job_descriptions` 保存用户私有的结构化岗位、可选公司 Logo HTTPS URL 和来源身份；删除岗位会释放来源唯一键，但不会删除既有求职历史。平台另有独立 `global_companies` 公司资料表，当前不与用户岗位建立关系，也不参与导入匹配。
- `job_applications` 保存岗位快照、可选正式简历版本快照、投递事实、流程生命周期、Offer、归档状态与乐观锁；`applied_at` 为空就是待投递。
- `job_application_stages` 以追加记录保存稳定阶段类型、用户可见名称、可选面试轮次、顺序和当前标记；当前阶段和历史都以该表为准。
- `interview_sessions` 同时承载单场排期和复盘，并关联产生排期的具体求职阶段；`schedule_kind` 区分固定场次和开放窗口，开放窗口上的一组可空 `answer_plan_*` 字段保存个人作答计划。
- `interview_assets` 保存面试录音、视频或文档的对象元数据，文件访问继续校验所属求职进程。
- 创建面试必须先存在岗位、求职进程和可排期阶段，不能产生孤立排期；阶段动作只能由后端应用服务执行。

## 依赖边界

该功能依赖身份、简历正式版本、统一 LLM、对象存储和审计。浏览器插件只负责提交用户确认后的岗位采集字段；AI 助手可把岗位、求职进程和复盘作为只读上下文，但不能代替求职中心写阶段状态。

## 关键流程

### 岗位进入系统

- 手工创建直接走统一创建服务；职位名称和公司名称必填，职位描述可以留空。
- 文字/图片智能导入只生成待确认草稿；用户确认后才创建岗位，原始输入和模型正文不落库。未识别出职位描述不阻止确认创建。
- 插件导入先清洗页面字段、规范化来源 URL 和站点身份，再复用相同创建与重复解决事务，不调用 LLM。
- 手工导入和插件核对页都允许填写可选公司 Logo URL；后端只保存通过 HTTPS 绝对 URL 校验的值，不下载或代理图片。

### 求职与面试

1. 用户导入或填写岗位 JD 后，后端在同一事务中创建或复用一条待投递求职记录；JD 是先行必需项，正常入口不再要求用户另建求职进程。
2. 待投递记录可一次进入筛选中、测评、笔试、AI 面试、普通面试或 Offer，也可以直接终止；这次操作同时建立第一条阶段历史并隐式完成“已投递”。用户可以补填实际投递时间，不填时以后端本次有效操作时间为准。简历可不选；选择简历时绑定本人最新正式版本。
3. 后续每次阶段变化只追加新阶段并保留历史，不覆盖旧阶段。筛选、测评、笔试、AI 面试和 Offer 使用稳定类型；普通面试名称由用户按公司流程填写，例如“一面”“二面”“技术终面”或“HR 面”，轮次由用户选填，不从名称推断。
4. “添加下一阶段”弹窗用同一条阶段轨道直接选择测评、笔试、AI 面试、普通面试或 Offer。测评填写可选链接、必填开始时间和完成期限，并保存为开放窗口；开放窗口笔试填写官方开始/结束时间，固定笔试、AI 面试和普通面试填写开始时间与持续时长。开放窗口创建后可在排期详情用同样的开始时间与持续时长方式设置或清除个人作答计划。其余阶段关联、完成与失败语义保持不变。
5. 音频素材先校验进程所有权，再保存对象与元数据；读取和删除继续通过 session→application→user 链路授权。后端继续兼容历史评价字段以及既有视频、文档素材，不因前端入口简化而清除存量数据。
6. Offer 阶段只在用户已经收到 Offer 后添加，不再区分 OC 与书面 Offer。进入阶段时可选填 Base、单值薪资、币种、计薪周期和福利待遇，也允许全部留空；填写薪资时要求同时选择币种和计薪周期，但保存的是这次投递的实际 Offer，不自动复制个人偏好。Web 的列表、看板、详情标题、求职信息和进度节点统一展示“已收到 Offer”；状态记录失败的异常记录显示“Offer 状态待确认”。历史 `accepted` 兼容展示为“已收到 Offer”，历史 `declined` 兼容展示为“已主动结束”，但前端不提供接受或婉拒 Offer 的录入动作。

### 求职进程看板

- 看板分为待投递、筛选中、测评、笔试、AI 面试、用户自定义普通面试、Offer 和已终止；测评和笔试各自独立成列，普通面试按 `stage_label` 动态拆列。
- 桌面看板的阶段栏与页面共用背景，不使用独立的整栏卡片底色、圆角或完整边框；相邻栏只通过浅色单线分隔，栏内岗位卡片继续保持独立卡片层级。阶段列按容器宽度使用舒适列宽：常见 13 寸桌面窗口优先完整展示约六列，更窄时减少可见列并保留横向滚动，更宽时可自然展示更多列。
- 待投递卡片可以直接选择任何业务阶段或终止；进行中的卡片可以在阶段轨道上直接选择下一阶段或终止，不再经过独立“标记已投递”动作。阶段节点切换会立即替换下方表单，已填写的其他阶段草稿只保留在当前弹窗会话中。拖放和表单最终都调用阶段追加或终止接口，冲突后重新读取服务端状态。
- 已结束列的岗位卡片显示“结束阶段：阶段名称”，用于标明流程停留在哪个阶段；列表和详情仍展示“未通过”“已主动结束”等结束原因。
- 看板卡片在状态下方显示时间上下文：待投递展示岗位创建时间，筛选中展示投递时间，测评和笔试展示截止时间，面试展示下一场排期的开始与结束时间，Offer 展示进入 Offer 阶段的时间，已结束展示终止时间；对应时间缺失或无效时明确提示待确认或尚未安排。
- 看板卡片按左侧 32×32 Logo、右侧公司名与岗位名的布局展示岗位快照中的公司 Logo；没有 Logo 或第三方图片加载失败时使用公司名称首字占位，状态、时间和右上角操作菜单保持原位。
- 求职列表默认展示公司/岗位、求职分类、当前进度、最近安排、投递日期和更新时间；最近安排只展示进行中求职流程内尚未结束的有效排期，历史场次保留在详情中。列表按求职分类分组时隐藏重复的分类列，各分类使用带独立表头的表格区块，组间留白，分类标题显示记录数量。

- 右侧圆形“视图设置”图标按钮打开设置面板，顶部提供列表/阶段看板分段切换；阶段看板模式可按真实阶段列选择是否展示待投递、筛选、笔试/测评、各轮面试、Offer 和已结束，下方提供分组与排序下拉框。隐藏阶段只改变当前页面的看板显示，不修改求职记录或阶段流转。开启求职分类分组后，实习、校招、正式和未分类分别展示一行带独立列框的阶段看板，各行阶段列保持对齐；跨分类行拖动不会修改分类或推进阶段，分类通过卡片菜单“修改分类”保存。
- 求职分类复用 `job_snapshot.employment_type`，空值归入未分类。修改仅作用于这次求职记录，不改原岗位和其他记录的快照；后台采用同一进程乐观锁处理冲突。岗位导入和编辑的 `employment_type` 使用同样三类枚举，详情继续展示当前快照。

- 看板以接口返回的稳定阶段类型和普通面试 `stage_label` 组合真实阶段列；普通面试名称不压缩回固定轮次。栏目标题可左右拖动调整位置，也支持聚焦后使用左右方向键移动；顺序保存在当前浏览器标签页中，分组看板的各分类共用同一顺序。未归档、未终止且尚未进入 Offer 的进程可以发起卡片拖动，合法落点复用阶段追加接口；同列、非法倒退和终态拖放不写入，冲突后重新读取服务端状态。
- 宽看板支持 Shift+滚轮、空白区域拖动和卡片靠近边缘时自动横向滚动；横向位置保存在当前标签页的 `sessionStorage` 中，重新进入看板时恢复，卡片按钮和其他交互控件不触发空白拖动。
- 已结束记录在阶段看板卡片菜单和列表中提供永久删除入口。二次确认后删除这一次求职进程及其阶段、排期、复盘和素材文件；原始 JD 继续保留，进行中的求职记录不能通过该入口删除。

## 一致性与失败边界

- 删除岗位只解除求职进程的来源外键，已保存的岗位和简历快照必须继续可读。
- 删除已结束求职进程会清除该进程下的阶段、排期、复盘和素材对象，但不会删除其原始 JD；活动进程不能直接永久删除。
- 创建、阶段动作、排期移动和复盘更新使用 `lock_version` 或幂等请求边界，冲突时不覆盖较新的服务端状态。
- LLM、对象存储或插件采集失败不能生成部分岗位、孤立素材或虚假求职阶段。
- 新增阶段、结果、颜色或素材类型必须同步数据库 CHECK、应用服务、schema、前端映射和接口契约。

## 修改联动与验证

岗位来源契约变化还需同步插件 `contracts.ts`、Manifest 权限和导入测试；求职状态变化需同步看板、列表、排期、复盘和 Agent 上下文。兼容期内服务端继续维护旧扁平阶段字段，旧标签只用于历史投影，新 Web 以 `current_stage`、有序 `stages`、`phase` 和 `lifecycle_status` 为准。主要验证入口为后端 `test_job_descriptions.py`、`test_interviews.py`、`test_job_description_import.py`，以及 Web `JobSmartImportDialog` 和 `InterviewCenterPage` 测试。
