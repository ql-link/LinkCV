# AI 求职助手功能

修改区按消息所属 run 分组，默认只展示最新一轮的提案。发送新问题后，旧提案从修改区收起，但不自动放弃；原对话保留数量摘要，点击后以“历史修改”重新打开。历史列表最多加载最近 200 项。继续调整会显式关联所选提案，输入框提供取消关联入口；只有替代提案成功持久化后，原提案才标记为“已被替代”。未生成替代提案的失败或取消不改变原提案，历史提案的应用继续接受原有权限、有效期及目标冲突校验。

简历修改提案在对话中显示数量摘要入口，完整前后对比和逐项确认操作集中在输入框上方的可折叠修改区，不再堆叠多张卡片。修改区每次展示一项，通过上一项、下一项切换；展开详情有高度上限并独立滚动，收起后保留待确认数量。已应用、放弃或失效的提案仍可查看，但不显示确认操作。该布局不改变提案的逐项确认、冲突检测和持久化语义。

用户显式选择的简历优先于右侧打开的简历；没有显式选择时，当前编辑器提供隐式上下文。已确定本轮简历后，助手不应因存在另一份同名简历而重新询问对象，只澄清确实缺失的修改范围或事实。选择其他简历时，当前编辑器的选区不会带到另一份简历。

## 功能范围

LinkResume AI 助手提供独立对话工作区和简历编辑器侧栏，允许用户组合简历、历史版本、岗位、求职进程、面试复盘和资料集作为上下文，执行简历诊断与修改、保真翻译、面试准备、职业规划和标题建议。它不绕过用户确认直接改写或创建简历，也不向用户暴露模型密钥或 Pi 服务。

浅色助手工作区沿用全局暖白背景 Token；消息、编辑器和卡片等内容层继续通过各自表面样式区分层级。

接口与 SSE 终态见 [HTTP 接口契约](../api/http-contracts.md)；服务拆分、内部工具和模型治理见 [Agent/LLM 运行时架构](../internals/agent-runtime.md)。

## 用户入口

- `/assistant`：新建对话入口；`/assistant/:sessionId`：可刷新、可直接访问的独立会话地址。页面同时提供会话列表、快捷任务、上下文选择、对话、停止和提案确认；发送后的读取、分析和生成进度只在当前消息附近显示，不在消息区顶部重复渲染状态标题。侧栏在“新建对话”下方保留“资料库”入口，点击后在助手工作区内切换显示既有资料库而不改变路由；右上角“我的简历”打开本人简历选择器。选择简历后，同一页面右侧嵌入既有可编辑简历工作台，并自动将整块会话侧栏完全收起，不保留图标栏或占位宽度；工作区左上角的展开/收起按钮可恢复或再次隐藏完整侧栏。桌面端会话栏默认宽度为 240px，可拖动右侧分割线在 220–420px 范围内调整；置顶会话显示在独立的 `Pinned` 分组，未置顶会话显示在“最近对话”，两个分组可各自展开或收起，没有置顶会话时不渲染空的 `Pinned` 分组。打开历史会话只切换当前内容，不改变列表位置；用户在该会话发起新一轮消息后，它才移动到所在分组首位。Pin、Unpin、Rename 和 Delete 操作共用三点菜单；菜单仅在上方有足够列表空间时向上展开，否则向下展开并由滚动列表预留完整显示高度。已有对话的输入框固定在消息区底部，随输入内容增长到最多 6 行，超过后在编辑区内滚动；输入框内不重复提供添加资料按钮，资料入口保留在其下方。新建对话继续使用独立的居中大输入框，不继承已有对话的底部位移或动态高度。输入框键入 `@` 会在上方打开本人资料与简历的搜索列表，结果按“简历”和“资料”分组，`@` 后文字按资料名或简历名的前缀同时匹配，`Tab` 默认选择首项。选中结果在编辑区内成为不可拆分的文件引用单元，普通文字可以插在引用前后；发送后的用户消息继续在原位置显示内联文件单元，不显示 `@文件名` 占位文本或气泡下方的重复文件标签，提交协议仍使用结构化上下文引用。
- 当前浏览器标签页会记住最近一次已打开的会话；用户切到其他工作区后再点击顶部“AI 助手”会回到该会话，点击“新建对话”则清除这个返回目标。
- `/resumes/:resumeId/edit` 的 `AgentPanel`：围绕当前简历或选中文本发起助手请求。
- `/admin/llm/models`：管理员维护模型候选和四项能力绑定；这是治理入口，不属于普通用户助手操作。

## 核心规则

- Agent 按 Markdown 整体替换章节标题或经历标题时，仅清除被替换字段原有的文字样式片段，避免旧片段覆盖新文字；未修改字段的局部字号等样式保持不变。

- 浏览器只提交服务端签发的上下文引用和版本标记，不把受控对象全文拼入用户消息；`@` 提及只提供搜索与选择快捷入口，不能绕过服务端的用户归属、解析状态、对象键和版本校验。
- Agent Markdown 统一支持标题、段落、软换行、水平分隔线、表格、有序与无序列表、引用、强调、删除线、链接以及围栏/行内代码；一级至三级标题分别映射为消息内的 `h2`、`h3`、`h4`，字号按层级递减且始终大于所在消息正文。围栏代码显示语言和复制操作，表格与代码在窄容器内独立横向滚动。原始 HTML 不执行，远程图片只显示文字占位，任务列表、脚注和 Mermaid 等扩展语法不在普通消息边界执行。
- 独立助手和简历编辑器侧栏中的用户消息、AI 回复正文与周边控件统一使用随应用发布的思源黑体 UI 字体栈；独立助手消息正文使用 15px 字号，内联文件引用继承相同的字号和行高，并在同一文字基线上收紧外框。用户 Query 使用右对齐的中性浅灰气泡，AI 回复使用左对齐的无气泡 Markdown 正文。字体与消息布局只影响浏览器呈现，不改变消息正文、Markdown 或上下文引用的保存值。
- 独立助手成功完成或用户主动停止一轮发送后清空输入框内的草稿与已选引用；只有失败终态保留它们，以便用户调整后重试。已发送的 query 始终留在消息历史中，取消不能把它自动复制回输入框。请求、生成和提案操作失败复用页面根层上方居中的统一反馈浮层，局部字段校验和上下文选择状态仍留在对应区域。
- 独立助手运行不依赖当前页面是否挂载：切换到简历或其他页面、切换会话、刷新页面只断开当前浏览器订阅，不取消后台生成；返回原会话时恢复“思考中”或流式输出，并在运行已完成时读取持久化结果。用户点击“停止生成”仍会显式取消。
- 从简历编辑器侧栏发送请求，或在独立助手中打开简历后发送请求时，Web 先保存当前草稿，再通过统一 `contexts` 协议提交 `{type:"resume",id}`；会话本身不保存默认简历。独立助手自动附带当前打开的简历时使用 `presentation:"implicit"`：后端仍保存并授权本轮简历上下文，但输入框和发送后的用户消息不渲染 `@简历` 引用单元；用户手工选择或输入 `@` 的资料继续显式展示。存在编辑器选区时，同一请求附带稳定块 ID、范围和内容摘要。经历的组织、角色、地点、起止时间、链接、学位和专业按各自 canonical 节点投影，表格行中的正文也保留可定位节点。
- Agent 运行可以定位、读取、诊断和生成提案；所有简历写入先形成 `resume_change_proposals`。复合修改意图会先按 section、entry、字段或独立块生成一份不可变任务清单，再由 Pi 在同一 run 中逐项串行执行“定位—读取—诊断—提案”；识别出多个目标不能作为拒绝修改的理由，也不允许多个提案工具共享可变目标状态并行执行。同一父范围内的重复短文本由一次父范围读取返回的不同 `block_id` 展开为独立任务。每个执行单元只生成一张提案，单项失败记录后继续剩余任务，重复调用同一批处理工具只返回既有结果而不重复创建提案。模型在提案操作中只引用本轮范围读取返回的稳定 `block_id`，Pi 运行时用同一份服务端结果补入完整 locator 与内容哈希，避免模型复制或改写授权目标导致提案请求失效。
- Pi 每轮先读取职业助手路由并选择唯一主工作流。面试准备、职业规划和标题建议为只读工作流；普通简历编辑继续使用范围化 operation；整篇翻译使用独立 `translate_resume` 提案，不能与润色或重写混用。
- 用户询问自己有哪些简历、已解析资料或面试记录时，Pi 可调用 `list_user_resources` 返回当前用户的轻量目录；目录只含名称、ID、状态、版本和更新时间，不包含正文。用户明确指定名称、ID 或目录中的某一版本用于当前请求时，Pi 调用 `resolve_resume_reference`；局部编辑再把该解析结果交给 `resolve_resume_target`，不退回依赖会话绑定。FastAPI 只在当前用户下解析目标，名称同名时返回候选，并允许按用户已给出的版本条件用候选 ID 精确解析。解析结果只授权当前运行读取，不绑定或改写会话，也不要求用户再次通过 `@` 选择。
- 诊断中的岗位关键词分数只表示文本覆盖率，不表示岗位匹配或录用概率。缺少数字本身不是高风险问题；真实的定性结果、交付物、服务范围、稳定性和业务作用同样构成结果证据。
- Agent 的用户可见回复先给出实质答案或实际结果；单一简单问题的整条回复默认使用一至三句连续正文，用户指定的事项数量是实质内容硬上限，必要限制必须并入已请求事项。两个及以上并列的发现、建议、步骤或选项使用真正的 Markdown 短列表且每项最多两句，列表后不追加补充段落。简单回复不添加标题，失败、未完成和未验证事项必须优先说明，回复结束后不重复总结或追加客套话。
- 工具阶段中模型主动生成的可见过程文字和服务端固定的工具执行标签实时累计在“思考中”的可展开区域，不写入正式对话；结构化活动按稳定 `callKey` 原位更新为运行中、成功或失败，因此同一次调用不会重复堆叠相同步骤。隐藏思考、工具参数和工具结果不在这里展示。全部工具结束后该区域一次性清空，正式回复从首个 token 开始在正文位置实时输出。
- 简历上下文和提案统一读取 strict canonical 快照；模板投影由 `LayoutPlan` 提供，Agent 不能把 region、slot 或分页信息写进正文。Agent 的 Markdown 上下文只在序列化边界把 canonical `InlineIcon/title_icon` 输出为白名单 `:icon[Name]:` 标记，不能把图标降级成普通正文后回写。旧快照只能经受控迁移/导入适配器进入系统。
- 用户确认提案时再次校验所有权、目标定位、内容前置条件和简历图片导出契约。多张范围化提案共享创建版本时，先确认一张不会让其他不相交提案失效：服务端在当前快照按目标哈希安全重放，只有目标自身变化才拒绝；旧快照和翻译提案继续严格校验 `base_lock_version`。图片缺失、不支持或超过单图/快照总量上限时拒绝确认，当前简历和提案状态保持不变。
- 停止、失败和异常 EOF 都有明确终态，不能把半条响应当作成功。

## 数据归属

会话、运行、消息、工具调用和提案分别由 `agent_sessions`、`agent_runs`、`agent_messages`、`agent_tool_calls` 与 `resume_change_proposals` 保存。会话只持久化标题、置顶和生命周期等展示状态，不持久化默认简历；简历归属保存在具体消息的上下文快照及提案目标中。列表先展示置顶会话，再按 `updated_at` 和内部 ID 倒序。模型候选、能力绑定、验证和计量属于技术治理数据，不是用户对话内容，详见运行时架构文档。

结构化澄清答案、被回复的助手消息序号和经过校验的编辑器选区一起保存在用户消息元数据中。回答澄清时，服务端沿该助手消息的 run 找回原用户消息上下文与选区，并重新校验资源归属、存在性和版本；客户端不能用同类型的另一资源或另一选区静默替换原目标。后续运行会同时恢复问题、选项 ID、答案、已复验上下文和稳定选区，不依赖页面未刷新的临时状态或展示文本重新猜测已确认的修改范围、动作或位置。字段或块内选区清空通过受目标哈希保护的空字符串替换表达；完整 paragraph/list item 使用结构化 `delete_target` 删除，不留下空 bullet，二者都须生成提案并由用户确认。

## 关键流程

1. Web 查询 readiness 和可选上下文，提交用户消息、幂等键及轻量引用。
2. FastAPI 校验上下文所有权与版本，创建 run/message 后调用 Pi，并把 Pi SSE 事件转换为浏览器协议。
3. Pi 只能通过内部工具列出轻量资源目录、读取受控材料、执行诊断或创建修改提案；目录查询不返回正文，用户明确指定简历时先解析本人简历作为本轮目标，再由现有范围化上下文工具读取正文。工具调用和结果摘要写入审计数据。
4. 需要补充信息时返回结构化 clarification；继续对话复用同一 session，每轮可以按用户要求选择不同的简历上下文。
5. 用户确认普通编辑提案后，FastAPI 重新读取目标和简历锁版本，校验 canonical 文档、presentation、模板快照与私有图片导出契约，再更新源简历。确认翻译提案时源简历保持不变，FastAPI 创建一份独立可编辑简历和初始版本；源简历私有图片复制到新命名空间，重复确认返回同一结果简历。

## 权限与失败边界

- session、run、proposal、上下文引用和目标简历都必须同时校验当前用户，公开 ID 不能代替归属条件。
- 会话支持独立的标题和置顶更新；更新只改变展示状态，不创建消息或触发模型调用。删除会话前必须确认没有运行中任务，并在事务中清理其提案、工具调用、消息和运行记录。
- 会话删除只作用于当前用户拥有的目标会话；其他用户的公开会话 ID 统一按 `AGENT_SESSION_NOT_FOUND` 处理。
- 删除简历只清理以该简历为目标的待确认提案；独立会话及历史消息继续保留，旧上下文快照不再授权读取已删除资源。
- 取消请求、Pi 不可用、模型失败、异常 EOF、提案过期、内容摘要不一致和锁冲突都有独立终态；失败不会把提案标为已应用。
- 对话正文不会写入 LLM 调用日志，模型凭据不会返回浏览器，内部工具不能接受任意 URL 或对象键。
- 登录用户可通过 `GET /api/agent/model` 读取当前 `pi_agent` 绑定的 `adapter` 和调用名 `name`；该摘要不返回配置 ID、地址、凭据、价格或验证记录，也不会为展示而解密凭据。
- 助手对岗位、求职和资料集只有受控读取能力；业务写入仍回到对应领域服务。资料替换后，后续引用读取最新 Markdown；资料正文不提供用户或 Agent 编辑入口。
- 求职进程上下文读取 `current_stage` 的稳定类型、显示名称与轮次，并单独读取 `phase` 和生命周期；兼容期内只有缺少阶段历史的旧记录才回退到扁平阶段字段。

## 修改联动与验证

修改 SSE 事件、上下文类型、提案 operation 或澄清结构时，需同步 `schemas.py`、Pi 协议、Web 两个客户端、接口契约和 Agent 测试；模型能力变化还需同步[运行时架构](../internals/agent-runtime.md)。主要验证入口为 `test_agent_routes.py`、`modules/agent/test_context_service.py`、`test_pi_client.py`、`test_service.py`，以及 Web `AssistantPage` 和 `AgentPanel` 测试；完整 Pi 运行时检查使用跨平台的 `npm run check:pi`。

## 管理员调用排障

管理员可在独立的「Agent 调用排障」页面按一次消息操作查看阶段轨迹。服务端从已校验归属的会话反查用户 ID，记录预检、运行创建、Pi 执行、工具调用、提案创建和确认的受控状态与错误码；页面不展示用户消息或简历正文。旧运行只提供原有摘要，标记为历史记录。
