# AI 求职助手功能

普通 AI 提案确认只更新当前简历，不查询、统计或新增 `resume_versions`，也不受历史版本容量限制。范围化提案重放 operation，新 scoped 提案只保存 operations 和有界 preview，不保存整篇副本；旧快照提案仍要求内部锁一致。正文和已应用状态在同一事务提交，重复确认不再次修改。

两个 Web 助手入口共用 Store 的保存与确认队列：先保存草稿，确认期间锁定目标编辑器写入，成功后使用响应更新 Store 和编辑器。传输失败会先查询提案状态，已应用则读取最新正文；不能核实结果时明确提示结果未确定，不自动重发确认。

修改区按消息来源分组，同一 run 的插入使用来源用户消息序号区分，并跟随对应助手回复保留在对话流中。发送新问题后，旧提案继续停留在原轮次下方并标记为“历史修改”，不会自动放弃。历史列表最多加载最近 200 项。继续调整会显式关联所选提案，输入框提供取消关联入口；只有替代提案成功持久化后，原提案才标记为“已被替代”。未生成替代提案的失败或取消不改变原提案，历史提案的应用继续接受原有权限、有效期及目标冲突校验。

简历修改提案不再额外显示数量摘要卡，也不固定在输入框上方；完整前后对比和确认卡直接出现在对应助手回复之后，并随消息区一起滚动。每个轮次的修改区始终展开且一次展示一项，右上角通过上一项、下一项切换；卡片不显示“基于版本”和重复的“简历修改提案”标题。待确认项底部左侧提供应用当前项、继续调整与放弃，右侧在存在多项待确认内容时提供“全部应用”；这些确认按钮按按钮层级 v2 使用描边次级样式，避免对话中多张卡片同时出现黑色主按钮；批量应用按列表顺序确认并在首个失败或冲突处停止，保留已成功项和剩余待处理项。已应用、放弃或失效的提案仍可查看，但不显示确认操作。该布局不改变单项提案的权限、冲突检测和持久化语义。

用户显式选择的简历优先于右侧打开的背景简历和历史记忆；明确点名与显式选择冲突时询问，当前编辑器自动附带的简历允许被本轮明确切换替代。短期记忆保存近期各轮简历身份及任务关系，供助手理解“继续看第二段”“回到前面那份”；它不自动绑定下一轮目标。指代明确后重新校验并读取当前内容，歧义、另一份未明确或记忆超窗时澄清；无关问题不读取简历。追问上一轮 `@` 过的简历内容（没有再次 `@` 也没有点名别的简历）视为对该简历的延续指代，会从记忆读取当前内容后回答。切换到其他简历时，旧编辑器选区不会带过去。记忆与授权边界见 [运行时架构](../internals/agent-runtime.md)。


助手展开的执行过程显示具体工作流名称和成功/失败状态，保留失败重试的独立记录；文字与工具状态按事件首次到达的顺序展示，工具完成时更新原记录。


管理端启用能力线路时自动验证模型；失败显示原因并保持停用，无需手动点击探测。意图识别协议在独立一行完整显示。

## 功能范围

管理员可以独立配置“助手意图识别”模型，选择 Chat 结构化识别或 AIHubMix 原生决策（System One）协议，在工具执行前识别多项目标；有效计划校验并保存后，助手按计划执行。未配置或识别调用失败时沿用已有路由，业务信息不足时仍先澄清。独立识别不改变用户选择的对话模型，也不能扩大资料权限或跳过提案确认。配置与失败边界见 [Agent 运行时](../internals/agent-runtime.md#调用链)。

识别规则先区分用户是否要求执行业务工作流，再检查该任务必要信息。普通问候、能力介绍和使用方法不生成任务；混合请求保留全部业务目标，历史仅用于解释当前指代。已选简历的“泛优化、先看看问题”可以先诊断，不额外生成修改提案，也不要求补全岗位等无关字段。原生决策每次选择最先阻塞执行的一项澄清原因；Pi 的澄清工具不得追问识别结果以外的类别。置信度不足、结果矛盾和格式错误分别记录，继续沿用受原权限、任务校验和提案确认约束的主模型路由。

LinkResume AI 助手提供独立对话工作区和简历编辑器侧栏，允许用户组合简历、岗位、求职进程、面试复盘和资料集作为上下文，执行简历诊断与修改、保真翻译、面试准备、职业规划和标题建议。它不绕过用户确认直接改写或创建简历，也不向用户暴露模型密钥或 Pi 服务。

浅色助手工作区沿用全局暖白背景 Token；消息、编辑器和卡片等内容层继续通过各自表面样式区分层级。

共享侧栏的“首页”仅在新对话入口选中；打开历史会话（包括读取中或空会话）时取消首页选中背景，由对应的最近对话行显示选中状态。

主动询问期间可以在主输入框直接发送新消息，跳过当前询问；发送后询问卡片移除，旧询问不再作为普通消息展示。选择“其他”并输入补充内容时，只通过外层选项边框表示选中，不叠加输入框边框或聚焦描边。

接口与 SSE 终态见 [HTTP 接口契约](../api/http-contracts.md)；服务拆分、内部工具和模型治理见 [Agent/LLM 运行时架构](../internals/agent-runtime.md)。

已验证的 AIHubMix 快速模型在按推荐协议绑定后，助手探测和正式对话都显式关闭上游思考；GPT-6 Luna 需要使用 Responses，原有 Chat 绑定不会被代码自动替换。适用模型及参数见 [运行时模型治理](../internals/agent-runtime.md#治理数据)。其他模型沿用其原有请求参数。

供应商返回超长调用编号时，FastAPI 与 Pi 保留成功结果和计量，管理日志的对应可选编号留空；边界处理见 [运行时模型治理](../internals/agent-runtime.md#治理数据)。

## 用户入口

- `/assistant` 展示首页任务卡与输入框；`/assistant/:sessionId` 展示可恢复的会话。共享侧栏提供首页、简历、模板、岗位看板、面试日程、资料库和最近对话，点击工作区入口进入对应独立路由。会话菜单提供 Pin、取消 Pin、重命名与删除；Pin 状态通过现有会话接口持久化。Pin 对话单独显示在最近对话上方，两栏同级且可独立收起展开；收起状态在当前账号的页面切换中保留，切换账号时重置。最近对话标题右侧不提供新建按钮。共享侧栏仅在存在置顶会话时展示 Pin 分组，取消最后一条置顶后整个分组隐藏。共享侧栏在首页、历史对话及全部工作台模块均不提供“新建对话”按钮；返回首页可进入新对话输入状态。
- 首页问候、副标题、快捷指令和任务卡等待所需数据齐备后一起展示，加载中保留原布局占位，不先展示通用文案再替换。读取失败显示可重试状态，不把失败当作没有简历、面试或岗位。返回首页重新读取时不会先展示上次的结果；切换账号或页面后的迟到响应不覆盖当前页面。历史会话在内容读取完成前使用对话加载态，不短暂展示新对话首页，读取失败可原位重试。
- 首页 Offer 卡读取本人求职记录的结构化回复截止，已填写日期按最早截止优先；未填写时提示补充。日期只精确到日，剩余天数、当天和过期状态按浏览器本地日历计算。对比卡打开真实 Offer 对比表，展示公司、岗位、薪资、地点、福利和三项日期；只有同币种、同计薪周期且薪资已填写时才计算差距。
- 输入框支持模型选择、资料引用和截图；`@` 搜索本人简历和已完成资料，发送继续使用结构化上下文引用。截图在输入框显示 56px 缩略图，发送后显示 72px 缩略图，超出可用宽度显示余量入口。截图预览属于本地交互，不会悄悄当作已上传的服务端上下文。
- 对话右侧可预览简历、资料、图片和生成文档；默认宽 520px，可在 400–720px 之间拖动，窄于 1280px 时用覆盖抽屉。最多保留六个预览标签，超过时移除最早打开项，Esc 收起面板但保留标签。打开简历复用可编辑工作台及现有保存队列，选区引用会定位相应内容。
- 明确的文档生成请求走现有 Agent 消息和流式运行接口，沿用当前模型、资料引用、权限及失败处理；完整 AI 回复中有一级 Markdown 标题时，将实际正文呈现为可预览文档。失败、未完成、澄清和普通回复不使用示例文档替代。产物 ID 来自会话与运行，历史消息可重新恢复文档正文；保存状态仍只在当前页面内存。点「保存到资料库」先选择本人现有文件夹，也可在弹窗中新建文件夹，再把当前正文作为 `.md` 文件通过 `POST /api/datasets` 上传；成功后才标记原会话中的文档已保存。重名时添加时间和随机后缀保留两份，失败时提示并保持未保存。网络结果不明确或服务端仍在上传时，原文件、目标文件夹和幂等键保持固定，关闭后重新打开也复用该请求；新建文件夹不随取消保存回退。产物之外的卡片状态仍只在当前页面内存。不可用资料显示失效状态，不支持预览的格式保留下载入口。
- `/resumes/:resumeId/edit` 的 `AgentPanel` 围绕当前简历或选中文本发起请求。
- `/admin/llm/models`：管理员维护接入商连接、逻辑模型（含对话页是否可选）、线路与使用场景绑定（含模拟面试、识别稿修正、简历匹配度、面试准备清单、语音识别和语音合成）；AIHubMix 连接可在默认地址不可达时切换到官方备用地址，再同步目录并重新探测关联线路。管理员只能删除从未被使用过的连接、模型和线路；已经用于绑定、调用或会话的只能停用，这样用户的历史会话和调用记录不会丢失模型信息。这是治理入口，不属于普通用户助手操作。
- 旧 `/assistant/workspace/*` 地址保留兼容解析，新导航使用各模块的独立地址。
- Mac 原生客户端经 desktop Bearer 使用同一组用户侧 `/api/agent/*` 接口：侧栏最近对话、新对话、消息 SSE、进行中运行重连、停止、追问选项、附加资料与修改建议应用/不采用；也支持切换模型（`PATCH` 会话 `modelId`）、服务端开放 steering 时生成中插话，以及把含一级标题的回复保存为资料库 `.md`。右侧文件预览可打开附加的简历、资料、生成文档与截图（简历用预览快照渲染，并把待确认修改的原文所在段落标黄；资料读取解析文本）。截图可经系统区域截图、剪贴板、图片文件或拖入添加，与 Web 相同只保留在本机：带截图发送不请求后端，只留下本地消息，明确要求生成文档时提示先移除截图。详见 [原生客户端](../../apps/native/README.md#mac-ai-对话)。

助手首页的任务卡按可用内容宽度自动改变列数，快捷指令允许换行，顶部留白随窗口高度收缩；窄屏预览覆盖内容区。导航与弹窗约束见 [Web 响应式布局](../internals/web.md#响应式布局)。

首页“与简历最匹配的岗位”卡只在原本显示岗位推荐的位置出现，数据来自用户全部已保存岗位和最近编辑的简历。页面读取结果，没有结果时自动请求后台计算并每 3 秒轮询，最多 20 次；加载中、计算中、没有岗位、不可用和出错各有不含示例数字的卡片状态。这张卡的分析走统一 LLM 的 `job_match` 场景，不属于 Agent 运行时。

## 消息排队与插入

独立助手和编辑器侧栏不在用户消息下方展示任务摘要及完成状态；服务端的任务规划、执行和结果记录保持不变。

独立助手与编辑器侧栏不再挂载本机消息队列，不显示输入框上方的运行恢复、队列暂停、排队列表或编辑入口。文字请求直接调用现有消息接口；生成期间只显示停止按钮，用户仍可输入草稿，Enter 不会加入队列，也不会自动发送下一条。运行结束或停止后恢复发送按钮，用户手动提交下一条消息。重复提交在首次请求准备期间被拦截，发送只清理本次草稿，之后输入的内容保留。

旧本机队列数据不被删除，但两个入口不再读取、恢复或调度它们。历史会话与已经启动的运行继续通过既有接口恢复，历史插入消息仍按来源显示。服务端消息、取消、插入及回执接口保持不变；此变更只关闭 Web 排队能力。

## 核心规则

- 消息、代码块和生成文档复制使用统一剪贴板兼容方法；远程 HTTP 下没有 Clipboard API 时仍尝试复制，失败时显示错误。编辑器选区摘要在 Web Crypto 缺失时保留同一 UTF-8 SHA-256 算法与摘要格式，见 [Web 浏览器能力兼容](../internals/web.md#浏览器能力兼容)。

- Agent 在 canonical 节点上替换文字，保留未改文字的局部样式；新增文字继承被替换位置的样式。工作模块只有正文块、没有独立经历条目时，仍可读取模块并定位连续正文范围，分析或提出局部修改；不会因此要求重新导入简历。

- 浏览器只提交服务端签发的上下文引用和版本标记，不把受控对象全文拼入用户消息；`@` 提及只提供搜索与选择快捷入口，不能绕过服务端的用户归属、解析状态、对象键和版本校验。
- 独立助手首页默认附带最近编辑的简历标签；发送文字请求时，标签引用会补上与手动 `@` 相同的简历名称指向，已有对应 `@` 时不重复添加。消息展示使用补齐后的内容，输入草稿不被改写；移除标签后不补充引用，手动选择另一份简历则使用新的选择。结构化简历引用仍负责权限和版本校验。
- Agent Markdown 统一支持标题、段落、软换行、水平分隔线、表格、有序与无序列表、引用、强调、删除线、链接以及围栏/行内代码；兼容 `**` 加粗结束标记前带空格、中文标点后紧接正文的情况，代码与转义内容仍保留原文。一级至三级标题分别映射为消息内的 `h2`、`h3`、`h4`，字号按层级递减且始终大于所在消息正文。围栏代码显示语言和复制操作，表格与代码在窄容器内独立横向滚动。原始 HTML 不执行，远程图片只显示文字占位，任务列表、脚注和 Mermaid 等扩展语法不在普通消息边界执行。
- 独立助手和简历编辑器侧栏中的用户消息、AI 回复正文与周边控件统一使用随应用发布的思源黑体 UI 字体栈；独立助手的消息按 V3 对话样式呈现，内联文件引用继承所在消息的字号和行高，并在同一文字基线上收紧外框。用户 Query 使用右对齐的中性浅灰气泡，AI 回复使用左对齐的无气泡 Markdown 正文。悬停消息或将键盘焦点移入消息时，用户消息右下、AI 回复左下显示该条消息的时间和复制按钮；触屏设备常显这组操作，复制保留消息正文中的 Markdown 标记。字体与消息布局只影响浏览器呈现，不改变消息正文、Markdown 或上下文引用的保存值。
- 独立助手的本机队列保存成功后清理本次提交的草稿和引用；运行结束、失败或停止保留后来新输入的内容。已发送的 query 始终留在消息历史中，取消不能把它自动复制回输入框。请求、生成和提案操作失败复用页面根层上方居中的统一反馈浮层，局部字段校验和上下文选择状态仍留在对应区域。
- 独立助手运行不依赖当前页面是否挂载：切换到简历或其他页面、切换会话、刷新页面只断开当前浏览器订阅，不取消后台生成；返回原会话时恢复“思考中”或流式输出，并在运行已完成时读取持久化结果。用户点击“停止生成”仍会显式取消。
- Web 收到运行终态后即结束流消费，不再等待连接关闭。独立助手及编辑器侧栏结束后的会话、提案回读属于补充同步；回读失败时保留已收到的回复、提案和运行终态，不把已完成对话误报为失败。真实的运行失败、终态前断流和无法续期的发送请求仍按错误处理。
- 从简历编辑器侧栏发送请求，或在独立助手中打开简历后发送请求时，Web 先保存当前草稿，再通过统一 `contexts` 协议提交 `{type:"resume",id}`；会话本身不保存默认简历。独立助手自动附带当前打开的简历时使用 `presentation:"implicit"`：后端仍保存并授权本轮简历上下文，但输入框和发送后的用户消息不渲染 `@简历` 引用单元；用户手工选择或输入 `@` 的资料继续显式展示。存在编辑器选区时，同一请求附带稳定块 ID、范围和内容摘要。经历的组织、角色、地点、起止时间、链接、学位和专业按各自 canonical 节点投影，表格行中的正文也保留可定位节点。
- 用户在独立助手中应用目标为当前右侧简历的提案时，Web 先保存尚未落库的编辑内容；确认成功后重新读取服务端 canonical 快照，并显式替换 Tiptap 文档且不触发新的编辑保存，使右侧工作台立即显示修改结果。其他简历的提案不会替换当前编辑器；提案已应用但刷新失败时保留“已应用”状态并提示重新打开简历。
- Agent 运行可以定位、读取、诊断和生成提案；所有简历写入先形成 `resume_change_proposals`。纯诊断是只读流程：只读取并分析简历，不产生任何修改提案；要求“先诊断再修改”才是两项任务。修改时模型一次提交完整修改计划（可含多个目标），由运行时按顺序逐项定位、校验并创建提案，识别出多个目标不能作为拒绝修改的理由，也不允许并行共享可变目标状态。同一父范围内的重复短文本由一次父范围读取返回的不同 `block_id` 展开。每个执行单元只生成一张提案（整段经历重写合并为同一段经历的一张提案），单项失败记录后继续剩余项，重复提交同一计划只返回既有结果而不重复创建提案。模型在提案操作中只引用本轮范围读取返回的稳定 `block_id`，Pi 运行时用同一份服务端结果补入完整 locator 与内容哈希，避免模型复制或改写授权目标导致提案请求失效。任务结果由运行时依据实际生成的提案判定：没有生成提案的修改不会被记为完成。
- 简历编辑的执行 Skill 按原文是否存在及修改范围选择，而不是按“润色、优化、改写”等措辞选择：无原文进入素材生成，单字段、单 bullet 或块内选区进入局部编辑，同一经历摘要或多个 bullet 进入经历重写；多个独立局部目标使用复合局部修改清单。
- Pi 每轮先读取职业助手路由，保存本轮任务清单，再逐项选择工作流并记录结果。面试准备、职业规划和标题建议为只读工作流；普通简历编辑继续使用范围化 operation；整篇翻译使用独立 `translate_resume` 提案；不同任务可分别使用翻译、润色或重写。
- 用户询问自己有哪些简历、已解析资料或面试记录时，运行时读取当前用户的轻量目录并交给模型整理；目录只含名称、ID、状态和更新时间，不包含正文。本轮显式选择或编辑器背景的简历自动用于需要简历的任务；用户明确点名另一份、指代历史简历或要求切换时，才通过受控解析得到目标简历（同名时返回候选，可按更新时间等条件用候选 ID 精确解析）。解析结果只授权当前任务读取，不绑定或改写会话，也不要求用户再次通过 `@` 选择。
- 诊断中的岗位关键词分数只表示文本覆盖率，不表示岗位匹配或录用概率。缺少数字本身不是高风险问题；真实的定性结果、交付物、服务范围、稳定性和业务作用同样构成结果证据。
- Agent 的用户可见回复先给出实质答案或实际结果；单一简单问题的整条回复默认使用一至三句连续正文，用户指定的事项数量是实质内容硬上限，必要限制必须并入已请求事项。两个及以上并列的发现、建议、步骤或选项使用真正的 Markdown 短列表且每项最多两句，列表后不追加补充段落。简单回复不添加标题，失败、未完成和未验证事项必须优先说明，回复结束后不重复总结或追加客套话。
- 工具阶段中模型主动生成的可见过程文字和服务端固定的工具执行标签实时累计在“思考中”的可展开区域，不写入正式对话；结构化活动按稳定 `callKey` 原位更新为运行中、成功或失败，因此同一次调用不会重复堆叠相同步骤。隐藏思考、工具参数和工具结果不在这里展示。全部工具结束后该区域一次性清空，正式回复从首个 token 开始在正文位置实时输出。
- 简历上下文和提案统一读取 strict canonical 快照；模板投影由 `LayoutPlan` 提供，Agent 不能把 region、slot 或分页信息写进正文。Agent 的 Markdown 上下文只在序列化边界把 canonical `InlineIcon/title_icon` 输出为白名单 `:icon[Name]:` 标记，不能把图标降级成普通正文后回写。旧快照只能经受控迁移/导入适配器进入系统。
- 用户确认提案时再次校验所有权、目标定位、内容前置条件和简历图片导出契约。多张范围化提案共享创建版本时，先确认一张不会让其他不相交提案失效：服务端在当前快照按目标哈希安全重放，只有目标自身变化才拒绝；旧快照和翻译提案继续严格校验 `base_lock_version`。图片缺失、不支持或超过单图/快照总量上限时拒绝确认，当前简历和提案状态保持不变。
- 停止、失败和异常 EOF 都有明确终态，不能把半条响应当作成功。

一轮请求可包含多项简历、翻译、面试或职业建议任务。助手先保存本轮任务清单，为每项任务选择本轮已授权的资料引用；初始规划只看到资料目录，启动任务后才重新校验并取得该任务的有界正文。不同任务可以复用同一引用，但不能自动读取其他任务的材料。任务记录所用材料的类型、ID、版本、正文指纹和来源角色；“来源陈述”不等于已核实的个人经历。执行时逐项记录完成、部分完成、受阻或失败；会话回读的用户消息包含任务结果及不含正文的材料收据。简历任务只有生成待确认提案才算创建了修改产物，提案未确认前不会改变当前简历；正常结束的 Agent run 不代表每项任务都已完成。标题建议默认给一个候选，用户明确要求数量时最多给五个有不同侧重点的候选。

- 确认非翻译提案成功时在同一事务内写入 `ai_customization_applied` 产品漏斗事件，带提案类型与发起入口；助手页发送 `entry: "assistant"`，编辑器侧栏发送 `entry: "editor"`，未携带时记 `unknown`。翻译提案只记 `resume_created(translate)`。

## 数据归属

会话、运行、消息、工具调用和提案分别由 `agent_sessions`、`agent_runs`、`agent_messages`、`agent_tool_calls` 与 `resume_change_proposals` 保存。会话持久化标题、置顶、生命周期和显式选中的逻辑模型 ID，不持久化默认简历；简历归属保存在具体消息的上下文快照及提案目标中。列表先展示置顶会话，再按 `updated_at` 和内部 ID 倒序。接入商、逻辑模型、场景绑定和调用日志属于技术治理数据，不是用户对话内容，详见运行时架构文档。

结构化澄清答案、被回复的助手消息序号和经过校验的编辑器选区一起保存在用户消息元数据中。回答澄清时，服务端沿该助手消息的 run 找回原用户消息上下文与选区，并重新校验资源归属、存在性和版本；客户端不能静默替换原目标；仅当澄清续答显式选择另一份简历并声明替换时，服务端重新校验目标、舍弃旧选区。其他同类型资源或选区变更仍被拒绝。后续运行会同时恢复问题、选项 ID、答案、已复验上下文和稳定选区，不依赖页面未刷新的临时状态或展示文本重新猜测已确认的修改范围、动作或位置。字段或块内选区清空通过受目标哈希保护的空字符串替换表达；完整 paragraph/list item 使用结构化 `delete_target` 删除，不留下空 bullet，二者都须生成提案并由用户确认。

`0111–0115` 之后，会话置顶列为 `agent_session.is_pinned`，接口字段仍为 `pinned`。删除会话时，服务依次删除提案、工具调用、消息、运行、阶段事件和操作；调用日志作为计费记录保留，其 `agent_run_id` 置空。数据库没有外键，这些清理都在应用层完成。详见[阿里巴巴 MySQL 规约整改](../internals/backend.md#阿里巴巴-mysql-规约整改)。

## 关键流程

1. Web 查询 readiness 和可选上下文，提交用户消息、幂等键及轻量引用。
2. FastAPI 校验上下文所有权与版本，创建 run/message 后调用 Pi，并把 Pi SSE 事件转换为浏览器协议。
3. Pi 只能通过运行时开放的内部工具读取受控材料、解析本人简历、召回授权资料或提交简历修改计划；目录查询不返回正文。工具调用和运行时步骤的结果摘要写入审计数据。
4. 需要补充信息时返回结构化 clarification；继续对话复用同一 session，每轮可以按用户要求选择不同的简历上下文。
5. 用户确认普通编辑提案后，FastAPI 重新读取目标和简历锁版本，校验 canonical 文档、presentation、模板快照与私有图片导出契约，再更新源简历。确认翻译提案时源简历保持不变，FastAPI 创建一份独立可编辑简历和初始版本；源简历私有图片复制到新命名空间，重复确认返回同一结果简历。

## 权限与失败边界

- session、run、proposal、上下文引用和目标简历都必须同时校验当前用户，公开 ID 不能代替归属条件。
- 会话支持标题、置顶及当前对话模型更新；切换模型会校验有效对话列表，不创建消息或触发模型调用。删除会话前必须确认没有运行中任务，并在事务中清理其提案、工具调用、消息和运行记录。
- 会话删除只作用于当前用户拥有的目标会话；其他用户的公开会话 ID 统一按 `AGENT_SESSION_NOT_FOUND` 处理。
- 删除简历只清理以该简历为目标的待确认提案；独立会话及历史消息继续保留，旧上下文快照不再授权读取已删除资源。
- 取消请求、Pi 不可用、模型失败、异常 EOF、提案过期、内容摘要不一致和锁冲突都有独立终态；失败不会把提案标为已应用。
- 对话正文不会写入 LLM 调用日志，模型凭据不会返回浏览器，内部工具不能接受任意 URL 或对象键。
- 管理端模型使用情况分别展示估算和供应商结算费用、计价覆盖及未计价原因，提供 CSV 账单对账。历史数据修复通过有界的后端补算接口进行，页面不提供历史补算按钮。普通请求、Pi 请求和语音请求共用后端计价规则；缺少可靠用量或价格单位时保留原因，零金额不会被当成缺失金额。补算不重新调用模型，不覆盖原始价格和用量；时间依据不明的历史调用单独提示，详细契约见 [HTTP 契约](../api/http-contracts.md)。
- 登录用户通过 `GET /api/agent/models` 读取有效对话模型列表和默认模型 ID；选择写入当前会话，运行开始时冻结实际线路。列表与会话响应均不返回地址、凭据或价格。
- 助手仅在问题涉及本轮授权资料，或回答缺少其中可能包含的事实时调用 `search_resume_materials`，不在每轮对话例行调用。资料库默认走 LinkRag 多路融合排序，取前 6 条作为回答补充；未建索引的资料和 LinkRag 失败时沿用子串匹配。召回范围仍只限本轮任务授权资料，来源版本与引用校验不变；纯资料问答使用只读 `material_lookup` 工作流。
- 助手对岗位、求职和资料集只有受控读取能力；业务写入仍回到对应领域服务。资料替换后，后续引用读取最新 Markdown；资料正文不提供用户或 Agent 编辑入口。
- 求职进程上下文读取 `current_stage` 的稳定类型、显示名称与轮次，并单独读取 `phase` 和生命周期；兼容期内只有缺少阶段历史的旧记录才回退到扁平阶段字段。

## 修改联动与验证

修改 SSE 事件、上下文类型、提案 operation 或澄清结构时，需同步 `schemas.py`、Pi 协议、Web 两个客户端、接口契约和 Agent 测试；模型能力变化还需同步[运行时架构](../internals/agent-runtime.md)。主要验证入口为 `test_agent_routes.py`、`modules/agent/test_context_service.py`、`test_pi_client.py`、`test_service.py`，以及 Web `AssistantPage` 和 `AgentPanel` 测试；完整 Pi 运行时检查使用跨平台的 `npm run check:pi`。

## 管理员调用排障

管理员可在独立的「Agent 调用排障」页面按一次消息操作查看阶段轨迹，并可按操作 ID 或用户 ID 精确查找。服务端从已校验归属的会话反查用户 ID，记录预检、运行创建、Pi 执行、工具调用、提案创建和确认的受控状态与错误码；页面不展示用户消息或简历正文。旧运行只提供原有摘要，标记为历史记录。管理台统计（`/api/admin/insights/agent`）复用排障列表的同一状态合成规则，给出操作次数、失败率、运行中数量、P95 耗时和最常失败阶段；LLM 调用日志列表支持按场景、状态、错误码、Call ID、用户 ID 与时间窗筛选，并按筛选条件汇总调用数、Token 与费用。

简历历史表已在 `0089` 退役。助手只读取当前简历；旧 `resume_version` 上下文请求继续返回 `AGENT_CONTEXT_RETIRED`，不查询历史表。删除历史功能不改变提案对当前内容的校验、应用与独立翻译副本行为。


## 账号能力与客户端边界

对话「添加资料」弹窗提供当前简历、资料、岗位、求职进程和面试记录，不提供「个人画像」按钮；历史消息中的画像引用仍可展示。画像读取仍需版本与授权校验，作为只读材料传给 Pi，不自动写入简历。界面语言仅影响助手导航、状态与操作文案，不翻译用户消息或模型正文。新运行、日志和最终写回重新验证账号，活跃运行阻止注销。见[账号功能](identity-account.md)。

助手对话不再弹出面试准备清单卡片：清单属于具体的已排期面试，由面试记录页的“AI 生成准备清单”按钮生成并保存，详见[求职中心](career-center.md#面试准备清单)。

此前 @ 的个人画像、简历、资料文件、岗位、求职进程和面试记录均纳入同会话有界短期身份记忆。用户继续指向其中某个对象时，助手先理解本轮指代并由服务端重新校验资源和读取当前内容；记忆不代表默认选择，也不自动携带原文件全文。明确选择新的同类型对象优先于历史，多对象歧义先澄清；新会话、删除或越权对象不能凭旧引用继续读取。

同一对话中后续轮次 `@` 选择另一份简历时，以本轮显式选择为准，助手不会再询问“是哪一份简历”；只有用户文字明确点名与选择不同的简历时才会确认。

分析、诊断和建议类回复先给一句总体判断，再用 Markdown 列表逐条分点；只问单个事实的问题仍保持一至三句。

简历诊断按请求区分整体诊断、单段经历、岗位匹配、结构格式、内容问答和片段评价；每条发现都引用原文位置并给出改法。诊断只在无法确定分析哪段内容时追问；经历是否已发生、具体数据等需要用户补充的事实不中断诊断，而是在结论中分情况给出建议并列出补充问题。助手依据当天日期判断简历中的时间已经过去还是尚未到来，不为此追问。
