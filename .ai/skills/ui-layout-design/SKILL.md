# UI 布局设计

## 1. 职责与边界

把已经明确的用户任务和内容关系转成稳定、可读、可适配的空间结构。布局先表达产品优先级，再选择 Grid、Flex、普通文档流、滚动容器或定位方式。

本技能只在布局本身是任务内容时使用：

- 新建页面、工作台、列表、详情、表单或设置区域；
- 改变页面主要区域、导航、主次栏、信息密度或阅读顺序；
- 修复拥挤、扁平、错位、卡片滥用、内容裁切或响应式结构问题；
- 需要决定窄、中、宽容器下如何重排、折叠、滚动或渐进披露。

文案、颜色、阴影、圆角、字体、图标或单个间距值的局部修改不单独触发本技能。业务流程、API、权限和数据语义由当前请求、`solution.md` 或其他已确认依据负责，本技能不能用视觉方案改变它们。

## 2. 必读证据

按任务范围读取最小证据：

1. 用户请求以及当前 `ui-design.md`；混合任务同时读取上游 `solution.md`；
2. `DESIGN.md`、目标页面和直接复用的布局或组件；
3. 页面真实内容范围、状态和主要操作；
4. 当前 Token、间距尺度和响应式约定；
5. 目标路由的邻近测试与浏览器可观察结果。

没有 `ui-design.md` 的轻量任务，直接从当前请求和真实页面判断。不要为了布局审查加载所有页面、整个组件库或无关设计参考。

## 3. 布局命题

编码前形成最小布局命题；已有 `ui-design.md` 覆盖时直接复用，不再改写：

```text
主任务：用户进入后最需要完成或理解什么
阅读顺序：第一、第二和辅助信息分别是什么
分组：哪些内容必须靠近，哪些必须明显分开
密度：高频操作区、内容阅读区和辅助区各需要多紧凑
结构：页面流、网格、主次栏、滚动容器和稳定操作区
适配：窄、中、宽容器下重排、折叠、换行、滚动或披露方式
```

只有结构存在两个都会改变用户结果的合理答案时才向用户确认。能沿现有页面模式确定的比例、gap、容器宽度和断点属于实现细节。

## 4. 布局规则

### 分组与层级

- 先用距离表达分组，再用背景面，密集数据确实需要时才使用分隔线；组间距离应明显大于组内距离。
- 页面保持一个主焦点或主任务路径；次要区域通过位置、空间、权重或对比降级，不让所有卡片和标题同等突出。
- 对齐到少量共享边缘，避免每个局部形成自己的起止线。
- 让空间节奏有紧有松：相关控制紧凑，独立区域留出明确分隔，不把同一 padding 复制到所有容器。
- 不为每组内容创建卡片，也不嵌套没有状态或交互意义的卡片。

### 结构与密度

- 结构服务内容关系：普通信息流优先文档流，二维关系使用 Grid，同轴排列与分布使用 Flex。
- 高频操作和扫描型数据可以紧凑；阅读、解释和首次使用区域需要更宽松。密度必须由使用频率和决策复杂度决定。
- 主次栏宽度、固定区和可伸缩区要表达两者关系；不能只因为常见模板就使用侧栏或均分网格。
- 关键操作留在正常流或稳定操作区，不放在容易被滚动、键盘、弹层或缩放裁切的位置。
- 固定尺寸只用于真实固定几何；文字容器允许增长、换行和本地化扩展。

### 响应式与容器

- 断点来自内容或操作开始失效的位置，不机械复制设备预设。
- 页面整体结构使用视口断点；可复用组件在不同宿主宽度中出现时优先容器查询。
- 响应式不是等比缩小：按重要性重排、折叠、换行、横向滚动或渐进披露，同时保持核心功能可用。
- 视觉顺序改变时核对 DOM、键盘和辅助技术阅读顺序，不能只用 CSS 排列制造另一条不可访问的顺序。
- 固定、吸附和全宽内容必须考虑滚动容器、弹层、移动端安全区和触控目标。

## 5. 分级应用

- `轻量`：只修复已定位的布局根因，使用现有尺度和结构，不重新提出页面命题；检查受影响容器和一个相邻尺寸。
- `标准`：为既有页面的区域调整写布局命题，核对主任务、分组、密度和受影响断点；不改变现有视觉世界。
- `完整`：为新页面或主要结构重做展开窄、中、宽布局，覆盖典型、长内容、空状态、弹层和缩放；必要时用小型 ASCII 线框表达区域关系，不生成装饰性方案竞赛。

档位继承 `frontend-design` 或 `frontend-delivery` 的结论，不在本技能重新分级。

## 6. 验证与输出

实现或审查后用代码证据和适用的真实浏览器观察核对：

- 主任务、次要信息和主要分组在弱化细节后仍可辨认；
- 长文案、空内容、动态数量、滚动和弹层不会遮挡内容或关键操作；
- 受支持尺寸下阅读与操作顺序保持清晰；
- 视觉顺序与 DOM、焦点和触控顺序一致；
- 没有无理由的任意间距、固定文字尺寸、嵌套卡片或重复断点；
- 未实际检查的尺寸、缩放、本地化或设备明确标为未验证。

审查输出按根因合并问题，给出文件位置、触发场景、用户影响和最小修复方向。实施任务直接把布局结论交回 `frontend-delivery`，不创建第二份布局报告。
