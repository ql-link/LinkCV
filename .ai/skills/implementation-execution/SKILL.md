# 实施执行

## 1. 职责

把已确认的需求和适用设计落实为真实代码，并保持实现、测试和当前确认依据一致。本技能负责：

- 核实前置条件和当前工作区；
- 在确认范围内修改代码、配置、测试和必要文档；
- 处理实现中发现的确认依据或方案偏差；
- 方案先行任务只有出现已允许的实际方案偏差、已接受限制或必须交接的遗留风险或下一步事项时，才补充最小实施记录；
- 把完成的实现交给测试和质量审查。

本技能不负责创建分支、提交、推送、PR，除非用户另外明确要求进入 `branch-pr-workflow`。

纯前端页面、组件、交互、布局或视觉任务使用 `frontend-delivery`。前后端混合任务中，本技能只执行当前 `solution.md` 约束的后端、API、共享契约、配置与必要消费方同步；页面设计与前端实现由 `frontend-delivery` 消费同一契约。

## 2. 进入条件

### 直接实现

- 已由 `backend-delivery` 的七维判断明确判为直接实现，或用户关闭工作流后直接进入本技能；
- 任务属于纯后端，或属于契约已完全明确且可逆的混合任务后端工作包；
- 七维结果为准备 `可实施`，复杂度为简单或符合直接实施条件的中等；记录需要不改变直接实现路径；
- 风险可以是常规或严格。严格风险的具体触发项、必要确认、失败结果、回退或不可逆点和验证要求已经明确；仍有会改变权限、数据、安全、兼容或生产结果的选择时不能开工；
- 不要求创建 `.specs`；
- 用户当前请求、可读取的 Issue、飞书文档或用户明确指定的其他材料已经足以确定目标、边界和可观察结果；
- 存在来源 Issue 时完整读取其正文和关联材料；没有 Issue 不阻止直接实现，也不要求关闭工作流。已有详情文档时同时读取。

### 方案先行

以当前 `solution.md` 为实施中心。确认后的方案是本任务的当前实施依据；飞书和 Issue 只保留为初始来源，不与方案并列裁决实现。AI 结合最新用户指令、存在的 Spec 附件、Git 差异和真实代码判断能否开工；缺少状态字段、哈希或阶段命令本身不得构成阻塞。

方案文档选择契约验收时，应当存在与当前方案一致的 `acceptance.feature`；选择直接施工时不产出该文件，方案文档“代码实施计划”和“验证与验收”就是施工与验证依据。仍有会改变范围、行为、权限、数据、安全、兼容或不可逆结果的未决项时返回 `solution-generator`；普通实现细节由 AI 按真实仓库自行决定。只有方案明确引用了尚未吸收的事实附件时才按需读取初始来源，不能用飞书或 Issue 覆盖当前方案。本阶段不发送过程性的 Issue 规格同步评论，交付说明统一留到 PR 收口。

混合任务存在已确认原型或 Figma 时可以读取它核对前端消费方式，但它不能改变 `solution.md` 中的 API、权限、数据、状态或失败语义；发现冲突时停止并返回上游方案。

## 3. 必读材料

1. `AGENTS.md`；
2. 用户当前请求和已经确认的范围；
3. 直接实现任务存在来源 Issue 时完整读取其正文和关联材料，不限制来源平台；
4. 直接实现任务存在飞书模块详情文档时完整读取；方案先行任务只在当前方案明确引用尚未吸收的事实附件时按需读取；
5. 方案先行任务的当前 `solution.md` 和实际存在的 Acceptance、人工验收或实施报告；
6. 目标文件、直接调用方、共享类型和最近测试；
7. `git status --short`、当前任务相关差异和用户已有未提交修改；
8. 涉及 API、环境变量或部署时，读取前端 API 客户端、Vite 代理和部署配置；
9. 涉及迁移或存储时，读取现有模型、迁移、事务和回滚方式。

不要只读方案文档而跳过真实代码。方案文档中的路径、字段和契约都需要在实施前再次核实。

## 4. 实施纪律

### 聚焦范围

- 只实现确认范围，不顺带重构无关模块；
- 复用现有模式前先确认它仍适用于当前模块；
- 新依赖必须说明必要性并更新对应锁文件；
- 不覆盖、不丢弃用户已有修改；重叠区域必须先理解再编辑。

### 契约同步

修改接口、共享类型、错误、环境变量或部署行为时，同步检查所有消费方。结构、语义或兼容影响不清楚时使用 `contract-guard`；同一个具体值散落多处时使用 `config-contract-sync`；最终实现改变长期项目事实时使用 `doc-maintenance-sync`。只选择真实命中的技能，不固定串行调用。修改数据库模型时先核实已确认物理 schema，再使用 `alembic-migration` 同步模型与 revision，处理旧数据、事务、兼容发布和回滚；不要手工改库绕过迁移链。

### FastAPI 路由与部署契约

- 当前全部 `/api` 由 FastAPI 处理，仓库不再存在 Express 运行入口；不得寻找或恢复 `server/` 作为兼容方案；
- 修改路由、前端 API client、Vite Proxy、环境变量或部署入口时，必须按当前路径的确认依据同步处理消费方、验证和回滚。方案先行任务以当前 `solution.md` 为准；直接实现以来源材料、当前确认结论和 `backend-delivery` 七维简报列出的严格检查项为准；
- SQLAlchemy 模型和 Alembic 基础已经存在，根 revision `0001` 创建 `users`、`resumes`；后续数据库任务必须落地顺序编号的 SQL-first migration，并核对目标环境 current revision，不能把 SQLite 集成测试当作 MySQL 就绪证据。

### 安全与数据

- 鉴权、资源归属和文件访问必须在可信边界校验；
- 不把用户真实简历、联系方式、密钥或本地敏感路径写入代码和测试；
- 示例与测试数据使用虚构信息，默认姓名使用“张三”。

涉及 LLM 或第三方服务时，严格按当前路径的确认依据落实数据最小化、后端密钥边界、预算和限流、超时重试与幂等、取消和部分结果、降级反馈、脱敏可观测性以及测试替身。方案先行任务消费当前 `solution.md`；直接实现消费来源材料、当前确认结论和 `backend-delivery` 的严格检查项。不得把真实简历正文、密钥或供应商完整响应写入日志和测试；不得为了成功率无限重试，或静默切换会改变数据处理承诺的供应商。

## 5. 实施步骤

1. 读取当前实施依据并判断下一步；方案任务以 `solution.md` 为中心，不要求先执行阶段命令。
2. 检查工作区和相关差异，区分用户修改与本任务修改。
3. 读取目标代码和测试，列出最小可交付改动顺序。
4. 按依赖顺序实现，每完成一个可验证单元就运行最窄相关检查。
5. 补充或修改距离行为最近的有效测试；简单邻近测试可直接编写，需要独立测试设计、复杂 Mock 或分层调整时使用 `test-authoring`。测试必须能在实现错误时失败。
6. 检查 API、类型、权限、数据、配置、部署和长期文档是否需要同步，按契约影响选择对应专项技能。
7. 实现稳定后更新必要 `docs/`，不要把临时 Spec 内容复制成项目现状。
8. 完成后交给 `run-all-tests` 直接执行范围匹配的自动化验证，不保存本地“已通过”状态。
9. 存在跨端、浏览器、上传下载、PDF 或视觉行为且自动化测试未覆盖时，转 `manual-acceptance` 生成并记录人工验收；不适用时直接跳过。
10. 全部必要验证通过后交给 `code-review-and-quality` 做质量审查。审查是实际动作，不是持久阶段；代码随后变化时由 AI 根据影响重新验证和复审。

## 6. 实施偏差与回流

实施中发现以下情况时停止当前实现：

- 新行为不在需求范围内；
- 验收契约遗漏了权限、异常、边界或幂等规则；
- 方案文档中的路径、契约、数据模型或兼容方案无法成立；
- 真实影响面已经超出当前交付路径能承担的范围。

按归属回流：

- 整个模块目标或商业前提变得不成立，且需要重新开展模块初步设计：转 `module-planning`；飞书冲突本身不触发 `module-planning`；
- 方案先行任务中，用户在实施中改变范围、用户结果、权限、数据语义、兼容或发布决定：先更新当前 `solution.md` 并确认受影响决定，再继续实现；不因选择影响大就自动升级为模块规划；
- 直接实现任务出现上述新决定，或准备程度、复杂度、风险、记录需要、后端路径可能变化：返回 `backend-delivery` 只重评受影响维度；
- 上游决定未变化、只是本地规格遗漏：按影响返回 `solution-generator` 或 `acceptance-generator`；
- 仅文件组织、方法命名、测试落点或其他不改变外部结果的实现细节不同：继续实现，按重要性在 PR 说明，不修改方案；接口、数据模型、迁移、状态或兼容方案需要改变时才返回 `solution-generator` 修订并确认受影响决定；
- 准备程度、复杂度、风险或记录需要发生变化，导致原路径不再成立：返回 `backend-delivery` 只重评受影响维度；只有领域边界改变时才返回 `flow-router`。风险升高本身不自动等于方案先行。

不改变核心产品目标、验收、权限、数据安全或兼容承诺的实现偏差，可以继续推进，并根据实际重要性在实施报告或 PR 中说明原确认依据、实际实现、原因、影响和验证，不反向修改初始材料。会改变上述产品或风险边界的事项必须先回到对应上游：整个模块前提失效时才进入 `module-planning`；方案任务的单需求变化直接交 `solution-generator` 修订方案、确认受影响决定；七维判断或后端路径变化返回 `backend-delivery`，只有领域变化才返回 `flow-router`。本阶段不回写飞书或 Issue；最终 PR 和一条 Issue 交付评论由 `branch-pr-workflow` 统一完成。

## 7. 实施报告

方案先行任务只在命中以下至少一项时，读取 [implementation_report.template.md](implementation_report.template.md) 并生成 `.specs/<KEY>/implementation_report.md`：

- 实际实现存在不改变核心目标、验收、权限、数据安全或兼容承诺，且已经允许保留的方案偏差；
- 存在用户或上游已经明确接受、但接手者仍需知道的当前限制；
- 存在必须跨会话交接的遗留风险或下一步，单靠当前方案、Git 差异和代码无法安全续做。

数据库迁移、跨端契约、权限边界、部署配置、多模块改动或严格风险本身都不触发报告；这些内容已经由方案文档、代码、测试、人工验收和 PR 各自承担。三项触发条件都未命中时，不创建空报告。

报告只是当前方案的增量补充，只写“与方案的实际偏差”“已接受限制”“跨会话遗留风险与接手点”中真实命中的章节。每项按需写清原因、影响、确认来源、已做验证和下一步，不复述正常实现结果、运行链路、文件清单、测试命令、人工验收或 PR 审查清单。空章节直接删除，不写“无”。

如果偏差实际改变核心产品目标、验收、权限、数据安全或兼容承诺，必须先回流、更新方案并确认受影响决定，不能把报告当作绕过确认的渠道。直接实现不创建 Spec 或实施报告文件；跨会话时从当前请求、来源材料、七维简报、Git 差异和真实代码恢复。只有目标、准备程度或复杂度发生变化并可能影响后端路径时才返回 `backend-delivery`；领域变化才返回 `flow-router`，不能仅因跨会话强制改走方案先行。

## 8. 完成标准

进入下游前必须满足：

- 实现与确认范围一致；
- 没有静默规格偏差；
- 相关测试已新增或更新；
- 适用的人工端到端流程已有清单，未执行、失败和阻塞项没有被隐去；
- API、配置、数据、部署和文档已按影响同步；
- 涉及数据库时，ORM、forward-only Alembic revision、数据处理、向前升级测试和 schema 文档保持一致；
- 用户已有修改保持完整；
- 未执行的验证和已知风险已明确记录；
- 没有自动修改 Issue、创建提交或发布远端变更。
