# 配置契约一致性

## 1. 唯一职责

回答“同一个物理值在各处是否一致，运行时到底使用哪个”。典型值包括：

- API 路径和当前服务归属；
- FastAPI、MySQL、MinIO 的端口或地址；
- 环境变量名称、默认值和覆盖优先级；
- Vite Proxy、根级启动命令和 Compose 中的目标；
- bucket、对象路径前缀或其他跨模块标识。

本技能不判断字段语义或兼容策略，不更新长期文档，不做通用代码审查。

## 2. 使用边界

只有同一个值确实分布在两个以上位置，或者 `check_runtime_contracts.py` 已报告漂移时才使用。单文件局部配置、不涉及消费方的实现常量和纯文档修改不触发。

默认只诊断。用户要求修复时，把确认后的统一方案交给 `implementation-execution`，不要在诊断请求中扩大修改授权。

## 3. 必读材料

1. [契约面与事实源映射](../../../docs/internals/contract-governance.md) 中相关契约面；
2. `scripts/quality/runtime-contract-rules.yaml` 中命中的确定性规则；
3. 值的代码实际读取点；
4. 环境模板、启动命令、代理、Compose 和部署消费方中适用的部分。

不要读取真实 `.env` 中的密钥或把凭据写入输出。环境模板不能代替代码实际读取点。

## 4. 核对步骤

1. 为每个待核对值定义含义，避免把名称相似但职责不同的变量混为一个契约。
2. 从代码读取点向外追踪默认值、环境覆盖、启动命令和消费方。
3. 标明每处是 `生效值`、`默认值`、`模板值`、`覆盖入口` 还是 `死值`。
4. 运行 `npm run check:contracts` 获取确定性证据；门禁没有覆盖的值继续人工核对。
5. 出现分叉时指出根因和建议真值源，列出全部同步位置。
6. 如果分叉实际代表结构或兼容策略变化，停止并转 `contract-guard`，不在值层替用户决定。
7. 多处取值已经一致但运行仍失败时，转 `incident-triage` 沿真实调用链继续定位，不重复比较同一批值。

## 5. 输出

```text
一致性结论：一致 | 存在漂移 | 配置未生效 | 待确认

| 契约值 | 位置 | 当前取值或来源 | 角色 | 结论 |
| --- | --- | --- | --- | --- |

生效真值：<实际读取链>
根因：<漂移、死值、覆盖或误用>
统一方案：<目标值和全部改动点>
验证：<机器门禁与仍需人工验证的行为>
```

不要只比较字符串；必须说明运行时为何使用该值。
