# 领域交付入口

## 1. 唯一职责

本技能只回答两个问题：

1. 当前改动属于纯前端、纯后端还是前后端混合；
2. 哪一个领域交付 Skill 应当接管后续判断和实施。

```text
代码改动请求
  → flow-router
      ├── 纯前端 ─────→ frontend-delivery
      ├── 纯后端 ─────→ backend-delivery
      └── 前后端混合 ─→ backend-delivery
```

它不判断准备程度、简单/中等/复杂、严格风险、持久记录、直接实现或方案先行；不选择 Sol/Luna，不创建 `solution.md`、原型或 Figma，也不主持产品讨论、写代码、测试、提交或修改外部系统。这些决定归领域交付 Skill。

## 2. 何时使用

用户要求新增功能、修复、重构、迁移或配置改动，且尚未进入明确的领域交付 Skill 时使用。

以下情况不使用：

- 只要求解释、审查、排障、研究或报告状态，没有代码修改授权；
- 明确要求先讨论整个模块或撰写飞书初步设计：直接使用 `module-planning`；
- 已经存在匹配任务且领域明确的 `solution.md`、已确认原型或 Figma：直接恢复对应 `backend-delivery` 或 `frontend-delivery`；
- 用户已经明确调用 `backend-delivery` 或 `frontend-delivery`；
- 当前已经在下游实施，且没有证据表明任务领域发生变化。

纯运行故障先进入 `incident-triage`。取得修复授权后，再用本技能确定代码改动属于哪个领域。

## 3. 最小核实

读取用户当前请求、`AGENTS.md` 和区分领域所必需的最小代码面。至少确认预计改动入口、直接消费方，以及是否改变公共契约。存在 Issue 或飞书材料时，它们只作为领域判断的补充；没有 Issue 不阻止路由。

不要为领域判断完整扫描模块、评估全部测试、展开风险矩阵或估算工作量。领域仍无法从当前请求和最小代码证据确定时，只报告缺少的具体事实并做一次只读调查；不要提前执行七维判断。

## 4. 领域规则

- `纯前端`：只改变 `apps/web` 的页面、组件、交互呈现、布局、样式或前端内部状态，并沿用既有 API、权限、数据和错误语义；
- `纯后端`：只改变 FastAPI、服务、持久化、任务处理、后端配置或其他不含 Web UI 实施的行为；
- `前后端混合`：新增或改变请求、响应、共享类型、权限、数据、错误语义、代理或部署契约，同时需要 Web 前端呈现或消费。

文件位置不能单独决定领域：前端 API client 跟随后端契约变化属于混合任务；后端只提供已经存在的接口而页面独立调整仍是纯前端。浏览器扩展、小程序和 PDF 按真实应用边界转对应模块流程，不因使用 TypeScript 自动归入 Web 前端。

## 5. 用户选择的传递

用户明确给出的控制项必须原样传给下游，不在本技能重判或覆盖：

```text
工作流：自动 | 开启 | 关闭
路径：自动 | 直接实现 | 方案先行
后续：自动 | 直接施工 | 契约验收
```

- `纯前端`：由 `frontend-delivery` 判断是非视觉直接修改还是原型驱动实现；
- `纯后端`或`前后端混合`：由 `backend-delivery` 完成七维判断并解释路径；
- `工作流：关闭`：下游跳过交付文档和模型编排，但仍执行真实代码核实、必要验证、安全与 Git 边界。

用户选择与领域事实冲突时，只指出冲突并传递事实。例如用户指定纯前端直接实现，但请求实际改变 API，则转 `backend-delivery` 并说明这是混合任务；不得为了遵从路径名称把契约变化伪装成纯前端。

## 6. 输出与重新路由

默认只输出：

```text
领域：纯前端 | 纯后端 | 前后端混合
依据：<一个足以区分领域的真实事实>
下一站：frontend-delivery | backend-delivery
```

只有领域证据不足时补充：

```text
领域：待确定
缺少事实：<会改变领域归属的具体证据>
下一步：<一次最小只读调查>
```

下游发现 API、权限、数据、后端行为或消费方边界变化时，才返回本技能重新判断领域。准备程度、复杂度、风险、记录需要或后端直接/方案路径变化不返回本技能；前端内部变化留在 `frontend-delivery`，后端和混合任务留在 `backend-delivery`。
