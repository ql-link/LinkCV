# 后端领域入口

## 职责

本技能只服务现有后端交付链：判断改动是纯后端还是前后端混合，并把用户已经给出的后端工作流选择交给 `backend-delivery`。它不判断复杂度、风险、记录需要和实施路径，也不创建方案或修改代码。

明确只修改 `apps/web`，并沿用既有 API、权限、数据、错误和部署语义的任务，由当前 Codex 直接开发，不经过本技能，也不生成领域交接结果。

## 何时使用

- 请求直接修改 FastAPI、服务、持久化、后端配置、数据库或部署行为；
- 前端开发中发现需要新增或改变请求、响应、共享类型、权限、数据、错误语义、代理或部署契约；
- 当前任务是否涉及后端仍有一个能通过最小只读调查解决的事实缺口。

只要求解释、审查、研究或故障定位而没有修改授权时不使用。纯运行故障先使用 `incident-triage`；用户授权修复且改动涉及后端后，再使用本技能。

## 最小核实

读取当前请求、预计修改入口、直接消费方和判断公共契约所需的最小代码。Issue 和飞书材料只是补充来源，没有 Issue 不阻止判断。不要在这里扫描完整模块、执行七维判断、估算工作量或规划测试。

- `纯后端`：只改变 FastAPI、服务、持久化、任务处理、后端配置或其他不含 Web UI 实施的行为；
- `前后端混合`：后端或公共契约变化同时需要 Web 前端呈现或消费。

文件位置不能单独决定领域。前端 API Client 跟随后端契约变化属于混合任务；仅调整页面并复用现有接口仍是纯前端，应退出本技能并继续普通前端开发。

## 后端选择与输出

用户明确给出的后端控制项必须原样传递：

```text
工作流：自动 | 开启 | 关闭
路径：自动 | 直接实现 | 方案先行
后续：自动 | 直接施工 | 契约验收
```

用户选择与代码事实冲突时只说明事实，不把契约变化伪装成纯前端。确认涉及后端后输出：

```text
领域：纯后端 | 前后端混合
依据：<一个足以区分领域的真实事实>
下一站：backend-delivery
```

证据不足时只报告会改变上述判断的具体缺口，并继续一次最小只读调查。后端准备程度、复杂度、风险、记录和路径变化留在 `backend-delivery`；本技能不拥有后续编排。
