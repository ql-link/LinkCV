## 1. 审查步骤

1. 获取规则来源的最新正文；网络不可用时使用下面的稳定检查面，并把“未核对最新版”记录为限制。
2. 只审查本次改变或直接受影响的 TSX、CSS 和入口配置，不借机重写无关页面。
3. 按 `file:line - 问题；必要时给最短修复方向` 输出，按文件分组；无问题的文件标记 `✓ pass`。
4. 先处理会造成不可操作、信息丢失、明显可访问性缺陷、运行错误或性能灾难的问题；语境性建议要结合业务与项目事实判断。
5. 修复后重新运行最窄测试、类型检查和浏览器复查。

## 2. 网络不可用时的稳定检查面

- 语义与键盘：动作使用 `button`，导航使用链接；图标按钮有名称；键盘可完成所有流程。
- 焦点：焦点清晰可见，弹窗正确进入、约束和归还焦点，不用无替代的 `outline: none`。
- 表单：标签与控件关联，类型与自动填充合理，错误靠近字段，提交中防重复且保留明确文案。
- 动效：支持 `prefers-reduced-motion`，优先 `transform` 和 `opacity`，不使用 `transition: all`，交互可以中断动画。
- 内容：短、常规和超长文本都不破坏布局；flex 子项可收缩；空数组与空字符串有明确结果。
- 图片：替代文本、尺寸、加载优先级和首屏/非首屏策略正确。
- 状态与导航：可分享、可恢复的筛选、分页和标签状态进入 URL；临时弹窗、悬停和本地编辑中状态不强制深链。
- 触控与布局：移动端命中区足够，输入不会触发意外缩放，弹层处理滚动，布局优先 CSS Grid/Flex。
- 本地化：日期和数字使用 `Intl.*`；中文界面不机械套用英文 Title Case、弯引号或 `&` 规则。
- 性能：避免渲染期布局读取、无界动画和重型依赖；大列表是否虚拟化根据真实数量、行高和交互成本判断，不只按固定阈值。
- 文案：动作名具体且前后一致；错误给出下一步；空状态提供入口；删除无功能的说明文字。

## 3. 规则优先级与取舍

`AGENTS.md`、用户确认范围、业务契约和 `DESIGN.md` 高于通用指南。遇到冲突时不要静默忽略：说明上游建议、项目事实和采用的处理。不要为了满足一条通用建议引入路由状态库、虚拟列表库、图片框架或另一套主题系统；只有真实页面需求成立时才增加依赖。
