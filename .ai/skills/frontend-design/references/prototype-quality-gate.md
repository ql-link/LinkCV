# 可视预览拒收门禁

标准或完整档的真实页面预览、HTML 原型或 Figma 在展示给用户前必须通过本门禁。它检查浏览器中的实际画面，不检查“代码里是否写了设计词”。

## 1. 先与真实产品对齐

- 直接复用目标页面所在应用壳的品牌名、导航结构、内容宽度、背景层级和控件气质；原型不得自行发明新的 Logo、胶囊导航、强调色或页面主题。
- 从 `DESIGN.md` 和真实组件读取视觉角色，而不是只抄色值。`primary` 必须表达主要交互；近黑色负责正文和结构，不能代替品牌主按钮。
- 只有本次明确重做应用壳时才允许改变导航和全局框架；否则它们只是上下文，不是设计对象。

## 2. 浏览器截图必须拒收这些结果

- **比例失衡**：桌面首屏的核心内容缩在角落、主要容器明显过窄，或大片空白没有表达主次关系。
- **卡片滥用**：每个标题、说明或操作都被独立白卡包裹；能用排版、距离、分隔线或单一背景层表达的关系不得增加卡片。
- **层级扁平**：所有区域同样大、同样白、同样圆角、同样边框，第一眼无法判断主任务和次要信息。
- **文字过小**：核心正文、表单、按钮或区域说明依赖 12–13px 才能塞下；12px 只用于短元信息，正文和控件遵循 `DESIGN.md` 的 16px / 14px 角色。
- **模板化装饰**：无业务意义的水印、渐变、巨型字母、统计装饰、悬浮阴影或任意图标占据注意力。
- **错误强调**：主要动作不是 LinkCV 蓝，多个动作同时抢主按钮层级，或危险操作比主任务更醒目。
- **移动端只是缩小**：桌面结构等比压窄，没有按任务顺序重排；操作过密、触控不足或产生冗长无意义滚动。

命中任意一项就先修订原型，不能以“无横向溢出”“交互可点”“使用了 Token”判定视觉通过。

## 3. 展示前的最小自审

1. 在本地浏览器查看本次主要桌面尺寸与 390px，不只读取 DOM 或 CSS。
2. 暂时忽略颜色和文案，确认第一眼仍能看出唯一主任务、核心内容和辅助区。
3. 暂时弱化边框与卡片背景；如果分组随之消失，说明布局依赖容器堆叠，重新用间距和排版组织。
4. 与当前生产页面或同一应用壳的邻近页面并排比较，确认没有凭空引入第二套品牌语言。
5. Sol 自审后由主 Agent 再看一次实际截图；主 Agent 有明显的比例、层级或审美疑虑时必须退回，不得把质量判断转嫁给用户。

输出只需说明选定方向和关键取舍；本门禁不是新的文档产物。
