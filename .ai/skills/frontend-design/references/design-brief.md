# Design Brief 模板

在编码前用 8–12 行完成，简单页面可以合并条目。

```text
页面类型：列表 / 详情 / 表单 / 设置 / 工作台 / 弹窗 / 状态页
主题与受众：页面属于什么真实任务；谁在什么情境使用
主任务：用户进入页面后最重要的一件事
信息层级：标题与上下文 → 核心内容 → 辅助信息
操作层级：主操作；次操作；危险操作及确认点
状态：加载；空；错误；成功；禁用；权限不足
布局：1440；1024；390 下的区域变化和操作位置
视觉方向：现有 Token 与字体角色；一个有业务理由的标志性元素
组件：复用；从 shadcn 查询；需要组合的新组件
视觉风险：长文本、密集数据、溢出、焦点、动效或性能
```

不要在 Brief 中复制 API 字段表、精确 Token 数值或完整 JSX。它用于约束页面判断，事实仍在代码、契约和设计规范中。
