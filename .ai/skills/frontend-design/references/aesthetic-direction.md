# Anthropic 视觉方向适配

本参考根据 Anthropic 官方 `frontend-design` Skill 的方法改写，用于 LinkCV 新页面、页面重做和营销入口设计。它不复制上游措辞，也不覆盖 `AGENTS.md`、`DESIGN.md`、业务契约或用户明确要求。

- 上游来源：<https://github.com/anthropics/skills/blob/main/skills/frontend-design/SKILL.md>
- 核对版本：`f17010c9bb483898c1d9c9f42dde2b3a98889434`

## 1. 从主题出发

先明确页面服务的具体任务、受众和唯一工作。设计线索来自主题自身的材料、工具、语言和行为，而不是“后台”“AI 产品”或“SaaS”这类泛化标签。

对 LinkCV 来说，可以使用的真实线索包括简历纸张与编辑、求职材料整理、岗位比较、版本演进和审核流程；不能因此把简历纸张的字体与材质直接扩散到软件操作界面。

## 2. 先计划，再批评

第一遍形成紧凑计划：

- 色彩：说明页面需要哪些语义角色。内部功能区把角色映射到现有 Token；只有营销边界可以提出独立色板。
- 字体：说明 display、body、utility 的职责，并从 `DESIGN.md` 选择既有字体。
- 布局：用一句话描述信息流；存在两个合理构图时用小型 ASCII 线框比较。
- 标志性元素：只选一个与任务直接相关的记忆点，例如版本时间线、简历纸张与工作区的空间关系或明确的状态过渡。

第二遍检查这些选择是否也能原封不动地用于任意产品。如果能，重新寻找与当前任务有关的表达。再检查标志性元素是否改善理解、操作或品牌识别；仅用于填空的装饰应删除。

## 3. 克制地形成辨识度

- 把设计力度集中在一个位置，其他区域用精确间距、排版和层级支撑它。
- 营销页的首屏需要表达产品主张；内部功能页的首屏应快速建立上下文与主任务，不强行套用 Hero。
- 结构元素必须编码真实信息。编号只表示真实顺序，分隔线只表示分组或边界，标签只说明状态或类别。
- 动效用于状态变化和空间关系。一次完整、可中断的过渡优于许多零散动画；没有需要解释的变化时可以不动。
- 极简页面的质量来自间距、字体和细节精度；复杂视觉方向才值得承担更高实现和性能成本。

## 4. 把文案视为界面材料

- 使用用户认识的任务和对象，不暴露实现术语。
- 控件直接说明结果，例如“保存更改”，不使用含糊的“提交”或“继续”。
- 同一动作在按钮、处理中状态、成功反馈和错误提示中保持同一个动词。
- 错误说明发生了什么以及下一步；空状态提供可执行入口，不用情绪化或宣传性句子填充。
- 每个标签、示例和帮助文本只承担一个职责，删除不帮助理解或操作的文字。

## 5. LinkCV 四类边界

- 营销页：允许独立构图、主题色板和更强的首屏记忆点，但要控制性能与可访问性。
- 登录与注册：可继承营销氛围，表单和反馈必须使用项目 UI 组件与语义。
- 登录后功能区：优先清晰、密度和操作效率；辨识度来自结构和细节，不为每页发明主题。
- 简历文档：纸张、Markdown 和 PDF 排版独立，不使用软件界面 Token，也不反向定义应用界面。
