# 长期项目文档同步

## 1. 唯一职责

维护 `docs/` 中可供开发者和 AI 长期调阅的当前项目知识。文档解释系统现在是什么、模块如何协作以及稳定契约如何使用。

`.specs/<KEY>/` 保存某次需求的方案文档、Acceptance、实施报告和人工验收记录，不属于本技能。尚未实现的计划、备选方案和一次性排障过程不得写成 `docs/` 当前事实。

## 2. 触发与免触发

以下情况使用：

- 新增、删除、重命名或移动重要模块和入口；
- API、错误、权限、数据模型、配置或部署行为变化；
- FastAPI 路由、Vite Proxy、客户端或部署入口的归属和兼容边界变化；
- `contract-guard` 给出文档同步清单；
- `check_docs_sync.py` 报告缺失；
- 用户单独要求补充或修正文档。

局部 bug 修复、测试内部调整、格式化和不改变模块边界的实现重构通常不需要。

## 3. 必读材料

1. [docs 文档索引](../../../docs/README.md)；
2. 本次变化的真实代码、配置和测试；
3. [契约面与事实源映射](../../../docs/internals/contract-governance.md) 中相关契约面；
4. `scripts/quality/doc-sync-rules.yaml` 中命中的同步规则；
5. `contract-guard` 已有影响清单（如果本次调用由其转交）。

已有影响清单时直接消费，不重新做完整契约分析。没有清单的纯文档请求，只核实文档涉及的代码事实。

## 4. 同步步骤

1. 判断内容属于 `api`、`internals` 还是 `ops`，只读取最小必要文档。
2. 以代码实际入口、测试和运行配置核实事实，不从 Brief 或聊天记忆推断当前能力。
3. 更新失效段落；新增文档时同时更新 `docs/README.md` 索引。
4. 一个事实只在一处正式描述，其他位置使用链接，避免多份文案漂移。
5. 删除已经不存在的路径、接口和模块说明；不要保留“以后可能恢复”的陈旧事实。
6. 运行 `npm run check:docs`；涉及配置值时再运行 `npm run check:contracts`。

## 5. 写作约束

- 默认使用中文，代码标识、路径、命令和协议名称保留原文。
- 说明职责、边界、入口、调用关系和扩展方式，不逐行复述源码。
- 不写密钥、真实账号、私有部署凭据或用户数据。
- 不把 `AGENTS.md` 膨胀成知识库；项目入口只链接到文档索引。
- 不为通过门禁机械修改无关文档；规则误报时应修正规则或说明例外。

## 6. 输出

```text
同步结论：已同步 | 无需同步 | 被事实缺口阻塞
更新文档：<文件及更新主题>
事实来源：<代码、配置或测试>
未写入 docs：<仍属计划、Spec 或待确认的内容>
验证：<实际运行命令和结果>
```
